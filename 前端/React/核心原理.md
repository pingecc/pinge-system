# 在useState中传入一个函数

```js 
import { useState } from 'react';

// 接收两个参数：存储的键名 key，以及默认值 initialValue
export function useLocalStorage(key, initialValue) {
  
  // 1. 状态初始化：惰性计算，只在组件首次渲染时执行一次
  const [storedValue, setStoredValue] = useState(() => {
    try {
      // 先去 localStorage 里找找看有没有存过这个 key
      const item = window.localStorage.getItem(key);
      // 如果存过，就解析出来用；如果没存过，就用传入的默认值
      return item ? JSON.parse(item) : initialValue;
    } catch (error) {
      console.error("读取 localStorage 失败:", error);
      return initialValue;
    }
  });

  // 2. 包装 set 方法：在更新 React 状态的同时，顺手把数据存进本地
  const setValue = (value) => {
    try {
      // 更新 React 的状态，触发 UI 重新渲染
      setStoredValue(value);
      // 同步把最新值存入浏览器的 localStorage 
      window.localStorage.setItem(key, JSON.stringify(value));
    } catch (error) {
      console.error("写入 localStorage 失败:", error);
    }
  };

  // 3. 返回值格式和普通的 useState 保持完全一致
  return [storedValue, setValue];
}
```

上面的useState中，传入了一个函数，而不是直接传入一个值，因为这样写会带来性能问题：
```js 
// 每次组件重新渲染（比如你在输入框每敲一个字母），括号里的代码都会被执行一遍！
const [storedValue, setStoredValue] = useState(
  JSON.parse(window.localStorage.getItem(key)) || initialValue
);
```

虽然 React 只在第一次渲染时使用这个初始值，但是 localStorage.getItem 和 JSON.parse **这两个动作却会在每一次组件重新渲染时都被迫执行一次**。 读取浏览器本地存储（硬盘 I/O 操作）和解析 JSON 都是比较耗费性能的操作，每次敲击键盘都去读一次硬盘，页面必然会卡顿。

### ⁠0.1 ⁠重新渲染 = 重新执行整个函数

组件重新渲染时，整个组件函数体会从第一行到最后一行重新执行一遍，`useState` 这个函数也会在每次渲染时都被重新调用。

在 React 中，所谓的“函数组件”，本质上就是一个普通的 JavaScript 函数。 当你调用 `setState` 导致状态改变时，React 所谓的“重新渲染组件”，**其实就是把这个函数重新运行了一次**，以便拿到最新的 JSX（也就是 UI 的样子）。

### ⁠0.2 ⁠JavaScript 的传参规则：先执行计算，再传入结果

假设我们在组件里这样写：
```
function MyComponent() {
  // 每次组件更新，这个函数就会被重新调用
  
  const [value, setValue] = useState( JSON.parse(localStorage.getItem('key')) );
  
  // ...
}
```

这里是最关键的步骤。站在 JavaScript 引擎的角度，当它执行到 `useState(...)` 这一行时，它必须**先计算出括号里的值**，然后才能把结果传给 `useState`。

  

流程是这样的（假设这是第 5 次重新渲染）：
1. 运行 `localStorage.getItem('key')`（**读硬盘了！**）
2. 运行 `JSON.parse(...)`（**消耗 CPU 了！**）
3. 得到结果 `{ name: "张三" }`。
4. 调用 `useState({ name: "张三" })`。
5. **React 内部逻辑**：`useState` 接收到了 `{ name: "张三" }`。React 翻了一下备忘录说：“哦，这是第 5 次渲染，我已经记住之前的状态了，你传给我的这个初始值我**不需要了，直接丢弃**。”
    
**你发现问题了吗？** 虽然 React 内部最终丢弃了这个初始值，但在把它传给 React 之前，JavaScript 已经老老实实把 `getItem` 和 `JSON.parse` 执行完了。这就是为什么直接传值会导致每次渲染都白白消耗性能。

### ⁠0.3 ⁠为什么传函数就能解决问题？

现在我们来看“惰性初始化”（传一个箭头函数）：


```js
function MyComponent() {
  const [value, setValue] = useState( () => {
    return JSON.parse(localStorage.getItem('key'));
  });
}
```

流程变成了这样（同样是第 5 次重新渲染）：
1. JavaScript 执行到这一行，发现括号里是一个**函数定义** `() => { ... }`。
2. JavaScript **不会执行这个函数里面的代码**，它只是把这个“函数本身”当作参数。
3. 调用 `useState(那个箭头函数)`。
4. **React 内部逻辑**：`useState` 接收到了这个箭头函数。React 说：“这是第 5 次渲染，我已经有状态了，我**绝对不会去调用**你传给我的这个函数。”
**结论：** 因为 React 拒绝调用这个函数，所以函数内部的 `localStorage.getItem` 和 `JSON.parse` 在后续的渲染中**一次都没有被执行过**。只有在组件第 1 次挂载时，React 发现自己没有状态，才会主动去调用一下这个函数，把返回值作为初始状态。
