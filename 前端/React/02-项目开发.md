
# 使用脚手架快速搭建项目


## ⁠1 ⁠初始化项目

1、由于 React 官方不再提供纯前端的脚手架，业界目前的标准做法是直接使用 Vite 的通用创建指令。

```bash
npm create vite@latest
```

执行后，Vite 的脚手架引擎会弹出以下交互菜单：
- **Project name:** 输入项目文件夹名称（如 `my-react-app`）
- **Select a framework:** 在框架列表中选择 **React**
- **Select a variant:** 选择语言变体。推荐选择 **TypeScript + SWC**（SWC 是基于 Rust 编写的极速编译器，打包和热更新速度比传统的 Babel 更快）。
> **一键直达指令**：如果你不想回答问题，想在 CI/CD 脚本或终端里一步到位生成 React 项目，可以直接拼接参数： `npm create vite@latest my-react-app -- --template react-ts`


2、安装依赖和启动本地开发环境

无论你创建的是 Vue 还是 React，脚手架工作完成后，只会生成文件目录，**并不会自动帮你下载体积庞大的依赖包**。你还需要执行最后三步标准化操作：

```bash
# 1. 进入脚手架刚刚生成的项目文件夹
cd my-vue-app  # 或你定义的项目名

# 2. 让包管理器读取 package.json，下载所有构建工具和框架源码到 node_modules 目录
npm install    # 如果你习惯用其他包管理器，这里可以是 pnpm install 或 yarn install

# 3. 唤醒 Vite 开发服务器，开始写代码
npm run dev
```

## ⁠2 ⁠项目结构说明


项目根目录文件

| 文件/文件夹                 | 作用                                      | 为什么存在                                                                                    | 对应构建阶段 / 工具                   |
| ---------------------- | --------------------------------------- | ---------------------------------------------------------------------------------------- | ----------------------------- |
| **index.html**         | 整个应用的**真正入口 HTML**                      | Vite 采用“HTML 优先”设计，不再像 CRA 那样把 index.html 放在 `public/` 里。浏览器请求这个文件后，Vite 再注入打包后的 JS/CSS。 | **开发服务器 + 生产构建入口**（Vite 核心）   |
| **package.json**       | 项目元信息、依赖、脚本                             | 定义项目名称、依赖版本、常用命令（`dev`/`build`/`lint`/`preview`）                                         | **包管理 + 脚本入口**（npm/pnpm/yarn） |
| **pnpm-lock.yaml**     | 依赖精确锁定文件                                | 你用了 pnpm，它会生成这个文件，保证团队/CI 安装出完全一致的依赖树                                                    | **依赖安装阶段**（pnpm）              |
| **vite.config.ts**     | Vite 的核心配置                              | 配置插件（React）、路径别名、代理、构建选项等                                                                | **开发服务器 + 打包构建**（Vite）        |
| **tsconfig.json**      | TypeScript 项目总入口                        | 使用 **Project References**，把应用代码和 Node 环境配置分开，提升类型检查速度和准确性                                | **类型检查阶段**（TypeScript）        |
| **tsconfig.app.json**  | 应用代码（`src/`）的 TS 配置                     | 针对**浏览器环境**：开启 DOM、JSX、React 相关类型                                                        | **应用代码类型检查**（TypeScript）      |
| **tsconfig.node.json** | Node 环境代码的 TS 配置                        | 针对 `vite.config.ts` 等运行在 **Node.js** 的文件（没有 DOM，有 Node API）                              | **配置文件类型检查**（TypeScript）      |
| **.oxlintrc.json**     | Oxlint 配置文件                             | 官方模板已改用 Oxlint（Rust 写的超快 linter），替代原来的 ESLint                                            | **代码质量检查阶段**（Oxlint）          |
| **node_modules/**      | 所有安装的依赖包                                | 运行 `pnpm install` / `npm install` 后产生                                                    | **依赖安装后产物**                   |


### ⁠2.1 ⁠public/ 目录

```
public/
├── favicon.svg
└── icons.svg
```

- **作用**：放**不会被 Vite 处理**的静态资源。
- 开发时直接以 `/favicon.svg` 访问，生产构建时会原样复制到 `dist/` 根目录。
- 适合放 favicon、robots.txt、一些不需要 hash 的静态文件。
- **对应阶段**：静态资源复制（Vite 构建时直接 copy）。

> 注意：`src/assets/` 里的图片会被 Vite 处理（加 hash、压缩等），而 `public/` 里的不会。

---

### ⁠2.2 ⁠src/ 目录



官方模板通常包含：

```
src/
├── main.tsx          # 应用入口（ReactDOM.createRoot）
├── App.tsx           # 根组件
├── App.css           # 根组件样式
├── index.css         # 全局样式
├── assets/           # 会被 Vite 处理的静态资源（图片、svg 等）
└── vite-env.d.ts     # Vite 环境变量 + 模块声明的类型定义
```

| 文件 | 作用 | 对应阶段 |
|------|------|----------|
| **main.tsx** | 真正的 JS/TS 入口。把 `<App />` 挂载到 `index.html` 的 `#root` | 运行时入口 + 打包入口 |
| **App.tsx** | 根组件，后续你所有页面/组件都从这里开始写 | 业务代码 |
| ***.css** | 样式文件 | 被 Vite 的 CSS 处理流水线处理 |
| **assets/** | 会被打包、加 hash 的图片等资源 | 资源处理阶段（Vite） |
| **vite-env.d.ts** | 让 TypeScript 认识 `import.meta.env`、`.svg` 等 Vite 特有东西 | 类型声明 |

### ⁠2.3 ⁠整个构建/编译过程对应关系

```
1. 安装依赖
   package.json + pnpm-lock.yaml → node_modules/

2. 开发阶段（pnpm dev / npm run dev）
   ├── vite.config.ts          → 启动 Vite 开发服务器
   ├── index.html              → 入口 HTML
   ├── src/main.tsx            → 入口 JS
   ├── tsconfig.app.json       → 编辑器 + 类型提示
   └── .oxlintrc.json          → 可选的 lint（通常单独跑）

3. 类型检查（pnpm build 会先跑）
   tsc -b
   ├── tsconfig.json           → 总控
   ├── tsconfig.app.json       → 检查 src/
   └── tsconfig.node.json      → 检查 vite.config.ts

4. 生产构建（vite build）
   ├── vite.config.ts          → 配置打包行为
   ├── src/                    → 编译、打包、Tree-shaking
   ├── public/                 → 原样复制到 dist/
   └── 输出 → dist/

5. 代码质量
   .oxlintrc.json → oxlint（替代 ESLint）
```





下面按完整链路给你讲清楚：

1. **项目是怎么启动起来的**
2. **自己新增页面应该怎么写**
3. **打包后的产物长什么样**
4. **如何把产物部署到线上**


#### ⁠2.3.1 ⁠项目启动完整流程

1、开发模式启动（`pnpm dev` / `npm run dev`）

```bash
pnpm dev
# 实际执行的是：vite
```

执行过程如下：

```
1. 读取 package.json 的 scripts.dev → 启动 Vite
2. Vite 读取 vite.config.ts（加载 @vitejs/plugin-react 等插件）
3. Vite 找到根目录的 index.html 作为入口
4. 解析 index.html 里的 <script type="module" src="/src/main.tsx">
5. 开始编译 src/main.tsx 及其依赖树
6. 启动本地开发服务器（默认 http://localhost:5173）
7. 浏览器请求页面 → Vite 按需编译、注入热更新（HMR）代码
```

**关键文件执行顺序：**

```
index.html
    ↓
src/main.tsx
    ├── 引入 index.css（全局样式）
    └── 渲染 <App />
            └── App.tsx
                    └── 引入 App.css
```

开发模式下 **不会真正打包**，而是按需编译，所以启动极快，改代码后几乎瞬间热更新。

---

#### ⁠2.3.2 ⁠2. 生产构建流程（`pnpm build`）

```bash
pnpm build
# 实际执行的是：tsc -b && vite build
```

分两步：

| 步骤 | 命令 | 作用 |
|------|------|------|
| 1 | `tsc -b` | 用 TypeScript 做类型检查（根据 `tsconfig.json` + `tsconfig.app.json` + `tsconfig.node.json`） |
| 2 | `vite build` | 真正打包，输出到 `dist/` 目录 |

如果类型检查失败，构建会直接中断。



#### ⁠2.3.3 ⁠打包后的产物结构

执行 `pnpm build` 后，会生成 `dist/` 目录，大致如下：

```
dist/
├── index.html                 # 入口 HTML（已经被处理过）
├── favicon.svg                # 从 public/ 复制过来的
├── icons.svg
├── assets/
│   ├── index-xxxxx.js         # 打包后的主 JS（带 hash）
│   ├── index-xxxxx.css        # 打包后的 CSS（带 hash）
│   ├── react-xxxxx.svg        # 被处理过的图片资源
│   └── ...
```

关键变化说明

| 开发时 | 打包后 | 说明 |
|--------|--------|------|
| `src/main.tsx` + 各种组件 | `assets/index-xxxxx.js` | 所有 JS 被打包、压缩、Tree-shaking |
| `index.css` + `App.css` | `assets/index-xxxxx.css` | CSS 被合并、压缩 |
| `src/assets/xxx.png` | `assets/xxx-xxxxx.png` | 加 hash，方便缓存 |
| `public/` 下的文件 | 直接复制到 `dist/` 根目录 | 不做处理 |
| 源代码 | 完全看不到 | 只剩压缩后的产物 |

`index.html` 里会自动变成类似：

```html
<script type="module" crossorigin src="/assets/index-D8f3k2.js"></script>
<link rel="stylesheet" crossorigin href="/assets/index-C9a1b2.css">
```

#### ⁠2.3.4 ⁠如何部署产物

`dist/` 就是最终要部署的静态文件，可以用任何静态服务器托管。

1、最简单 —— 本地预览

```bash
pnpm preview
# 实际执行 vite preview
```

会在本地起一个静态服务器，模拟线上效果（默认也是 5173 端口）。

---

2、部署到 Nginx

1. 把 `dist/` 里的**所有文件**上传到服务器某个目录，例如 `/var/www/my-react-app`
2. Nginx 配置示例：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    root /var/www/my-react-app;
    index index.html;

    # 关键：支持 React Router 的 history 模式
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静态资源长期缓存（因为有 hash）
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

`try_files $uri $uri/ /index.html;` 这一句非常重要，否则刷新子路由（如 `/about`）会 404。

---

3、部署到 Vercel / Netlify（推荐新手）

**Vercel：**
1. 把项目推到 GitHub
2. 打开 [vercel.com](https://vercel.com) 导入仓库
3. 框架选择 Vite，构建命令默认就是 `pnpm build` 或 `npm run build`
4. 输出目录填 `dist`
5. 一键部署

**Netlify 同理**，输出目录也是 `dist`。

这两个平台会自动处理 SPA 的路由回退问题。

---

4、部署到自己的服务器（用 Node 简单起服务）

如果只是临时演示，也可以用：

```bash
# 先全局安装一个静态服务器
pnpm add -g serve

# 进入 dist 目录
cd dist
serve -s .
```

`-s` 参数表示单页应用模式（会把所有路由回退到 `index.html`）。

---

5、部署到子路径（重要）

如果你的网站不是挂在域名根路径，而是类似 `https://xxx.com/my-app/`，需要额外配置：

**vite.config.ts**
```ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  base: '/my-app/',   // 关键：加上子路径
})
```

然后重新 `pnpm build`，部署时把 `dist` 内容放到服务器的 `/my-app/` 目录下。

---

总结：

```
开发阶段
  pnpm dev
    → Vite 开发服务器
    → 浏览器访问 localhost:5173
    → 热更新

新增页面
  1. src/pages/Xxx.tsx 写页面
  2. App.tsx 里加 <Route>
  3. 需要的话在导航里加 <Link>

生产构建
  pnpm build
    → tsc 类型检查
    → vite build
    → 生成 dist/

部署
  把 dist/ 整个目录丢到静态服务器
  （Nginx / Vercel / Netlify / OSS 等）
  注意配置 SPA 路由回退
```




### ⁠2.4 ⁠日常开发模式

#### ⁠2.4.1 ⁠使用路由和新增页面

目前模板只有一个 `App.tsx`，适合做 Demo，后续自己新增页面日常开发时，一般建议引入路由

1、使用 React Router


```bash
pnpm add react-router-dom
```

2、建议的目录结构

```
src/
├── main.tsx
├── App.tsx                 # 变成布局/路由出口
├── pages/                  # 所有页面放这里
│   ├── Home.tsx
│   ├── About.tsx
│   └── NotFound.tsx
├── components/             # 公共组件
├── assets/
├── index.css
└── App.css
```

3、改造 `main.tsx`（开启路由）

```tsx
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import { BrowserRouter } from 'react-router-dom'
import './index.css'
import App from './App.tsx'

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <BrowserRouter>
      <App />
    </BrowserRouter>
  </StrictMode>,
)
```

4、改造 `App.tsx`（作为路由出口）

```tsx
import { Routes, Route, Link } from 'react-router-dom'
import Home from './pages/Home'
import About from './pages/About'
import NotFound from './pages/NotFound'
import './App.css'

function App() {
  return (
    <div>
      {/* 简单导航示例 */}
      <nav style={{ padding: '1rem', borderBottom: '1px solid #eee' }}>
        <Link to="/" style={{ marginRight: 16 }}>首页</Link>
        <Link to="/about">关于</Link>
      </nav>

      {/* 路由出口 */}
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
        <Route path="*" element={<NotFound />} />
      </Routes>
    </div>
  )
}

export default App
```

5、新建页面示例

**`src/pages/Home.tsx`**
```tsx
export default function Home() {
  return (
    <div style={{ padding: '2rem' }}>
      <h1>首页</h1>
      <p>这是首页内容</p>
    </div>
  )
}
```

**`src/pages/About.tsx`**
```tsx
export default function About() {
  return (
    <div style={{ padding: '2rem' }}>
      <h1>关于我们</h1>
      <p>这是关于页面</p>
    </div>
  )
}
```

**`src/pages/NotFound.tsx`**
```tsx
import { Link } from 'react-router-dom'

export default function NotFound() {
  return (
    <div style={{ padding: '2rem', textAlign: 'center' }}>
      <h1>404</h1>
      <p>页面不存在</p>
      <Link to="/">返回首页</Link>
    </div>
  )
}
```

之后新增页面只需要：
1. 在 `src/pages/` 下新建一个 `.tsx` 文件
2. 在 `App.tsx` 的 `<Routes>` 里加一条 `<Route>`



#### ⁠2.4.2 ⁠使用tsx或者jsx

一个 `.jsx`（或 `.tsx`）文件它本质上就是一个普通的 JavaScript 模块文件，完全遵循你之前了解的 ESM 工作流。`.jsx` 后缀仅仅是告诉构建工具（如 Vite）和代码编辑器，这个文件里面包含了 JSX 语法（类似 HTML 的标签结构），需要进行相应的编译解析。

可以在一个文件中包含哪些内容？

你可以在同一个文件里混合写以下所有内容：

1. **多个组件**：一个主组件加上多个拆分出来的微型辅助组件。
2. **非组件的纯函数**：用于处理数据的工具函数、API 请求函数等。
3. **常量和配置**：纯数据、枚举字典或默认配置对象。

**代码示例：**

```jsx
// 1. 导出一个普通常量
export const DEFAULT_AVATAR = '/images/default.png';

// 2. 导出一个纯工具函数
export function formatUserName(firstName, lastName) {
  return `${firstName} ${lastName}`.trim();
}

// 3. 导出一个微型辅助组件（命名导出）
export function Avatar({ url }) {
  return <img src={url || DEFAULT_AVATAR} className="w-10 h-10 rounded" />;
}

// 4. 导出这个文件的核心主组件（默认导出）
export default function UserProfile({ user }) {
  return (
    <div className="profile-card">
      {/* 在同一个文件内直接调用上面的辅助组件和函数 */}
      <Avatar url={user.avatarUrl} />
      <h2>{formatUserName(user.firstName, user.lastName)}</h2>
    </div>
  );
}

```

实际工程开发中的常见潜规则

虽然语法允许把成百上千个组件写在一个文件里，但在真实的业务项目中，大家通常会遵循一些为了方便维护的约定：

* **一文件一主组件**：通常一个 `.jsx` 文件只负责渲染一个核心的主组件，并用 `export default` 暴露出去。文件命名通常与这个主组件一致（例如 `UserProfile.jsx`）。
* **私有小组件同源**：如果主组件内部的某一块结构稍微有点复杂，需要拆成一个小组件（如上例的 `Avatar`），且这个小组件**绝不可能被其他页面复用**，就直接写在同一个文件里，不往外导，或者按需导出。
* **公共逻辑剥离**：如果发现上例中的 `formatUserName` 这种数据处理函数或者 `Avatar` 这种 UI 积木块在别的 `.jsx` 文件里也用得到，就会立刻把它们抽离到单独的 `utils/` 或 `components/` 目录下。


## ⁠3 ⁠配置说明

| 文件                   | 服务对象             | 运行环境 | 主要职责           |
| -------------------- | ---------------- | ---- | -------------- |
| `vite.config.ts`     | Vite 本身          | Node | 配置开发服务器和打包行为   |
| `tsconfig.json`      | 整个项目             | -    | 项目引用入口，串联两个子配置 |
| `tsconfig.app.json`  | `src/` 下所有代码     | 浏览器  | 应用代码的类型检查规则    |
| `tsconfig.node.json` | `vite.config.ts` | Node | 配置文件的类型检查规则    |

### ⁠3.1 ⁠`vite.config.ts`（Vite 核心配置）

```ts
import react from '@vitejs/plugin-react'
import { defineConfig } from 'vite'

// https://vite.dev/config/
export default defineConfig({
  plugins: [react()],
})
```



| 行 | 代码 | 含义 |
|----|------|------|
| 1 | `import react from '@vitejs/plugin-react'` | 引入官方 React 插件。它负责：JSX 转换、React Fast Refresh（热更新）、开发时自动注入 React 相关处理。 |
| 2 | `import { defineConfig } from 'vite'` | 引入 Vite 提供的类型辅助函数。用它包裹配置后，编辑器会有完整的类型提示和自动补全。 |
| 4 | 注释 | 官方文档链接，方便查阅所有可配置项。 |
| 5 | `export default defineConfig({ ... })` | 导出 Vite 配置对象。`defineConfig` 只是帮助类型推断，实际效果和直接 `export default { ... }` 一样。 |
| 6 | `plugins: [react()]` | 启用 React 插件。这是目前模板里**唯一真正生效的配置**。 |

1、这个文件目前很简洁的原因

官方模板故意保持最小配置，让新手先跑起来。真实项目里你通常会继续加：

```ts
export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: {
      '@': path.resolve(__dirname, 'src'), // 路径别名
    },
  },
  server: {
    port: 3000,
    proxy: { '/api': 'http://localhost:8080' }, // 开发代理
  },
  build: {
    outDir: 'dist',
    sourcemap: true,
  },
  base: '/', // 部署子路径时改这里
})
```

**所属阶段**：开发服务器启动 + 生产打包（Vite 全程使用这个文件）。


### ⁠3.2 ⁠`tsconfig.json`（TypeScript 总入口）

```json
{
  "files": [],
  "references": [
    { "path": "./tsconfig.app.json" },
    { "path": "./tsconfig.node.json" }
  ]
}
```

1、 ⁠逐行解释

| 配置项 | 含义 |
|--------|------|
| `"files": []` | 这个根配置本身**不直接编译任何文件**。它只是一个“项目引用”的容器。 |
| `"references"` | TypeScript 的 **Project References** 功能。告诉 `tsc`：这个项目由两个子项目组成。 |
| `{ "path": "./tsconfig.app.json" }` | 引用应用代码（`src/`）的配置。 |
| `{ "path": "./tsconfig.node.json" }` | 引用 Node 环境代码（主要是 `vite.config.ts`）的配置。 |

2、⁠为什么要这样拆？

- 浏览器代码需要 `DOM`、`JSX` 等类型。
- `vite.config.ts` 运行在 Node 环境，需要 `node` 类型，**不能**有 DOM。
- 拆开后，编辑器能精确知道当前打开的文件该用哪套规则，类型检查也更快。

执行 `tsc -b`（build 模式）时，会根据这个文件把两个子项目都检查一遍。


### ⁠3.3 ⁠`tsconfig.app.json`

应用代码配置，最重要

```json
{
  "compilerOptions": {
    "tsBuildInfoFile": "./node_modules/.tmp/tsconfig.app.tsbuildinfo",
    "target": "es2023",
    "lib": ["ES2023", "DOM"],
    "module": "esnext",
    "types": ["vite/client"],
    "allowArbitraryExtensions": true,
    "skipLibCheck": true,

    /* Bundler mode */
    "moduleResolution": "bundler",
    "allowImportingTsExtensions": true,
    "verbatimModuleSyntax": true,
    "moduleDetection": "force",
    "noEmit": true,
    "jsx": "react-jsx",

    /* Linting */
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "erasableSyntaxOnly": true,
    "noFallthroughCasesInSwitch": true
  },
  "include": ["src"]
}
```



#### ⁠3.3.1 ⁠基础编译选项

| 选项 | 值 | 含义 |
|------|-----|------|
| `tsBuildInfoFile` | `./node_modules/.tmp/tsconfig.app.tsbuildinfo` | 增量编译缓存文件位置。加快第二次及以后的类型检查速度。 |
| `target` | `"es2023"` | 把 TypeScript 编译成符合 ES2023 语法的 JavaScript。现代浏览器基本都能直接支持。 |
| `lib` | `["ES2023", "DOM"]` | 告诉 TypeScript 有哪些全局 API 可用。`ES2023` 提供最新 JS 特性，`DOM` 提供 `window`、`document`、`HTMLElement` 等浏览器 API。 |
| `module` | `"esnext"` | 使用最新的 ES 模块语法（`import`/`export`）。交给 Vite 去打包，不需要 TypeScript 自己转换模块。 |
| `types` | `["vite/client"]` | 只引入 Vite 的客户端类型声明。这样你就能用 `import.meta.env`、`*.svg` 等 Vite 特有功能，并且有类型提示。 |
| `allowArbitraryExtensions` | `true` | 允许导入任意扩展名的文件（比如 `.css`、`.svg`），配合 Vite 的处理。 |
| `skipLibCheck` | `true` | 跳过对 `node_modules` 里声明文件（`.d.ts`）的类型检查。大幅提升检查速度，一般项目都开。 |

#### ⁠3.3.2 ⁠Bundler 模式（专为 Vite 这类打包工具设计）

| 选项 | 值 | 含义 |
|------|-----|------|
| `moduleResolution` | `"bundler"` | 模块解析策略改成“打包工具模式”。比传统的 `node` 更适合 Vite/Webpack/esbuild。 |
| `allowImportingTsExtensions` | `true` | 允许在代码里写 `import './xxx.ts'`（带 `.ts` 后缀）。Vite 支持这种写法。 |
| `verbatimModuleSyntax` | `true` | 更严格的模块语法检查。要求 `import type` 和普通 `import` 明确区分，避免类型被错误地打进最终包。 |
| `moduleDetection` | `"force"` | 强制把所有文件都当成模块（即使没有 `import`/`export`），避免意外变成全局脚本。 |
| `noEmit` | `true` | **不输出任何 JS 文件**。类型检查只做检查，真正的编译和打包交给 Vite。这是 Vite 项目的标准做法。 |
| `jsx` | `"react-jsx"` | 使用新的 JSX 转换（React 17+）。不再需要每个文件都 `import React from 'react'`。 |

#### ⁠3.3.3 ⁠代码质量相关（类似轻度 lint）

| 选项 | 值 | 含义 |
|------|-----|------|
| `noUnusedLocals` | `true` | 定义了但没用到的局部变量会报错。 |
| `noUnusedParameters` | `true` | 函数参数定义了但没用到会报错。 |
| `erasableSyntaxOnly` | `true` | 只允许可以被完全擦除的语法（主要是类型相关），对一些会生成运行时代码的语法更严格。 |
| `noFallthroughCasesInSwitch` | `true` | `switch` 语句中禁止 case 穿透（忘记写 `break`）。 |

#### ⁠3.3.4 ⁠包含范围

```json
"include": ["src"]
```

只检查 `src/` 目录下的文件。`vite.config.ts` 不在这里面。

### ⁠3.4 ⁠`tsconfig.node.json`（Node 环境配置）

```json
{
  "compilerOptions": {
    "tsBuildInfoFile": "./node_modules/.tmp/tsconfig.node.tsbuildinfo",
    "target": "es2023",
    "lib": ["ES2023"],
    "types": ["node"],
    "skipLibCheck": true,

    /* Bundler mode */
    "module": "nodenext",
    "allowImportingTsExtensions": true,
    "verbatimModuleSyntax": true,
    "moduleDetection": "force",
    "noEmit": true,

    /* Linting */
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "erasableSyntaxOnly": true,
    "noFallthroughCasesInSwitch": true
  },
  "include": ["vite.config.ts"]
}
```

与 `tsconfig.app.json` 的关键差异

| 选项 | app 版本 | node 版本 | 原因 |
|------|----------|-----------|------|
| `lib` | `["ES2023", "DOM"]` | `["ES2023"]` | Node 环境没有 DOM，不能加 `DOM`，否则会误报。 |
| `types` | `["vite/client"]` | `["node"]` | 需要 Node 的全局类型（`process`、`__dirname`、`fs` 等）。 |
| `module` | `"esnext"` | `"nodenext"` | Node 环境用更贴近 Node 实际模块解析的策略。 |
| `include` | `["src"]` | `["vite.config.ts"]` | 只负责检查 Vite 配置文件。 |

其他选项（`noEmit`、`skipLibCheck`、lint 相关）含义与 app 配置完全相同。
