

前端页面是建立在浏览器这个软件的基础上的，对比Java，.class文文件是建立在JVM的基础上的。

| Java / 后端           | 前端                    |
| ------------------- | --------------------- |
| JVM 把 `.class` 解析执行 | 浏览器把 HTML/CSS/JS 解析渲染 |
| 你写的接口最终是 HTTP 请求/响应 | 页面本身就是一次 HTTP 响应      |
| 组合、分层、可维护性          | 语义化、盒模型、布局            |

再看和 React 的关系：**React 的最终产物仍然是 HTML/CSS/DOM**，它只是帮你更高效地生成和更新它们。如果你不知道「页面是怎么被浏览器画出来的」，就无法理解组件、状态、重渲染这些概念到底在解决什么问题。


# 从 URL 到页面

1. **DNS 解析**：域名 → IP。 类比：你在 Spring Boot 里连数据库写 `localhost:3306`；浏览器也需要把域名翻译成服务器的 IP 地址。
    
2. **发出 HTTP 请求**：浏览器向服务器要 `index.html` 等资源。 这步你本来就是专家：请求行、请求头、状态码 200/404/500……
    
3. **解析 HTML → DOM 树**：把标签文本变成内存中的一棵树（节点之间有父子/兄弟关系）。 类比：解析 JSON 变成对象树；你接触过 XML DOM，完全同构。
    
4. **解析 CSS → CSSOM，再合成渲染**： `DOM + CSSOM → 渲染树（Render Tree）→ Layout（计算每个盒子的位置和大小）→ Paint（画到屏幕上）`。
    
    - `Layout` 是「几何阶段」：这个盒子多宽？在哪一行？
        
    - `Paint` 是「美术阶段」：颜色、边框、文字。
        
5. **JS 会「插队」**：遇到 `<script>` 时，浏览器默认要停下手头工作先执行 JS（阻塞 HTML 解析）。 这也是后面为什么要引入构建工具、模块化的重要原因之一（阶段 04 的伏笔）。
    

输入 URL  
  → ① DNS：域名 → IP  
  → ② HTTP 请求 / 响应（200 OK + HTML）  
  → ③ 解析 HTML → DOM 树  
  → ④ 解析 CSS → CSSOM  
       DOM + CSSOM → 渲染树 → Layout → Paint  
  → ⑤ JS 插队执行（默认阻塞解析）  
页面出现在屏幕上

**为什么要知道这些**：后面学 React 会听到「虚拟 DOM」「diff」「重渲染」——它们都站在第 3、4 步的肩膀上做优化。
