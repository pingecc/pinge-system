## ⁠1 ⁠React是什么

传统将数据渲染到页面的步骤：
1. 发送请求获取数据
2. 处理数据（过滤、整理格式）
3. **操作DOM 呈现页面**

React 就做了第三步。

React 是一个将 **数据** 渲染为 **HTML视图**的开源JavaScript 库。也即你给React数据，React帮你渲染视图。

## ⁠2 ⁠为什么要学React

1. 原生JavaScript操作DOM繁琐，效率低（DOM- API操作UI）
2. 使用原生Java Script操作DOM，浏览器会进行大量的重绘重排
3. 原生javaScript没有**组件化**编码方案，代码复用率低

关于组件化：传统的设计只能说是模块化，也即拆JS，把功能单独拆成一个js ，而组件化不仅仅是拆js，还拆结构HTML 还有CSS，也即从页面视图的角度进行拆。

1. 采用组件化模式，声明式编码，提高开发效率及组件复用率。

## ⁠4 ⁠虚拟DOM

### ⁠4.1 ⁠为什么要有虚拟DOM

浏览器渲染一个页面要经过：解析 HTML → 生成 DOM 树 → CSSOM → 布局（Layout/Reflow）→ 绘制（Paint）→ 合成（Composite）。其中 **JavaScript 修改 DOM 很可能触发重新布局和重绘**，这是整个渲染流程里最昂贵的部分


早期的前端开发中，常见写法是：数据变了 → 手动找到对应 DOM 节点 → 直接改它。当页面简单、更新少时还能接受；一旦组件多、状态变化频繁（列表增删、表单联动、实时数据刷新等），就会出现大量不必要的 DOM 操作，导致卡顿。

更糟糕的是：

- 开发者很难精确控制“只改真正变了的部分”，容易写出重复或过度的 DOM 操作。
- 多个地方同时更新时，缺乏统一的批量与调度机制，容易造成多次强制同步布局（layout thrashing）。

React 引入虚拟 DOM 的思路是：**把“描述 UI”和“真正改 DOM”解耦**。

- 用轻量的 JavaScript 对象树（虚拟 DOM）来描述当前 UI 应该长什么样。
- 状态变化时，先生成一棵新的虚拟 DOM 树。
- 通过高效的对比（diff）算法，找出两棵虚拟树之间的最小差异。
- 最后**只把这些差异批量应用到真实 DOM 上。**

## ⁠1 ⁠函数式组件

执行了ReactDom.render(<MyComponent/>)....之后，发生了什么，React的工作过程
- React解析组件标签，找到了MyComponent组件
- 发现组件是使用函数定义的，随后调用该函数，将返回的虚拟DOM转为真是的 DOM，随后呈现在页面中
## ⁠2 ⁠类式组件

```js 
class MyComponent extends React.Component {


	render() {
	
	return <h2>....</h2>
	
	}


}
```


执行了ReactDom.render(<MyComponent/>)....之后，发生了什么，React的工作过程
- React解析组件标签，找到MyComponent组件
- 发现组件是类定义的，随后new出来该类的实例对象，通过该实例对象调用原型上的render方法
- 将render返回的虚拟DOM 转为真实的DOM，随后呈现在页面中

### ⁠3.3 ⁠事件

1、先了解下原生HTML如何给元素绑定事件的

2、render()函数中如何正确调用 自定义的其它函数：

- 直接在render() 函数中返回的标签中写 {this.changeWeather} 不管用，因为this变了，这种写法相当于直接把一个函数的引用返回了，当点击发生时，直接调用该函数，并不是通过实例对象调用函数。
```js

class Animal {
  constructor(name) {
    this.name = name;
  }

  speak() {
    console.log(`${this.name} 发出声音`);
  }
}


const dog = new Animal('旺财', '柴犬');
// 通过实例调用，此时speak内部可以拿到this
dog.speak();


const a = dog.speak;
// 函数直接调用
a()
```


![[Pasted image 20260919183819.png]]

这个时候解决办法就是，在这个changeWather被调用之前，给它绑定this指向：
1）方式1：在构造方法初始化时，通过bind()函数给changeWather() 绑定当前的this指向

```js 
this.changeWather = this.changeWather.bind(this)
```

但是如果当前类有多个自定义的函数，就要在构造方法里给每个方法单独协写上这个绑定this指向的语句，有点繁琐。

2）方式2：直接使用箭头函数来定义changeWeather，这样自动绑定外层的this，（另外在类中通过赋值语句的形式定义方法，这个方法不会挂在原型上，直接挂在实例上）

```js 

changeWather = ()=>{
	this
}
```
