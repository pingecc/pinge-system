**ESM (ECMAScript Modules)** 是 JavaScript 官方的标准化模块系统（也就是你代码里写的 `import` 和 `export`）。

  

从底层执行原理来看，浏览器或 JavaScript 引擎（如 V8）处理 ESM 并不是像传统脚本那样“按顺序边下载边执行”，而是将其拆分为了一个高度结构化的 **三阶段工作流**。

  

### 1. 构建阶段 (Construction)

这个阶段的核心任务是**下载文件、解析语法、并建立模块依赖图**，但**绝对不执行代码**。

  

- **入口触发**：浏览器遇到 `index.html` 中的 `<script type="module" src="main.ts">` 时，触发下载。
    
      
    
- **AST 解析**：引擎拿到文件后，不会立刻运行，而是将其交给编译器，扫描所有的 `import` 和 `export` 关键字，将其转换成一个名为 **Module Record（模块记录）** 的内部数据结构。
    
      
    
- **依赖图构建**：引擎根据 Module Record 里的 `import` 路径，继续发起网络请求下载下一个文件，重复上述解析过程。最终在内存中构建出一棵完整的模块依赖树（Dependency Graph）。
    
      
    

### 2. 实例化阶段 (Instantiation)

这个阶段的核心任务是**在内存中分配地址，并将所有的导入导出进行“硬连接”**。

  

- **内存分配**：引擎会采用深度优先遍历的方式，扫描依赖树的底层叶子节点。为每个模块的 `export` 声明在内存中开辟空间（此时这些内存空间里还没有真实的值，通常是 `undefined` 或处于暂存死区）。
    
      
    
- **实时绑定 (Live Bindings)**：引擎会将父模块中的 `import` 指针，直接**硬连接**到子模块 `export` 所分配的这块内存地址上。
    
      
    
- **关键特性**：这与 Node.js 传统的 CommonJS（`require`）有本质区别。CommonJS 是**值拷贝**，而 ESM 是**内存地址引用**。如果导出模块在未来修改了该变量的值，导入模块会通过相同的内存指针立刻读取到最新值。
    
      
    

### 3. 求值阶段 (Evaluation)

这个阶段的核心任务是**执行顶层代码，将真实的值填入刚才分配的内存中**。

  

- 引擎再次从依赖树的叶子节点（没有依赖其他模块的最底层文件）开始，自底向上逐个执行文件中的 JavaScript 顶层代码逻辑（函数外的代码）。
    
      
    
- 在执行过程中，计算出变量和函数的真实结果，并将它们推入第 2 阶段分配好的内存地址中。
    
      
    
- 因为是自底向上求值，当执行到最顶层的入口文件（如你的 `main.tsx`）时，它所依赖的所有底层模块的内存中都已经填满了真实的数据，程序得以安全运行。
    
      
    

**这套工作流对前端工程化的意义（Vite 的核心优势）**

  

在 Webpack 时代，工具必须在 Node 环境下人工模拟这三个阶段：把所有文件读取、解析、改写成闭包函数，最后打包成一个巨大的 `bundle.js` 塞给浏览器，导致项目越大，启动越慢。

  

你使用的 Vite 之所以极快，就是因为它**完全顺应了 ESM 工作流**。Vite 在开发环境下不进行任何打包，而是把**构建阶段**的模块依赖解析工作，直接交给了浏览器底层的 C++ 引擎去顺藤摸瓜地发起 HTTP 请求。Vite 服务器只做一个轻量级的拦截器——当浏览器请求某个 `.ts` 或 `.vue` 文件时，Vite 瞬间将其编译成合法的 ESM 格式返回，实现了真正的按需编译（O(1) 启动时间）。
