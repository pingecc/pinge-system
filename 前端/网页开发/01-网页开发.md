

# Js的职责

反过来，当我们去理解一个网页时，当涉及到下面五个时，就基本和js相关了。

## 1. 操作页面元素（改结构）

查找、创建、修改、删除 HTML 元素，这是最基础的职责。

- 查找：`document.getElementById('user-tbody')`、`document.querySelector('.menu-link')`
- 修改：`statValue.textContent = users.length`（改文字）
- 创建/删除：`users.js` 里用模板字符串拼接出 `<tr>` 插入表格

## 2. 响应交互事件（监听用户行为）

用户点击、输入、滚动、按键盘，JS 捕捉这些事件并做出反应。

```
form.addEventListener('submit', ...)      // 登录按钮
searchInput.addEventListener('input', ...) // 搜索框
tbody.addEventListener('click', ...)       // 表格里的编辑/删除
```

## 3. 管理数据和状态（内存 + localStorage + 后端）

网页的数据从哪来、存在哪、怎么变，都由 JS 管：

- 内存：`users.js` 里的 `state` 对象（当前列表、搜索词、正在编辑的 id）
- 本地：`localStorage` 读写（`Auth`、`UsersStore`）
- 后端：真实项目中用 `fetch` / axios 请求接口拿数据、提交数据（你的项目暂时没有，这是 JS 在现代网页里最重的职责）

## 4. 更新界面（数据变化 → 重新渲染）

数据一变，界面要跟着变。你的项目里反复出现的模式就是它：

```
UsersStore.saveUsers(state.users);  // 改数据
render();                            // 刷新界面
```

Vue / React 这类框架，本质上就是把这个"数据 → 界面"的同步过程自动化了——但底层仍是 JS 在做这件事。

## 5. 执行业务逻辑（校验、计算、控制流程）

表单校验、日期计算、错误提示、跳转路由、定时刷新，都属于"逻辑"：

- 校验：用户名必填、邮箱格式、用户名唯一
- 计算：`dashboard.js` 里自动生成近 7 天日期
- 流程控制：登录成功跳首页、失败显示错误；未登录访问强制跳回登录页

---

## 一句话总结

**JavaScript = 网页的"大脑 + 调度员"：它把用户的操作变成数据的变化，再把数据的变化变成界面的更新，同时负责中间所有的校验和业务逻辑。** 
顺带一提，现在 JS 还有第四个"隐藏职责"：**工程化**——模块化拆分、打包构建、跑测试，都是通过 JS 工具链完成的。不过对学习阶段来说
# 开发顺序
HTML → CSS → JS

写代码时永远按这个顺序，因为它符合依赖关系：

```
先写 HTML 骨架（结构）
  → 再写 CSS 美化（样式）
    → 最后写 JS 行为（逻辑）
```

原因很直接：**CSS 和 JS 都要靠 HTML 里的 id / class 才能找到目标**。没有 HTML，后面两层没有依附对象。

真实开发流程是：

1. **HTML**：先把表单写出来——`<form>`、两个输入框、一个按钮，顺手给它们起好 id（`username`、`password`、`remember`）
2. **CSS**：在 style.css 里让表单居中、加圆角、调颜色——用 `.login-card`、`.input-wrap` 这些类名命中元素
3. **JS**：最后在login.js里用 `getElementById('login-form')` 找到表单，绑定 `submit` 事件，写校验和跳转逻辑

所以 HTML 里那些 `id` / `class`，本质上是**写给 CSS 和 JS 的"接口"**——这是三者配合的桥梁。





1. 浏览器是从上到下逐行读 HTML 的。读到一个 `<link>` 就去下载 CSS，读到一个 `<script>` 就去下载并执行 JS。
2. JS 的执行会"阻塞"解析。** 浏览器读到 `<script>` 时必须停下来，等 JS 下载并跑完，才能继续往下读 HTML。所以你把 JS 放在 `</body>` 前面，确保执行时上面的 HTML 已经读完、元素已经存在，`getElementById` 才找得到。
3. CSS 放在 `<head>` 里，是为了先有样式。如果 CSS 放最后，页面会先显示没样式的裸 HTML、再突然变样（闪一下，叫 FOUC）。放前面则浏览器解析到内容时，样式已经就绪。
4. 渲染不一定等所有资源。** 大图片不会阻塞页面解析（但会阻塞 `load` 事件），所以"页面能交互"和"所有资源加载完"是两件事。
