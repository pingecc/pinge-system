由 Google 于 2007 年设计并于 2009 年正式开源的一种**静态强类型、编译型**编程语言。它的核心设计哲学是“大道至简”。

# Hello World
一个Go语言编写的程序对应一个或多个以.go为文件后缀名的源文件。每个源文件中以包的声明语句开始，说明该源文件是属于哪个包。包声明语句之后是import语句导入依赖的其它包
```go
package main
import "fmt"
func main() {
    fmt.Println("Hello, 世界")
}
```


Go 语言提供的工具都通过一个单独的命令 `go` 调用，`go` 命令有一系列子命令。最简单的一个子命令就是 `run`。这个命令编译一个或多个以。`.go` 结尾的源文件，链接库文件，并运行最终生成的可执行文件。
```bash
$ go run helloworld.go
Hello, 世界
```

> 注意，要想直接可以运行的话，请你写在`main.go` 中，在 Go 语言中，`main` 是一个特殊的包名。只有当包名为 `main` 且其中包含 `func main()` 时，Go 编译器才会将其识别为程序的入口点。


- Go 语言不需要在语句或者声明的末尾添加分号。

# 程序结构


## 命名

Go语言中的函数名、变量名、常量名、类型名、语句标号和包名等所有的命名，都遵循一个简单的命名规则：**一个名字必须以一个字母（Unicode字母）或下划线开头**，后面可以跟任意数量的字母、数字或下划线。大写字母和小写字母是不同的：heapSort和Heapsort是两个不同的名字。Go语言程序员推荐使用 **驼峰式** 命名


## 声明
Go语言主要有四种类型的声明语句：var、const、type和func，分别对应变量、常量、类型和函数实体对象的声明。这里主要讨论变量个类型的声明。

1、语法：
```go
// 使用const关键字
const identifier [type] = value
```


2、声明的位置：
- 在包下面直接声明，通过首字母大小写来区分是否可以被其他包导入使用
- 在函数内或者代码块中声明：局部常量
```go


package main

import "fmt"

// 这是一个包级导出常量，其他包导入当前包后可用
const MaxConnections = 100 

// 这是一个包级未导出常量，仅当前包可用
const defaultTimeout = 30  

func main() {
    fmt.Println(MaxConnections, defaultTimeout)
}
```

## 变量

1、使用`var` 来声明变量：

```go
var 变量名字 类型 = 表达式

var name string = "Alice"
var age int = 25

// 如果不赋初值，Go 会自动赋予“零值”（Zero Value），而不会像 Java 那样报未初始化错误
var count int    // 自动等于 0
var isValid bool // 自动等于 false
var text string  // 自动等于 "" (空字符串，不是 nil)
```

2、使用new函数
表达式new(T)将创建一个T类型的匿名变量，初始化为T类型的零值，然后返回变量地址，返回的指针类型为`*T`。
```go
p := new(int)   // p, *int 类型, 指向匿名的 int 变量
fmt.Println(*p) // "0"
*p = 2          // 设置 int 匿名变量的值为 2
fmt.Println(*p) // "2"

```

3、使用 `:=` 进行自动推导，常用方式

```go
// 省略 var 和类型，直接推导
name := "Bob"     // 推导为 string
price := 99.9     // 推导为 float64
isActive := true  // 推导为 bool

// 支持平行赋值，非常适合接收函数的多个返回值
x, y := 10, 20
```
> 注意：`:=` 只能在**函数内部**使用，不能用于声明全局（包级别）变量。
> **局部变量声明必须使用：** 如果你在函数内部声明了一个局部变量，但在后续代码中没有使用它，Go 编译器会直接报错（`declared and not used`），导致编译失败。全局变量则不受此限制。


4、批量声明

当需要一次性声明多个全局或局部变量时，可以使用 `var` 括号块，避免重复写 `var` 关键字。这在定义包级别的配置项时非常常见。
```go
var (
    globalTimeout int    = 30
    serverPort    string = ":8080"
    isReady       bool   // 默认为 false
)
```

### 指针
Go 语言的指针在底层机制上与 C 语言的指针**完全是一回事**，专门用于存储地址的一种数据类型（它们在内存中存储的都是一个纯粹的虚拟内存地址，通常占用 8 个字节）。
#### 指针的本质
问：指针指向的是变量的内存地址，还是数据的内存地址？
在 Go（以及 C）中，**“变量本身的内存地址”和“变量指向的数据所在的内存地址”是同一个概念。**
变量名仅仅是编译器提供给人类阅读的**逻辑占位符**，在最终编译出的机器码中，变量名是不存在的，全都是内存地址。
假设你写了这样一段代码：

```go
var a int = 10
var p *int = &a

```
在内存（虚拟地址空间）中，底层发生的事情如下：
1. 系统在栈（或堆）上分配了一块 8 字节的内存（假设地址是 `0x1000`），将数字 `10` 的二进制存入这块内存。此时，变量 `a` 就代表 `0x1000` 这个地址。
2. 系统又分配了另一块 8 字节的内存（假设地址是 `0x2000`）来存放指针变量 `p`。
3. 把 `a` 的地址（即 `0x1000`）作为数据，存入 `0x2000` 这块内存中。
因此，**指针 `p` 存储的是变量 `a` 的内存地址，而这个地址，就是实实在在存放数字 `10` 这块数据的物理起点。** 当你对指针进行解引用操作 `*p` 时，CPU 会读取 `0x2000` 里的值（得到 `0x1000`），然后顺藤摸瓜去 `0x1000` 把里面的 `10` 读出来。

---
#### 指针使用

在 Go 语言中，指针的使用非常务实，主要围绕两个核心操作符展开：`&`（取地址）和 `*`（根据地址解引用）。

由于 Go 语言在函数调用时**永远是值传递（Pass by Value）**——即将实参在内存中完整拷贝一份传递给形参，指针的存在主要是为了打破这种数据隔离，实现数据的跨作用域修改和零拷贝。

```go
package main

import "fmt"

func main() {
    age := 25
    
    // 使用 & 取得 age 在虚拟内存中的地址，赋给指针变量 p
    var p *int = &age 
    // 或者简写为: p := &age

    fmt.Println("age 的内存地址:", p) // 输出类似: 0x1400012a008
    
    // 使用 * 对指针解引用，直接向该内存地址写入新数据
    *p = 26 
    
    fmt.Println("修改后的 age:", age) // 输出: 26
}
```

#### 使用场景

场景一：在函数内部修改外部变量的状态（最常见）
```go
type User struct {
    Name string
    Role string
}

// 接收值（拷贝），无法修改原对象
func updateRoleFail(u User) {
    u.Role = "Admin" // 只是修改了 u 的副本
}

// 接收指针（地址），直接在原内存上修改
func updateRoleSuccess(u *User) {
    u.Role = "Admin" 
    // 注意：Go 提供了语法糖，对于结构体指针，不需要写 (*u).Role，直接写 u.Role 即可
}

func main() {
    user := User{Name: "Alice", Role: "Guest"}
    
    updateRoleFail(user)
    // user.Role 依然是 "Guest"
    
    updateRoleSuccess(&user)
    // user.Role 变成了 "Admin"
}
```

> 如果一个结构体非常庞大（例如包含几十个字段，占用几百字节内存），作为参数传递时触发的值拷贝会消耗 CPU 时钟周期并带来内存压力。 传入指针（`*Struct`），无论原始结构体多大，拷贝传递的永远只是一个 8 字节（在 64 位系统上）的虚拟内存地址，极大提升了执行效率。



**指针的初始化方式：**

在 Go 中，声明一个指针但未赋值时，其默认值为 `nil`。如果直接对 `nil` 指针解引用赋值，会导致 `panic`（类似 Java 的 NullPointerException）。你需要先为其分配内存：

**方式一：使用结构体字面量取址（推荐，最符合 Go 习惯）**

```go
// 一步到位：在堆区分配内存，初始化字段，并返回地址
u := &User{
    Name: "Bob",
    Role: "Admin",
}
```

方式二：使用内置函数 `new()`
```go
// new() 会在内存中分配空间，将字段全部置为零值，然后返回内存地址
u := new(User) 
u.Name = "Bob"
```


**绝对不该使用指针的场景**

- **不要对 Slice（切片）、Map（字典）、Channel（管道）使用指针：** 这些数据结构在 Go 底层已经是“引用描述符”（例如 Slice 底层是一个结构体，内部包含了一个指向底层数组的指针 `unsafe.Pointer`）。直接传递 `[]int` 或 `map[string]int` 就已经具备了修改底层数据和极小拷贝开销的特性，不需要画蛇添足地使用 `*[]int`。
    
- **不要为了“像 Java 一样一切皆对象”而滥用指针：** 对于简单且轻量的结构体（如仅包含几个 `int` 字段的坐标点 `Point`），直接传值（按值返回）是更好的选择。这会让变量安全地留在 CPU 的栈（Stack）上，随着函数结束瞬间销毁，避免触发逃逸分析（Escape Analysis）将变量推向堆（Heap），从而减轻垃圾回收器（GC）的扫描负担。

### 声明周期

在 Go 语言中，讨论变量的生命周期，首先要区分**作用域（Scope）**和**生命周期（Lifecycle）**。作用域是编译期的概念（代码里能在哪里访问它），而生命周期是运行期的概念（变量在内存中存活的时间，从分配到回收）。

Go 语言中变量的生命周期主要分为两大类：**包级变量（全局变量）** 和 **局部变量**。由于 Go 拥有独特的内存管理机制，局部变量的生命周期走向完全由**编译器**决定。

####  包级变量（全局变量）

包级变量的生命周期与**整个程序的运行周期**完全一致。

* **创建与初始化：** 在 `main` 函数执行之前，Go 运行时（Runtime）会根据包的依赖顺序，为其在数据段（Data Segment/BSS）分配内存并进行初始化。如果包含 `init()` 函数，也会在这个阶段执行。
* **销毁：** 只有当整个程序退出（`main` 函数执行完毕或调用 `os.Exit` 崩溃）时，这些变量占用的内存才会被操作系统整体回收。

####  局部变量与“逃逸分析”

在 Java 中，基本数据类型在栈上，对象统统在堆上。在 C 语言中，局部变量全在栈上，想放堆上必须手动 `malloc`。Go 语言打破了这种规则：**局部变量到底分配在栈（Stack）上还是堆（Heap）上，完全由编译器通过“逃逸分析（Escape Analysis）”自动决定。** 这直接决定了局部变量的生命周期长短。

1、**未逃逸的局部变量（分配在栈上）**
如果编译器分析后确认，一个局部变量的物理内存地址**绝对不会被函数外部引用**，它就会被分配在当前函数的栈帧（Stack Frame）上。

* **生命周期起点：** 函数执行到该变量的声明语句时，CPU 通过移动栈顶指针（如 `SUB RSP` 指令）为其分配内存。
* **生命周期终点：** 函数执行完毕返回（`RET` 指令）的瞬间，栈帧被弹出，这块内存立刻失效并被系统回收。
* **特点：** 生命周期极短，分配和回收成本几乎为零（仅需几条汇编指令），完全不需要垃圾回收器（GC）介入，是最理想的运行状态。


**2、逃逸的局部变量（分配在堆上）**

如果编译器发现一个局部变量的地址在函数结束后**仍然可能被外部访问**，为了防止出现类似 C 语言的“悬挂指针（Dangling Pointer）”导致系统崩溃，编译器会强制将这个变量“逃逸”到堆（Heap）上分配。

* **生命周期起点：** 运行时通过内存分配器（类似 `tcmalloc` 的机制）在堆上寻找合适的空闲内存块进行分配。
* **生命周期终点：** 函数结束并不影响它的存活。它的生命周期直到**没有任何活动对象（可达路径）引用它**为止。此时，Go 的后台垃圾回收器（GC）会在下一次扫描时将其标记为垃圾，并异步回收其内存。

 **触发逃逸的常见场景**

掌握生命周期的关键，就是识别哪些操作会迫使变量离开栈区，变成由 GC 管理的长期对象：

1. **返回局部变量的指针：** 这是最典型的逃逸。
```go
func createConfig() *Config {
    cfg := Config{Host: "localhost"}
    return &cfg // cfg 的地址被返回，必定逃逸到堆上
}

```


2. **闭包捕获（Closure Capture）：** 匿名函数访问了外部函数的局部变量。
```go
func counter() func() int {
    count := 0
    return func() int {
        count++ // count 被内部函数引用，逃逸到堆上，生命周期与返回的函数实例绑定
        return count
    }
}

```


3. **发送指针到 Channel：** 在编译期，编译器无法得知究竟是哪个 Goroutine 会在什么时候从 Channel 中接收并使用这个指针，因此只能保守地将其分配在堆上。
4. **动态类型逃逸（赋值给 `interface{}`）：** 如果将变量赋值给接口类型（如最常用的 `fmt.Println(x)`，其参数是 `...any`），因为接口底层需要存储实际类型和数据指针，编译器通常无法在编译期确定其具体行为，往往会导致变量逃逸。
5. **变量体积过大：** 即使没有外部引用，如果局部变量占用内存极大（例如 `var arr [100000]int`），超过了栈帧的限制，也会被直接分配到堆上。

Go 语言通过逃逸分析，巧妙地融合了 C 语言的栈内存高效性和 Java 语言的堆内存安全性。在实际开发中，开发者无需手动干预内存分配，只需遵循“少用不必要的指针、尽量按值传递小结构体”的原则，就能让绝大多数局部变量在栈上快速生灭，从而大幅减轻 GC 压力，维持极高的系统吞吐量。

## 赋值

1、多重赋值与状态交换

```go
a, b := 10, 20
a, b = b, a // a 变成 20，b 变成 10
```


2、`:=` 的“半声明半赋值”特性

`:=` 用于声明并初始化新变量，要求等号左侧至少有一个全新声明的变量，**已经存在的老变量就会自动退化为“重新赋值”**，而不会引发重复声明（redeclared）的编译错误。

```go
// 第一次调用，f 和 err 都是在当前作用域新声明的变量
f, err := os.Open("file.txt") 

// 第二次调用，d 是新变量，但 err 是上面已经存在的变量
// 此时对 err 只是执行单纯的内存覆写（赋值），依然可以使用 :=
d, err := f.Stat()
```
> 这在 Go 的工程实践中极其常见。由于 Go 习惯通过返回 `error` 来处理异常，这个特性避免了开发者为了接收不同函数的错误去起 `err1`, `err2` 这种冗余的变量名。


3、底层核心：**绝对的“值拷贝”语义**

在 **Java** 中，对对象进行赋值（如 `User b = a;`），仅仅是拷贝了引用（即堆内存地址），`a` 和 `b` 在物理上指向同一片数据。 但在 **Go** 中，**所有的基本赋值（`=`）全都是将内存中的数据原样完整复制一份（Value Copy）。**

```go
type User struct {
    Name string
    Age  int
}

a := User{Name: "Alice", Age: 25}
b := a     // 发生物理级的内存拷贝，b 是 a 的完美克隆体
b.Age = 30 // 修改 b 所在的内存块，a 完全不受影响

// 如果想要实现 Java 那种多变量共享同一片内存的效果，必须显式传递指针地址
var c *User = &a 
c.Age = 40 // CPU 根据指针找到 a 的内存并修改，此时 a.Age 变成 40
```

## 类型

Go 语言的类型系统设计极为务实，它抛弃了传统面向对象语言（如 Java）中复杂的继承树，回归了类似 C 语言的底层内存视角，同时又引入了现代语言的安全机制。

Go语言将数据类型分为四类：基础类型、复合类型、引用类型和接口类型。

### 基本类型
这是直接映射到 CPU 寄存器和基本内存单元的类型。
- **整型 (Integer)：**
    - 显式位宽：`int8`, `int16`, `int32`, `int64` 以及对应的无符号版本 `uint8` 等。
    - **架构自适应：`int` 和 `uint`**。这是最常用的。它们的大小直接取决于你的操作系统架构（64 位系统上是 8 字节，32 位系统上是 4 字节）。
- **浮点型：** 只有 `float32` 和 `float64`，没有 `double` 关键字。
- **字符型（极具 Go 特色）：**
    - **`byte`**：本质上是 `uint8` 的别名，代表一个 ASCII 字符或原始二进制数据的 1 个字节。
    - **`rune`**：本质上是 `int32` 的别名，代表一个 **Unicode 字符**。因为中文字符在 UTF-8 编码下占 3 个字节，用 `byte` 处理会乱码，所以在 Go 中遍历处理中文字符串时，底层用的都是 `rune`。
- **字符串 (`string`)：** 底层是一个不可变（Immutable）的字节切片。它的内存结构只有两部分：一个指向底层字节数组的指针，和一个长度 `len`。

### 复合值类型
这些类型在赋值或作为函数参数传递时，会**完整拷贝整块内存数据**。
- **数组 (`[n]T`)：**
    - 与 Java 不同，**Go 的数组是纯粹的值类型**。`[3]int` 和 `[4]int` 在编译期被视为**完全不同的两种类型**，不能互相赋值。如果你把一个长度为 10 万的数组传给函数，Go 会老老实实地在内存里拷贝 10 万个元素。因此在 Go 中，极少直接使用数组，而是使用切片。
- **结构体 (`struct`)：**
    - 用来将多个不同类型的数据聚合在一起。它的内存布局是绝对连续的（类似 C 语言），零对象头开销，非常适合做底层网络协议解析或极致的性能优化。


### 引用描述符类型

它们在底层其实是**对复杂数据结构的一种轻量级封装（内部包含指针）**，传递它们时，虽然也是值拷贝，但拷贝的仅仅是“描述符”，因此能够实现修改底层共享数据的效果。
- **切片 (`slice` 即 `[]T`)：** 动态数组。底层结构是一个包含 `指针`、`长度(len)`、`容量(cap)` 的 24 字节结构体。
- **字典 (`map` 即 `map[K]V`)：** 哈希表。底层的 `hmap` 结构体指针。
- **通道 (`channel` 即 `chan T`)：** Go 并发模型的核心，用于 Goroutine 之间的通信。
- **指针 (`*T`)：** 存储内存地址。
- **函数 (`func`)：** 在 Go 中函数是一等公民，可以作为类型赋值给变量。

### 接口类型
这是 Go 语言实现多态的唯一手段，也是 Go 架构设计的灵魂。
- **隐式实现（Duck Typing）：** Go 没有 `implements` 关键字。只要一个结构体实现了某个接口定义的所有方法，编译器就自动认为该结构体属于这个接口类型（“只要走起来像鸭子，叫起来像鸭子，它就是鸭子”）。这种非侵入式设计让代码解耦极其容易。
- **空接口 (`interface{}` 或 `any`)：** 不包含任何方法的接口。因为所有类型至少都实现了“零个方法”，所以 `any` 可以接收 Go 语言中的**任何类型**（类似于 Java 中的 `Object`，但 `any` 连基础类型 `int` 也能直接接收，无需装箱）。


### 自定义类型

Go 允许基于现有类型创造新类型，有两种截然不同的语法：
```go
// 1. 类型定义 (Type Definition)：创造了一个全新的类型
// MyInt 和 int 在编译器眼里是完全不同的类型，不能直接运算，必须强转。
// 用途：为基本类型绑定新的面向对象的方法。
type MyInt int 

// 2. 类型别名 (Type Alias)：仅仅是起个外号 (Go 1.9 引入)
// MyAlias 和 int 完全等价，可以混合运算。
// 用途：重构大型项目时，平滑迁移代码。
type MyAlias = int
```

## 二元运算符

```go
package main

import "fmt"

func main() {
    a, b := 10, 3
    
    // 算术与字符串运算
    fmt.Println("a / b =", a/b) // 输出 3 (注意没有小数)
    fmt.Println("hello" + " world") // 输出 hello world

    // 位清空操作符 (&^) 示例
    // a = 10 (二进制 1010), b = 3 (二进制 0011)
    // a &^ b => 把 a 中对应 b 为 1 的位置全部清零
    // 1010 &^ 0011 = 1000 (十进制 8)
    fmt.Println("10 &^ 3 =", a&^b) 
}
```


在Go语言中，二元运算符是需要两个操作数才能完成计算的符号（例如 `a + b`）。Go的二元运算符主要分为四大类：算术、关系、逻辑和位运算符。

### 1. 算术运算符

用于执行常见的数学运算。对于字符串类型，`+` 也可用于拼接。

| 运算符 | 描述 | 示例 (`a=10`, `b=3`) |
| --- | --- | --- |
| `+` | 相加 / 字符串拼接 | `a + b` 结果为 13 |
| `-` | 相减 | `a - b` 结果为 7 |
| `*` | 相乘 | `a * b` 结果为 30 |
| `/` | 相除（整数相除会直接截断小数部分） | `a / b` 结果为 3 |
| `%` | 取模（求余数，只能用于整数） | `a % b` 结果为 1 |

### 2. 关系（比较）运算符

用于比较两个值，计算结果始终为布尔值（`true` 或 `false`）。

| 运算符 | 描述 | 示例 (`a=10`, `b=20`) |
| --- | --- | --- |
| `==` | 检查两个值是否相等 | `a == b` 为 false |
| `!=` | 检查两个值是否不相等 | `a != b` 为 true |
| `>` | 大于 | `a > b` 为 false |
| `<` | 小于 | `a < b` 为 true |
| `>=` | 大于或等于 | `a >= b` 为 false |
| `<=` | 小于或等于 | `a <= b` 为 true |

### 3. 逻辑运算符

用于连接多个布尔表达式，支持**短路求值**（如果左侧表达式已经能够决定最终结果，则不会计算右侧表达式）。

| 运算符 | 描述 | 示例 (`x=true`, `y=false`) |
| --- | --- | --- |
| `&&` | 逻辑 AND (两边都为true才返回true) | `x && y` 为 false |
| `||` | 逻辑 OR (只要有一边为true就返回true) | `x || y` 为 true |

### 4. 位运算符

直接对整数的二进制位进行底层操作。Go语言中没有 `~` 作为一元按位取反操作符，而是用 `^` 代替，同时引入了特有的位清空运算符 `&^`。

| 运算符 | 描述 | 二进制逻辑示例 |
| --- | --- | --- |
| `&` | 按位 AND (同为1才为1) | `1010 & 1100` = `1000` |
| `|` | 按位 OR (有一个为1就为1) | `1010 | 1100` = `1110` |
| `^` | 按位 XOR (异或，相同为0，不同为1) | `1010 ^ 1100` = `0110` |
| `&^` | **按位清空 (AND NOT)** | `a &^ b` (若 b 的某位为1，则将 a 对应的位强制清0) |
| `<<` | 左移 (相当于乘以2的n次方) | `1 << 2` 结果为 4 |
| `>>` | 右移 (相当于除以2的n次方) | `4 >> 1` 结果为 2 |

## 条件分支与循环
Go 语言的控制结构设计非常精简。最显著的特点是**条件表达式不需要加括号 `()**`，且大括号 `{}` 是强制要求的（左大括号必须与关键字在同一行）。
### 条件
**`if` 和 `else**`
最基本的用法与其他语言类似，但 Go 支持在条件判断前执行一条初始化语句，这在处理函数返回值（尤其是错误处理）时极其常见。初始化声明的变量作用域仅限于 `if` 和 `else` 块内。

```go
// 基础用法
if score >= 90 {
    fmt.Println("优秀")
} else if score >= 60 {
    fmt.Println("及格")
} else {
    fmt.Println("不及格")
}

// 带有初始化语句的 if（Go 惯用语法）
if err := doSomething(); err != nil {
    fmt.Println("发生错误:", err)
    return
}

```

**`switch` 语句**
Go 的 `switch` 比大多数语言更安全、更灵活。**默认自带 `break**`（匹配成功并执行完代码块后自动退出整个 switch，不会发生意外的穿透）。如果需要向下穿透，必须显式声明 `fallthrough`。

```go
// 基础用法
// 可以写初始化语句，后面跟着变量 day，指定判断目标，这样switch语句执行结束之后，da变量也回收
switch day := time.Now().Weekday(); day {
case time.Saturday, time.Sunday: // 可以用逗号分隔多个条件
    fmt.Println("周末，休息！")
case time.Monday:
    fmt.Println("周一综合征")
default:
    fmt.Println("普通工作日")
}

// 把score变量写在switch外面，扩大作用域
score := 85
switch {
case score >= 90:
    fmt.Println("级别: A")
case score >= 80:
    fmt.Println("级别: B")
default:
    fmt.Println("级别: C")
}

```

### 循环


Go 语言极度克制，**只有 `for` 这一种循环关键字**，没有 `while` 或 `do-while`。它通过调整表达式实现了所有的循环场景。

**标准循环 (类似 C/Java)**
包含初始化、条件和后置语句。

```go
for i := 0; i < 5; i++ {
    fmt.Println(i)
}

```

**替代 `while` 循环**
省略初始化和后置语句，只保留条件判断。

```go
n := 1
for n < 10 {
    fmt.Println(n)
    n *= 2
}

```

**无限循环**
省略所有表达式。通常配合 `break`（完全跳出循环）或 `continue`（跳过当前迭代直接进入下一次循环）进行控制。

```go
for {
    msg := receiveMessage()
    if msg == "stop" {
        break
    }
}

```

**`for range` 迭代器**
遍历数据结构（数组、切片、Map、字符串和 Channel）的首选方式。每次迭代返回两个值：第一个是索引或键，第二个是对应的值的拷贝。

```go
names := []string{"Alice", "Bob", "Charlie"}

// 同时获取索引和值
for index, name := range names {
    fmt.Printf("第 %d 位: %s\n", index, name)
}

// 使用下划线 _ 忽略不需要的返回值（例如只取值，不要索引）
for _, name := range names {
    fmt.Println("名字:", name)
}

// 遍历 Map (无序)
ages := map[string]int{"Alice": 25, "Bob": 30}
for key, value := range ages {
    fmt.Printf("%s 是 %d 岁\n", key, value)
}

```

# 数据类型

虽然从底层而言，所有的数据都是由比特组成，但计算机一般操作的是固定大小的字，如整数、浮点数、比特数组、内存地址等。

Go语言将数据类型分为四类：基础类型、复合类型、引用类型和接口类型。

## 基础数据类型

### 整型
Go 语言的整型设计直接体现了它面向系统编程和极致内存控制的哲学。与 Java 中固定字节大小的整型（如 `int` 永远是 4 字节）不同，Go **提供了非常细粒度的整型划分**，将硬件架构的差异和内存的精确控制交还给了开发者。



Go 的整型可以清晰地划分为四大类：
- 架构自适应整型 int，推荐使用，除非严格控制内存占用
- 精确宽位类型 

Go中的整型使用工程规范：
- **禁止隐式类型转换**

#### 1. 架构自适应整型int（最常用）

这是日常业务开发中最常用的类型。它们的物理内存大小不是固定的，而是**直接取决于程序运行的底层操作系统和 CPU 架构**。

* **`int` 和 `uint` (无符号)：**
* 在 64 位操作系统上，它们占用 **8 个字节 (64 bit)**，等同于 CPU 的通用寄存器大小。
* 在 32 位操作系统上，它们占用 **4 个字节 (32 bit)**。


* **工程惯例：** 当你使用短变量声明 `count := 10` 时，Go 编译器默认推导出的类型就是 `int`。**在不涉及严格内存限制或网络协议封包的普通业务逻辑中，首选 `int`**，因为它能最大化利用当前 CPU 的原生处理字长，性能最高。

#### 2. 精确位宽整型（固定大小）

当你需要**严格控制内存占用**，或者处理网络协议、文件二进制结构、跨平台序列化时，必须使用这类明确指明内存大小的整型，以确保在任何机器上行为绝对一致。

* **有符号整型：** `int8`, `int16`, `int32`, `int64`
* **无符号整型：** `uint8`, `uint16`, `uint32`, `uint64`
> 场景示例：如果你要真正在内存里存一个包含 100 万个状态标志的数组，使用 `[]int8` 会比 `[]int` 节省整整 7 倍的内存（在 64 位机器上）。

#### 3. 语义化别名类型

Go 提供了两个特殊的类型别名，它们在物理上等同于基础整型，但在代码阅读上提供了强烈的业务语义：

* **`byte` (本质是 `uint8`)：** 强调这是一个**原始的二进制字节**数据。在处理网络流、文件读写、加密解密时，Go 统一使用 `[]byte`（字节切片），而不是 `[]uint8`。
* **`rune` (本质是 `int32`)：** 强调这是一个**完整的 Unicode 字符**。由于 UTF-8 编码的汉字通常占 3 个字节，用 1 字节的 `byte` 无法完整容纳。当你用 `for range` 遍历包含中文的字符串时，Go 会自动将每次迭代的字符解析为一个 4 字节的 `rune`，防止出现乱码或截断。

#### 4. 底层指针整型

* **`uintptr`：** 这是一个无符号整型，其大小刚好足以容纳当前系统的一个**内存指针地址**。它主要配合 `unsafe` 包使用，用于绕过 Go 的类型安全检查，直接进行类似 C 语言的底层内存偏移量计算（Pointer Arithmetic）。这是 Go 预留给极客操作底层硬件或与 CGO 交互的后门。



### 浮点数
**1. 核心类型**
* `float32`（单精度）：占用 4 个字节（32位），提供约 6 个十进制数字的精度。
* **`float64`（双精度）**：占用 8 个字节（64位），提供约 15 个十进制数字的精度。常用。

**2. 默认推导与最佳实践**
在使用自动类型推导（`:=`）时，Go 默认会将带有小数点的数值推导为 `float64`。

```go
var a float32 = 3.14 // 显式声明为 float32
b := 3.14            // 默认推导为 float64

```

**最佳实践**：在大多数情况下，应优先使用 `float64`。`float32` 精度较低，在进行多次算术运算时误差累积非常快，通常只在对内存占用有极致要求（如海量3D图形渲染数据）时使用。Go 的 `math` 标准库中的所有函数均接受并返回 `float64`。

**3. 精度丢失问题**
由于浮点数在计算机底层是以二进制分数表示的，某些十进制小数无法精确转换，会导致经典的精度丢失现象：

```go
fmt.Println(0.1 + 0.2) // 输出: 0.30000000000000004

```

**4. 浮点数比较**
因为精度丢失的存在，**绝对不能直接使用 `==**` 来比较两个浮点数是否相等。正确的做法是定义一个极小的误差范围（Epsilon），判断两数差值的绝对值是否小于该范围：

```go
package main

import (
	"fmt"
	"math"
)

func main() {
	a := 0.1 + 0.2
	b := 0.3
	
	// 错误做法： fmt.Println(a == b) // false
	
	// 正确做法：
	epsilon := 1e-9
	if math.Abs(a-b) < epsilon {
		fmt.Println("a 和 b 相等")
	}
}

```

**5. 格式化输出**
使用 `fmt` 包打印浮点数时，常用的占位符包括：

* `%f`：默认输出格式（通常保留6位小数）。
* `%.2f`：保留2位小数并进行四舍五入。
* `%e` / `%E`：科学计数法表示（如 `1.234568e+06`）。
* `%g`：根据数值大小自动选择 `%f` 或 `%e`，并自动去掉末尾的无用零。

**6. 特殊值**
Go 的 `math` 包支持 IEEE-754 规定的特殊浮点值：
* **`NaN` (Not a Number)**：例如 `0.0 / 0.0`，可用 `math.IsNaN()` 判断。
* **`+Inf` / `-Inf` (无穷大)**：例如 `1.0 / 0.0`，可用 `math.IsInf()` 判断。
### 复数

### 布尔类型
Go语言中的布尔类型（`bool`）非常简单直接，但在类型安全方面比 C/C++ 或 Python 等语言更加严格。以下是 Go 中布尔类型的核心知识点：

**1. 基础定义与取值**

* 布尔类型的关键字是 **`bool`**。
* 它只有两个预定义的常量值：**`true`** 和 **`false`**。
* 布尔值通常占用 1 个字节（byte）的内存空间。

**2. 默认零值**
如果在声明布尔变量时没有进行初始化，它的默认零值是 **`false`**。

```go
var isActive bool
fmt.Println(isActive) // 输出: false

```

**3. 严格的类型限制（无隐式转换）**
这是 Go 区别于很多其他语言的重要特点：**Go 不允许将其他类型（如整型、字符串、指针等）隐式转换为布尔值。**

* 在 C 或 Python 中，`0`、`""` 或 `nil` 可以被当作 `false`，非零值当作 `true`。
* 在 Go 中，这样做会导致**编译错误**。你必须显式地进行条件判断。

```go
// 错误做法（编译报错：non-bool (type int) used as if condition）
count := 1
if count { 
    fmt.Println("Count > 0")
}

// 正确做法：必须产生一个明确的 bool 结果
if count != 0 {
    fmt.Println("Count > 0")
}

```

**4. 逻辑运算符与短路求值**
布尔类型主要用于条件控制语句（`if`、`for` 等），配合以下三种逻辑运算符使用：

* **`&&` (逻辑 AND)**：只有两边都为 `true`，结果才为 `true`。
* **`||` (逻辑 OR)**：只要有一边为 `true`，结果就为 `true`。
* **`!` (逻辑 NOT)**：取反，`!true` 等于 `false`。

**短路求值（Short-circuit evaluation）**：
Go 会遵循短路原则，这意味着如果左侧的表达式已经能决定最终结果，右侧的表达式将不会被执行。这在防止空指针异常或避免不必要的函数调用时非常有用。

```go
// 如果 a 为 false，b() 将完全不会被执行
if a && b() { ... } 

// 如果 c 为 true，d() 将完全不会被执行
if c || d() { ... }

```

**5. 格式化输出**
在使用 `fmt` 包打印布尔值时，专门的占位符是 **`%t`**：

```go
isValid := true
fmt.Printf("状态是否有效: %t\n", isValid) // 输出: 状态是否有效: true

```
### 字符串

Go语言中的字符串（`string`）是一个非常核心且设计独特的类型。它默认全面支持 UTF-8 编码，并且在底层结构和内存管理上有严格的规范。以下是 Go 字符串的核心机制：

**1. 本质与底层结构**
在 Go 中，字符串本质上是一个**只读的字节切片（byte slice）**。底层由一个指向字节数组的指针和字符串的字节长度组成。
因为默认使用 UTF-8 编码，所以英文字符占用 1 个字节，而中文字符通常占用 3 个字节。

**2. 绝对的不可变性（Immutability）**
字符串一旦创建，其底层的数据就不能被修改。你不能像在 C 语言中那样通过索引直接更改某个字符。

```go
s := "hello"
// s[0] = 'H' // 错误：编译不通过（cannot assign to s[0]）

// 正确的修改方式：先转为切片，修改后再转回字符串
b := []byte(s)
b[0] = 'H'
s = string(b)

```

**3. 长度计算（字节数 vs 字符数）**
由于 UTF-8 是变长编码，内置函数 `len()` 返回的是**字节数**，而不是直观的字符个数。

```go
import "unicode/utf8"

s := "Go语言"
fmt.Println(len(s))                    // 输出: 8 (Go占2字节，'语言'占6字节)
fmt.Println(utf8.RuneCountInString(s)) // 输出: 4 (实际的字符数量)

```

**4. 两种遍历方式 (Byte vs Rune)**
因为中英文混排时的字节长度差异，Go 提供了两种不同的遍历方式：

* **按字节遍历**（使用传统 `for` 循环）：可能会截断中文字符导致乱码。
* **按字符（Rune）遍历**（使用 `for range`）：Go 会自动将 UTF-8 解码为 Unicode 字符（在 Go 中称为 `rune`，本质是 `int32`）。这是处理包含中文等非 ASCII 字符字符串的标准做法。

```go
s := "Go语言"
// 按 rune 遍历（推荐）
for index, char := range s {
    fmt.Printf("位置: %d, 字符: %c\n", index, char)
}

```

**5. 字面量表示法**
Go 支持两种形式的字符串字面量：

* **双引号 (`""`)**：解释型字符串，支持转义字符（如 `\n`, `\t`）。
* **反引号 (````)**：原生字符串（Raw string），内部的文本会原样输出，不支持任何转义，非常适合编写多行文本、HTML 模板或正则表达式。

```go
rawString := `第一行
第二行\n原样输出，不换行`

```

**6. 字符串拼接**

* **少量拼接**：直接使用 `+` 操作符即可（如 `s1 + s2`）。
* **大量拼接**：在循环中频繁使用 `+` 会导致大量内存分配和拷贝，性能极差。此时应使用 `strings.Builder`：

```go
import "strings"

var builder strings.Builder
builder.WriteString("Hello")
builder.WriteString(" ")
builder.WriteString("World")
fmt.Println(builder.String()) // 性能最优的拼接方式

```
### 常量

Go语言中的常量使用 `const` 关键字定义，它们在**编译时就已经确定，在程序运行期间无法修改**。Go的常量只能是基础数据类型：**布尔值、字符串或数字（整数、浮点数、复数）**，不能是切片、数组、字典或结构体。

  
**1、基础声明与批量声明**

常量的声明语法与变量类似，但必须在声明时赋值，且不能使用 `:=` 简短声明。
```go
// 单个声明
const Pi = 3.1415926
const MaxThreads int = 50

// 批量声明（推荐作法）
const (
    StatusOk       = 200
    StatusNotFound = 404
    ServerName     = "GoServer"
)
```
在批量声明中，如果某一行没有显式赋值，它会**默认采用上一行的表达式和类型**：
```go
const (
    A = 10     // A = 10
    B          // B = 10 (与A相同)
    C = "text" // C = "text"
    D          // D = "text" (与C相同)
)
```


 **2、有类型常量与无类型常量 (Untyped Constants)**

这是Go常量的一个核心特性。在Go中，如果不显式指定类型，常量就是**无类型的 (Untyped)**。
- **有类型常量：** `const a int32 = 10`。它的类型被彻底锁死，只能与 `int32` 类型的变量进行运算。
- **无类型常量：** `const b = 10`。它虽然在默认情况下表现为 `int`，但在运算时，它拥有极高的灵活性，可以像“变色龙”一样根据上下文自动隐式转换为所需的数字类型，无需手动强转。

```go
const Size = 1024 // 无类型常量

var a int32 = Size   // Size 自动适应为 int32
var b float64 = Size // Size 自动适应为 float64
var c complex64 = Size // Size 自动适应为 complex64
```

此外，无类型的数字常量拥有**任意精度**，不会像普通变量那样在编译阶段溢出，直到被分配给特定类型的变量时才会检查大小。

  

**3、 `iota` 常量生成器（枚举）**

Go语言没有 `enum` 关键字，而是通过 `const` 和内置标识符 `iota` 来实现枚举功能。`iota` 表示 `const` 声明块中的行索引（从0开始计）。

```go
const (
    Monday    = iota // 0
    Tuesday          // 1 (自动继承上一行的表达式 iota)
    Wednesday        // 2
    Thursday         // 3
    Friday           // 4
    Saturday         // 5
    Sunday           // 6
)
```

**`iota` 的高级用法：**
- **跳过值：** 使用下划线 `_` 忽略某些值。
- **自定义步进：** 可以在第一行对 `iota` 进行运算。
```go
const (
    _ = iota             // iota=0，但被忽略
    KB = 1 << (10 * iota) // iota=1，1 << 10 = 1024
    MB = 1 << (10 * iota) // iota=2，1 << 20 = 1048576
    GB = 1 << (10 * iota) // iota=3，1 << 30 = 1073741824
)
```

_注意：每次遇到新的 `const` 关键字，`iota` 都会清零重新计算。_

# 包和文件

Go 的包和文件设计体现了极简主义：抛弃了抽象的逻辑命名空间，直接拥抱操作系统的文件系统；抛弃了权限关键字，直接使用大小写；抛弃了类与文件的强绑定，赋予开发者完全自由的代码组织权。
## 物理目录就是包
**在 Go 语言中，物理目录就是包，一个目录，一个包**。在 Go 的底层视角中，包仅仅是物理文件系统目录在代码层面的逻辑映射。

在同一个物理文件夹（目录）下的所有 `.go` 源文件，必须声明属于同一个 `package`：
假设你有一个文件夹叫 `utils`，里面有 `str.go` 和 `math.go`，那么这两个文件的第一行通常都必须是 `package utils`。如果你在同一个目录下让一个文件叫 `package utils`，另一个叫 `package tools`，Go 编译器会直接报错。
> 例外：测试文件 `xxx_test.go` 可以声明为 `包名_test`（如 `package utils_test`），用于外部黑盒测试。*

## 编译的最小单元是包，而不是文件
在 Go 语言的编译底层机制中，**编译的最小单元就是“包（Package）”，而不是“文件（File）”**。味着同一个包下的所有go文件，最后都会被编译当作一个文件，按照多个文件来拆分，目的是为了更好的划分业务逻辑和功能。
* **没有“类与文件绑定”：** 你可以在一个 `models.go` 文件里定义 20 个不同的结构体（Struct），也可以把 1 个庞大的结构体及其方法拆分到 5 个不同的 `.go` 文件中。
* **跨文件免导入：** 同一个包（目录）下的不同文件，共享同一个命名空间。如果 `a.go` 里定义了变量 `X` 或函数 `FuncA()`，在同目录的 `b.go` 中可以直接调用，**完全不需要 import**。
* **如何拆分文件？** Go 开发者通常根据**业务逻辑**或**功能模块**来拆分文件，而不是根据对象。例如，标准的 HTTP 包 `net/http` 下，有 `request.go`、`response.go`、`server.go`，它们共同组成了 `package http`。

## 基于命名大小写来实现包访问权限

Go 语言认为 Java 中的 `public`, `private`, `protected` 等关键字是对语法的过度复杂化。Go 将访问权限的控制直接融合到了**命名规范**中，且权限的边界是**包（Package）**，而不是结构体（Class）。
* **公开（Public / Exported）：** 任何以**大写字母**开头的变量、函数、结构体或字段，都是公开的。其他包导入后可以直接访问。
```go
// 其他包可见
var GlobalConfig string
func CalculateSum() {}
type User struct {
    Name string // 外部可读写该字段
}

```
* **私有（Private / Unexported）：** 任何以**小写字母**开头的标识符，都是私有的。它们**只能在当前包（目录）内部的所有文件中使用**，对外部包绝对隐藏。
```go
// 仅当前包可见
var internalCache map[string]string
func parseLogic() {}
type config struct {
    token string // 即使结构体公开，这个字段外部也看不见
}

```



## `init()` 函数来初始化

在 Java 中，如果你想在类加载时执行一些一次性的初始化代码，会使用 `static { ... }` 静态代码块。在 Go 语言中，对应的机制是特殊的 `init()` 函数。
* **自动执行：** 任何包（包括 `main` 包）下，任何文件中都可以定义无参数、无返回值的 `func init() {}`。当这个包被别的包 `import` 时，Go 运行时系统（Runtime）会自动调用该包内的 `init()` 函数。
* **允许多个：** 与 `main()` 函数只能有一个不同，**同一个包下，甚至同一个文件下，可以定义多个 `init()` 函数**。编译器会按照依赖顺序和文件名的字典顺序自动将它们串联执行。
* **常见用途：** 用于在程序启动前初始化单例、加载配置、注册数据库驱动或建立系统级连接。
```go
package database

var DBConnection *sql.DB

// 当其他包 import "xxx/database" 时，此函数自动触发
func init() {
    DBConnection = connectToMySQL()
}
```


## 包的导入

```go
// 单个导入
import "fmt"
import "os"



// 多个导入
import (
    "fmt"                           // Go 标准库
    "os"
                                    // 使用空格来分组
    "github.com/gin-gonic/gin"      // 第三方远程库 (基于 URL 路径)
    "myproject/internal/service"    // 本项目的其他模块 (基于 go.mod 所在的相对路径)
)
```

- **路径解析基准：** 当编译器看到 `"myproject/internal/service"` 时，它会去当前项目的根目录寻找 `go.mod` 文件（假设该文件声明了 `module myproject`），然后顺着这个基准，进入 `internal/service` 文件夹，读取里面所有的 `.go` 文件。
    
- **命名空间调用：** 导入路径结束后，在代码中调用时，使用的是**目标目录中源文件实际声明的包名**。例如导入 `"[github.com/gin-gonic/gin](https://github.com/gin-gonic/gin)"`，代码中使用的是 `gin.Default()`，因为该路径下的源码声明了 `package gin`。

案例：在本地项目创建与使用自定义包

1）目录结构
```bash
myproject/          # 项目根目录
├── go.mod          # 包含: module myproject
├── main.go         
└── utils/          # 自定义包目录
    └── math.go
```

2）编写自定义包

```go
// 文件：myproject/utils/math.go
package utils // 必须与目录名一致

// 首字母大写，对外公开
func Add(a int, b int) int {
    return a + b
}
```

3）导入并使用自定义包
```go
// 文件：myproject/main.go
package main

import (
    "fmt"
    "myproject/utils" // 核心：使用绝对路径导入自定义包
)

func main() {
    result := utils.Add(10, 20) // 通过 包名.公开方法 调用
    fmt.Println(result)
}
```



**三种特殊的导入**：面对复杂的工程场景（如包名冲突或隐式初始化），Go 提供了三种特殊的导入修饰符：

1、**别名导入 (Alias Import)：** 如果同时导入了两个不同路径但包名相同的库，或者包名太长，可以在字符串前加上别名。
```go
import (
    "crypto/rand"
    mrand "math/rand" // 赋予别名 mrand
)
// 调用时使用别名
// mrand.Intn(10)
```

2、**匿名导入 / 空白导入 (Blank Import)：** 这是 Go 中极其独特且重要的一种导入模式。使用 `_` 作为别名。由于 Go 规定导入的包必须被使用，否则编译报错，当你**不需要调用某个包的任何函数，仅仅想触发该包内部的 `init()` 函数进行底层初始化**（例如注册数据库驱动）时，必须使用空导入。

```go
import (
    "database/sql"
    _ "github.com/go-sql-driver/mysql" // 仅触发其底层的 init() 注册 MySQL 驱动
)
```


3、**点导入 (Dot Import)：** 在字符串前加上 `.`。这会将目标包中所有公开的（首字母大写）变量和函数，直接“揉进”当前文件的命名空间中。

```go
import . "fmt"

func main() {
    Println("Hello World") // 不需要写 fmt.Println
}
```
