# 设计哲学

Python是一门**多范式**，高级**动态解释型**编程语言。

## 一切皆对象

❝ Everything is an object, and objects are immutable unless explicitly mutable ❞

**1、在 Python 中，所有的东西都是对象**，包括：int, str, list, 函数、类、模块、异常、甚至代码块和类型本身。
>在 Python 中，一切皆对象。对象的主要交互方式是通过属性和方法（方法本身也是属性）。因此，理解一个对象，很大程度上就是理解它有哪些属性、这些属性代表什么、以及哪些属性是可调用的。


**2、而Python中的对象又分为可变和不可变：**

1）不可变指的是**对象内容不可变**，对原有对象进行某些操作时实际上不会对原有对象的内容进行修改，而是创建一个新的对象返回。Python 的内建核心类型（int, float, str, tuple, bytes, frozenset）都是不可变的，是有意为之，确保对象一旦创建就安全、可哈希、可缓存。

```Python
# 创建 "abc"对象，并返回引用赋值给 a
a = "abc"
# 创建 3 对象，并返回引用赋值给 a，并不是直接对变量a原指向的对象的值进行修改
# 因为不可修改
a = 3
```

所以Python在进行大量数据的数值操作，效率远低于 C/Java，因为不断赋值，需要不断创建新对象，而即使像 int ，str等对象都是堆上的完整结构体，开销比 C 的一个字节数组大得多；对于大量数值操作一般借助专门的库来加速，比如numpy。

2）list, dict, set 这些类型是为了解决实际需要的“可变结构”而明确设计为可变的。

3、查看对象的常用函数

1）`type()` ：查看对象的类型

2）对象之间的转换：`int(x) float(x) str(x)`

3）查看对象有哪些属性和方法：dir(obj)



# 协议

**协议 = 一组约定好的特殊方法（通常以双下划线开头）**。  只要一个对象实现了这些方法，它就“支持某种能力”，Python **就能用统一的方式**使用它。

这和静态语言的 `interface` 不同：
- Python 的协议是**非正式的**（duck typing：看起来像鸭子、叫起来像鸭子，就是鸭子）。
- 语法上并不会强制，不需要显式声明“我实现了某某协议”，只要方法存在即可。那么就可以使用约定好的方式去调用。
>当你调用 `for`、`len()`、`in`、`+` 等语法或内置函数时，Python 实际上是在调用这些协议方法。


## 1. 迭代器协议（Iterator Protocol）

这是 Python 中最基础、使用频率最高的协议之一。

**核心方法**：
- `__iter__(self)`：返回迭代器对象自身（通常 `return self`）
- `__next__(self)`：返回下一个值；没有更多值时抛出 `StopIteration`

**可迭代对象 vs 迭代器**：
- **可迭代对象**（Iterable）：实现了 `__iter__`，返回一个迭代器
- **迭代器**（Iterator）：同时实现了 `__iter__` 和 `__next__`

```python
class CountDown:
    def __init__(self, start):
        self.current = start

    def __iter__(self):
        return self          # 自己就是迭代器

    def __next__(self):
        if self.current <= 0:
            raise StopIteration
        self.current -= 1
        return self.current + 1

for i in CountDown(5):
    print(i)   # 5 4 3 2 1
```

**相关**：
- `iter(obj)` 会调用 `__iter__`
- `next(obj)` 会调用 `__next__`
- 生成器（generator）自动实现了迭代器协议

## 2. 上下文管理器协议（Context Manager Protocol）

用于 `with` 语句，实现资源的自动获取与释放。

**核心方法**：
- `__enter__(self)`：进入 `with` 块时调用，返回值会赋给 `as` 后面的变量
- `__exit__(self, exc_type, exc_val, exc_tb)`：离开 `with` 块时调用（无论是否发生异常）。返回 `True` 可以抑制异常。

```python
class FileManager:
    def __init__(self, filename, mode):
        self.filename = filename
        self.mode = mode
        self.file = None

    def __enter__(self):
        self.file = open(self.filename, self.mode)
        return self.file

    def __exit__(self, exc_type, exc_val, exc_tb):
        if self.file:
            self.file.close()
        # 返回 False 表示不抑制异常

with FileManager('test.txt', 'w') as f:
    f.write('hello')
```

**标准库支持**：`contextlib.contextmanager` 装饰器可以让生成器函数轻松变成上下文管理器。

## 3. 描述符协议（Descriptor Protocol）

这是属性访问的底层机制，`property`、`classmethod`、`staticmethod`、以及许多框架（Django、SQLAlchemy）都基于它。

**核心方法**：
- `__get__(self, instance, owner)`：获取属性时调用
- `__set__(self, instance, value)`：设置属性时调用
- `__delete__(self, instance)`：删除属性时调用

只要实现了 `__get__` 或 `__set__`/`__delete__`，就是描述符。

```python
class Typed:
    def __init__(self, name, expected_type):
        self.name = name
        self.expected_type = expected_type

    def __get__(self, instance, owner):
        if instance is None:
            return self
        return instance.__dict__[self.name]

    def __set__(self, instance, value):
        if not isinstance(value, self.expected_type):
            raise TypeError(f'Expected {self.expected_type}')
        instance.__dict__[self.name] = value

class Person:
    name = Typed('name', str)
    age = Typed('age', int)

    def __init__(self, name, age):
        self.name = name
        self.age = age
```

## 4. 序列 / 映射 / 集合相关协议（Sequence / Mapping / Set）

这些协议让对象能像列表、字典、集合一样被使用。

**最常用的方法**：
| 协议       | 关键方法                          | 支持的操作                  |
|------------|-----------------------------------|-----------------------------|
| 容器协议   | `__contains__`                    | `in` / `not in`             |
| 序列协议   | `__len__`, `__getitem__`          | `len()`, 索引、切片、`for`  |
| 映射协议   | `__len__`, `__getitem__`, `__setitem__`, `__delitem__`, `keys` 等 | 字典操作                    |
| 可哈希     | `__hash__`, `__eq__`              | 能放入 set / 作为 dict 键   |

**最小可工作序列示例**：

```python
class MyList:
    def __init__(self, data):
        self._data = list(data)

    def __len__(self):
        return len(self._data)

    def __getitem__(self, index):
        return self._data[index]   # 支持索引和切片

ml = MyList([1, 2, 3, 4])
print(len(ml))       # 4
print(ml[1])         # 2
print(ml[1:3])       # [2, 3]
print(2 in ml)       # True（自动用 __getitem__ 实现）
```

实现 `__getitem__` + `__len__` 后，Python 会自动提供很多便利行为。

## 5. 可调用协议（Callable Protocol）

只要实现了 `__call__`，对象就可以像函数一样被调用。

```python
class Adder:
    def __init__(self, n):
        self.n = n

    def __call__(self, x):
        return self.n + x

add5 = Adder(5)
print(add5(10))   # 15
print(callable(add5))  # True
```

## 6. 数字相关协议（Numeric Protocol）

用于支持运算符重载：

- `__add__` / `__radd__` / `__iadd__`
- `__sub__` / `__mul__` / `__truediv__` / `__floordiv__` / `__mod__` 等
- `__lt__` / `__le__` / `__eq__` / `__ne__` / `__gt__` / `__ge__`（比较）
- `__neg__` / `__pos__` / `__abs__` 等

**注意**：`__rxxx__` 是反向运算（当左边对象不支持时调用右边对象）。

### 7. 其他常见重要协议

| 协议                  | 关键方法                     | 用途                              |
|-----------------------|------------------------------|-----------------------------------|
| 异步迭代器            | `__aiter__`, `__anext__`     | `async for`                       |
| 异步上下文管理器      | `__aenter__`, `__aexit__`    | `async with`                      |
| 缓冲区协议            | `__buffer__`（或旧版 `__getbuffer__`） | 与内存视图、NumPy、C 扩展高效交互 |
| 字符串表示            | `__str__`, `__repr__`        | `str()`, `repr()`, 打印           |
| 格式化                | `__format__`                 | `format()`, f-string              |
| 布尔值                | `__bool__`（或 `__len__`）   | `if obj:`                         |
| 属性访问钩子          | `__getattr__`, `__setattr__`, `__delattr__`, `__getattribute__` | 自定义属性查找行为 |

### 8. 使用 `collections.abc` 检查协议

Python 提供了抽象基类来正式定义这些协议，并可用于 `isinstance` 检查：

```python
from collections.abc import Iterable, Iterator, Sequence, Mapping, Callable, ContextManager

print(isinstance([1, 2, 3], Sequence))      # True
print(isinstance(iter([1, 2]), Iterator))   # True
print(isinstance(open, Callable))           # True
```

从 Python 3.8 开始，还可用 `typing.Protocol` 定义**结构化子类型**（静态类型检查友好）：

```python
from typing import Protocol

class SupportsClose(Protocol):
    def close(self) -> None: ...
```

### 总结与建议

1. **最常用的四个**：迭代器、上下文管理器、描述符、序列/映射。
2. 实现协议时，尽量遵循“最小实现”原则，只实现真正需要的方法。
3. 查看官方文档《Data Model》章节（`object.__xxx__`）是最权威的参考。
4. 实际开发中，优先使用标准库提供的工具（`@contextmanager`、`property`、`collections.abc`、生成器等），而不是自己从头写协议。

如果你想深入某个具体协议（比如描述符的完整原理、异步协议、或如何自己实现一个完整的 Sequence），告诉我，我可以继续详细展开。

### 4. 正式协议（typing.Protocol）——静态检查用

从 Python 3.8 开始，`typing.Protocol` 让协议变成**可被类型检查器验证**的正式接口：

```python
from typing import Protocol

class Drawable(Protocol):
    def draw(self) -> None: ...

def render(obj: Drawable):
    obj.draw()

class Circle:
    def draw(self):
        print("画圆")

render(Circle())   # 类型检查通过，因为实现了 draw
```

注意：这只是给**类型检查器**看的，运行时依然是鸭子类型，不强制检查。

## 5. Python 要用协议而不是强制接口？

- **灵活性极高**：任何对象只要实现对应方法就能用，不需要继承特定基类。
- **与“一切皆对象”高度一致**：行为完全由方法（属性）决定。
- **语法糖丰富**：`for`、`with`、`len()`、`in` 等都能自动适配协议。
- 代价是：错误发现得较晚（运行时才报错），需要良好文档和测试。

## if not

`not` 是逻辑非运算符，作用是把布尔值翻转：所以 `if not x` 的意思是：**如果 x 为假，就执行下面的代码**。

- `None`
- `0`、`0.0`

```python

if not name:

```

场景三：配合 `in` 取反


# 异常机制
在编程语言中，异常是一种 控制流转移机制 —— 当程序出现“非预期情况”时，**自动中断正常流程，然后跳转到异常处理逻辑**，交由专门的“异常处理代码”去应对。如果没有异常机制，则：
- 所有函数都要自己返回错误码；
- 调用者每次都要写一堆 if 判断；
- 错误容易被忽略。
- 或者程序将直接结束。

## 基本语法结构

```Python
try:
    # 可能抛出异常的代码
except [异常类型 [as 变量]]:
    # 处理异常
else:
    # 仅当try块中没有异常时执行
finally:
    # 无论如何都会执行
```

except [异常类型 [as 变量]] 中 as的作用：当异常发生时，Python 会自动创建一个异常对象（Exception object），里面保存了异常的类型、错误信息、调用栈信息等。

👉 as e 就是把这个异常对象赋值给变量 e，让你在 except 块里能访问这个对象、打印它、记录日志、或进行更细粒度的处理。如果没有as e则表示只捕获对应类型的异常，但不拿对象。

2. **异常的传播**

当解释器执行某条语句出错时：
1. 当前代码块被中断；
2. Python 会在当前的 try 语句中寻找匹配的 except；
3. 如果当前函数没有处理，异常会沿着调用栈向上传播；
4. 直到找到合适的 except，或到达程序顶层。

## 异常链
Python 3 引入了完善的异常链机制，主要用来保留异常发生时的完整上下文，方便调试和追踪根因。Python 3 提供了三种控制异常链的方式：

|写法|名称|效果|
|---|---|---|
|`raise NewError()`|**隐式链**|自动关联旧异常，打印冗长 traceback|
|`raise NewError() from e`|**显式链**|显式声明因果关系，保留完整上下文|
|`raise NewError() from None`|**抑制链**|彻底切断关联，只保留新异常|

### 1. 隐式链

默认情况，不显示使用from，在处理一个异常的过程中又抛出了另一个异常，Python 会自动把原来的异常挂到新异常的 **context** 上。

打印时显示：During handling of the above exception, another exception occurred:

```python
try:  
    int("abc")  # 抛出 ValueError  
except ValueError:  
    raise RuntimeError("配置解析失败")
```

**输出：**
```bash

ValueError: invalid literal for int() with base 10: 'abc'  
During handling of the above exception, another exception occurred:  
RuntimeError: 配置解析失败
```

**特点：**
- 旧异常自动挂到 `e.__context__`
- 打印时显示 `During handling of the above exception...`
- 语义模糊：是"处理过程中又出错"，而非"由...导致"


### 2.2 显式链

通过from 显示指定，使用 raise NewException from original_exception，把当前异常的原因明确指向另一个异常。
- 会设置新异常的 **cause** 属性。
- 打印堆栈时会显示 The above exception was the direct cause of the following exception:。
    

```python
try:  
    int("abc")  
except ValueError as e:  
    raise RuntimeError("配置解析失败") from e
```

**输出：**
```bash
ValueError: invalid literal for int() with base 10: 'abc'  
The above exception was the direct cause of the following exception:  
RuntimeError: 配置解析失败
```

**特点：**
- 旧异常设为 `e.__cause__`
- 打印时显示 `The above exception was the direct cause...`
- 语义明确：旧异常**直接导致**了新异常
- **推荐用于需要保留根因的调试场景**
    

---

### 2.3 抑制链

使用from None，把旧异常直接丢弃。

```python
try:  
    int("abc")  
except ValueError:  
    raise RuntimeError("配置解析失败") from None
```

**输出：**

RuntimeError: 配置解析失败

**特点：**

- 旧异常被完全隐藏，traceback 干干净净
- 设置 `e.__suppress_context__ = True`
- **推荐用于原始异常是噪音或需要信息隐藏的场景**

**使用场景：**

```python
# 配置校验：float() 失败的细节不重要  
try:  
    threshold = float(DOMESTIC_GOLD_ALERT_THRESHOLD)  
except ValueError:  
    raise RuntimeError(  
        "DOMESTIC_GOLD_ALERT_THRESHOLD 必须是数字"  
    ) from None  
      
      
# 对外隐藏内部实现细节  
try:  
    user_data = decrypt(encrypted_token)  
except DecryptionError:  
    raise AuthenticationError("认证失败，请重新登录") from None  
​  
# 对外只暴露 BusinessException，内部异常不暴露  
try:  
    result = fetch_remote_config()  
except (ConnectionError, TimeoutError, JSONDecodeError):  
    raise BusinessError("远程配置加载失败") from None
```


    
## 异常对象
异常本质上是对象。当你 raise 一个异常时，实际上是在创建一个异常类的实例，并抛出这个实例。
所有异常都继承自 BaseException：
```Python
BaseException
 ├── SystemExit
 ├── KeyboardInterrupt
 ├── GeneratorExit
 └── Exception
      ├── ArithmeticError
      │    ├── ZeroDivisionError
      │    └── OverflowError
      ├── LookupError
      │    ├── IndexError
      │    └── KeyError
      ├── ValueError
      ├── TypeError
      ├── OSError
      ├── RuntimeError
      └── ...
```

**🔹 两个核心基类：**
- BaseException：所有异常的祖先
- Exception：一般程序错误的基类
⚠️ 注意：KeyboardInterrupt、SystemExit不是Exception 的子类！
所以 except Exception: 不会拦截用户按 Ctrl+C 或调用 sys.exit()

异常对象的核心属性:

| 属性                         | 说明                               |
| -------------------------- | -------------------------------- |
| `args`                     | 传递给异常构造函数的参数元组                   |
| `__str__()` / `__repr__()` | 字符串表示                            |
| `__traceback__`            | 异常发生时的堆栈跟踪对象（`traceback` 对象）     |
| `__cause__`                | 显式异常链（`raise ... from ...`）      |
| `__context__`              | 隐式异常链（处理异常时又抛出新异常）               |
| `__suppress_context__`     | 是否抑制上下文显示（`from None` 时为 `True`） |

## 自定义异常

继承 Exception 来定义自己的业务异常：

```Python
class MyError(Exception):
    """自定义异常类"""
    pass

try:
    raise MyError("发生了自定义错误！")  # raise 向上抛出异常
except MyError as e:
    print("捕获自定义异常：", e)
# 在 except 块中，可以选择再次抛出异常：
try:
    func()
except ValueError:
```
