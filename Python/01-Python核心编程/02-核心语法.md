# 条件结构

### `if elif else`

```Python
if age > 10:
    print('age is greater than 10')
    print('age is greater than 10')
elif age < 10:
    print('age is less than 10')
    print('age is less than 10')
else:
    print('age is less than 10')
```

### if not

`not` 是逻辑非运算符，作用是把布尔值翻转：所以 `if not x` 的意思是：**如果 x 为假，就执行下面的代码**。


场景一：判断布尔值为 False
```python
is_valid = False
if not is_valid:
    print("数据无效")   # 会执行
```

场景二：判断为空（最常用）
在 Python 中，以下值会被视为"假"（Falsy）：
- `None`
- `0`、`0.0`
- 空字符串 `""`
- 空列表 `[]`、空字典 `{}`、空元组 `()`
- 空集合 `set()`

```python
name = ""
if not name:
    print("名字不能为空")   # 会执行

items = []
if not items:
    print("列表为空")       # 会执行
```

场景三：配合 `in` 取反
```python
banned = ["admin", "root"]
user = "guest"

if user not in banned:
    print("允许访问")       # 会执行
```

### if is 和 if is not

is 和 is not 是用于**判断两个对象是否为同一个对象（同一地址）的身份运算符**（identity operators），背后是调用 id()判断内存地址是否相同

```Python
if a is b:
    # a 和 b 是“同一个对象”（即 id(a) == id(b)）
    
if a is not b:
    # a 和 b 不是“同一个对象”
```

### if x is None

None 是一个内置的单例对象，它的类型是 NoneType，表示什么都没有，None 不是 0，不是空字符串，也不是 False，它是一个独立的对象。相当其它语言中的 null，这再次证明在 Python 中一切皆对象。

判断一个对象是否是 None，请使用：
`if a is None`

### 三元运算符

`value_if_true if condition else value_if_false`

如果condition结果是 true，则返回value_if_true 否则返回 value_if_false

```python
num = input("请写入内容")
data = "臭不要脸" if "苍老师" in num else "正经人"
print(data)
```


## 循环结构

### while 结构

```python
while age > 0:
    print('age is greater than 0')

```

### for 结构

```python
for 临时变量 in 待处理数据集(可迭代对象): 
    #逻辑        
name='abdasd'
for n in name:
    print(n)
```



`range(num)` 返回的是 可迭代对象 `<class 'range'>`，所以在开发中也经常会借助range来执行循环。

```python
for i in range(num)
for i in range(start, end)
for i in range(start, end, step)
```

不管是for结构，还是range结构，如果需要在循环体外部使用临时变量，可以在循环体开始之前就把临时变量定义好。

`continue` 和 `break` 关键字，**临时跳过或者直接结束****所在循环体**。


## 异常机制
在编程语言中，异常是一种 控制流转移机制 —— 当程序出现“非预期情况”时，**自动中断正常流程，然后跳转到异常处理逻辑**，交由专门的“异常处理代码”去应对。如果没有异常机制，则：
- 所有函数都要自己返回错误码；
- 调用者每次都要写一堆 if 判断；
- 错误容易被忽略。
- 或者程序将直接结束。

### 基本语法结构

```Python
try:
    # 可能抛出异常的代码
except [异常类型 [as 变量]]:
    # 处理异常
else:
    # 仅当try块中没有异常时执行
finally:
    # 无论如何都会执行
```

except [异常类型 [as 变量]] 中 as的作用：当异常发生时，Python 会自动创建一个异常对象（Exception object），里面保存了异常的类型、错误信息、调用栈信息等。

👉 as e 就是把这个异常对象赋值给变量 e，让你在 except 块里能访问这个对象、打印它、记录日志、或进行更细粒度的处理。如果没有as e则表示只捕获对应类型的异常，但不拿对象。

2. **异常的传播**

当解释器执行某条语句出错时：
1. 当前代码块被中断；
2. Python 会在当前的 try 语句中寻找匹配的 except；
3. 如果当前函数没有处理，异常会沿着调用栈向上传播；
4. 直到找到合适的 except，或到达程序顶层。

### 异常链
Python 3 引入了完善的异常链机制，主要用来保留异常发生时的完整上下文，方便调试和追踪根因。Python 3 提供了三种控制异常链的方式：

|写法|名称|效果|
|---|---|---|
|`raise NewError()`|**隐式链**|自动关联旧异常，打印冗长 traceback|
|`raise NewError() from e`|**显式链**|显式声明因果关系，保留完整上下文|
|`raise NewError() from None`|**抑制链**|彻底切断关联，只保留新异常|

#### 1. 隐式链

默认情况，不显示使用from，在处理一个异常的过程中又抛出了另一个异常，Python 会自动把原来的异常挂到新异常的 **context** 上。

打印时显示：During handling of the above exception, another exception occurred:

```python
try:  
    int("abc")  # 抛出 ValueError  
except ValueError:  
    raise RuntimeError("配置解析失败")
```

**输出：**
```bash

ValueError: invalid literal for int() with base 10: 'abc'  
During handling of the above exception, another exception occurred:  
RuntimeError: 配置解析失败
```

**特点：**
- 旧异常自动挂到 `e.__context__`
- 打印时显示 `During handling of the above exception...`
- 语义模糊：是"处理过程中又出错"，而非"由...导致"


#### 2.2 显式链

通过from 显示指定，使用 raise NewException from original_exception，把当前异常的原因明确指向另一个异常。
- 会设置新异常的 **cause** 属性。
- 打印堆栈时会显示 The above exception was the direct cause of the following exception:。
    

```python
try:  
    int("abc")  
except ValueError as e:  
    raise RuntimeError("配置解析失败") from e
```

**输出：**
```bash
ValueError: invalid literal for int() with base 10: 'abc'  
The above exception was the direct cause of the following exception:  
RuntimeError: 配置解析失败
```

**特点：**
- 旧异常设为 `e.__cause__`
- 打印时显示 `The above exception was the direct cause...`
- 语义明确：旧异常**直接导致**了新异常
- **推荐用于需要保留根因的调试场景**
    

---

#### 2.3 抑制链

使用from None，把旧异常直接丢弃。

```python
try:  
    int("abc")  
except ValueError:  
    raise RuntimeError("配置解析失败") from None
```

**输出：**

RuntimeError: 配置解析失败

**特点：**

- 旧异常被完全隐藏，traceback 干干净净
- 设置 `e.__suppress_context__ = True`
- **推荐用于原始异常是噪音或需要信息隐藏的场景**

**使用场景：**

```python
# 配置校验：float() 失败的细节不重要  
try:  
    threshold = float(DOMESTIC_GOLD_ALERT_THRESHOLD)  
except ValueError:  
    raise RuntimeError(  
        "DOMESTIC_GOLD_ALERT_THRESHOLD 必须是数字"  
    ) from None  
      
      
# 对外隐藏内部实现细节  
try:  
    user_data = decrypt(encrypted_token)  
except DecryptionError:  
    raise AuthenticationError("认证失败，请重新登录") from None  
​  
# 对外只暴露 BusinessException，内部异常不暴露  
try:  
    result = fetch_remote_config()  
except (ConnectionError, TimeoutError, JSONDecodeError):  
    raise BusinessError("远程配置加载失败") from None
```


    
### 异常对象
异常本质上是对象。当你 raise 一个异常时，实际上是在创建一个异常类的实例，并抛出这个实例。
所有异常都继承自 BaseException：
```Python
BaseException
 ├── SystemExit
 ├── KeyboardInterrupt
 ├── GeneratorExit
 └── Exception
      ├── ArithmeticError
      │    ├── ZeroDivisionError
      │    └── OverflowError
      ├── LookupError
      │    ├── IndexError
      │    └── KeyError
      ├── ValueError
      ├── TypeError
      ├── OSError
      ├── RuntimeError
      └── ...
```

**🔹 两个核心基类：**
- BaseException：所有异常的祖先
- Exception：一般程序错误的基类
⚠️ 注意：KeyboardInterrupt、SystemExit不是Exception 的子类！
所以 except Exception: 不会拦截用户按 Ctrl+C 或调用 sys.exit()

异常对象的核心属性:

| 属性                         | 说明                               |
| -------------------------- | -------------------------------- |
| `args`                     | 传递给异常构造函数的参数元组                   |
| `__str__()` / `__repr__()` | 字符串表示                            |
| `__traceback__`            | 异常发生时的堆栈跟踪对象（`traceback` 对象）     |
| `__cause__`                | 显式异常链（`raise ... from ...`）      |
| `__context__`              | 隐式异常链（处理异常时又抛出新异常）               |
| `__suppress_context__`     | 是否抑制上下文显示（`from None` 时为 `True`） |

### 自定义异常

继承 Exception 来定义自己的业务异常：

```Python
class MyError(Exception):
    """自定义异常类"""
    pass

try:
    raise MyError("发生了自定义错误！")  # raise 向上抛出异常
except MyError as e:
    print("捕获自定义异常：", e)
# 在 except 块中，可以选择再次抛出异常：
try:
    func()
except ValueError:
    print("记录日志后继续抛出")
    raise  # 不带参数，重新抛出原异常
```
