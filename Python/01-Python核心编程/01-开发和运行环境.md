
Python 只需要下载对应的Python 解释器，就可以直接进行开发和运行，这个解释器就包含了解释，编译各种工具以及标准库。

```Text
Python3.x/
├── bin/                  # Unix/macOS 中的可执行文件目录（Windows 则直接在顶级）
│   ├── python3           # Python 解释器可执行文件
│   ├── pip3              # pip 安装工具
│   └── python3.13-config # 编译配置脚本
├── include/              # C 语言接口的头文件（如 Python.h），用于扩展模块开发
│   └── Python.h
├── lib/                  # 标准库与模块存放目录
│   ├── python3.x/        # 标准库源码 `.py`、编译字节码 `.pyc`
│   └── site‑packages/    # 第三方安装包的位置[oai_citation_attribution:1‡geeksforgeeks.org](https://www.geeksforgeeks.org/python/get-location-of-python-site-packages-directory/?utm_source=chatgpt.com)
├── lib-dynload/          # Python 的系统扩展模块（.so/.dll）
├── DLLs/                 # Windows 特有 DLL 模块
├── Scripts/              # Windows 脚本命令（如 pip.exe）目录
├── share/                # 文档、示例等共享资源
└── pyvenv.cfg            # 如果是虚拟环境，会在目录根部存在此文件
```

进入 Python 交互环境

```Shell
python3
```


# 虚拟环境

虚拟环境是 Python 提供的一种机制，用来在**同一台机器上创建多个相互隔离的 Python 运行环境：指定****解释器** **+ 第三方依赖**

每个使用虚拟环境的项目，它会拥有自己的 Python 解释器、自己的 site-packages（即 pip 安装的第三方库），各个项目之间相互隔离不影响。

![[Pasted image 20260626222125.png]]


```text
your_project/

├── venv/ <-- 虚拟环境目录

│ ├── bin/ <-- 执行 python、pip 的地方（Mac/Linux）

│ ├── Scripts/ <-- Windows 执行文件

│ └── lib/ <-- pip 安装的包都在这里

├── main.py

```
为什么 Java 中没有这个所谓的虚拟环境，而 Python 需要搞一个这样的虚拟环境？

## 开发规范

1. 单个可执行项目结构
新创建一个项目，假设名字叫 【crm】，可以创建如下文件和文件夹来存放代码和数据。

```Plain
crm
├── app.py        文件，程序的主文件（尽量精简）
├── config.py     文件，配置文件（放相关配置信息，代码中读取配置信息，如果想要修改配置，即可以在此修改，不用再去代码中逐一修改了）
├── db            文件夹，存放数据
├── files         文件夹，存放文件
├── src           包，业务处理的代码
└── utils         包，公共功能
```

2. 多个可执行项目结构

新创建项目，假设名称叫【killer】，可以创建如下文件和文件夹来存放代码和数据。

```Plain
killer
├── bin                                        文件夹，存放多个主文件（可运行）
│   ├── app1.py
│   └── app2.py
├── config              包，配置文件
│   ├── __init__.py
│   └── settings.py
├── db                  文件夹，存放数据
├── files               文件夹，存放文件
├── src                 包，业务代码
│   └── __init__.py
└── utils               包，公共功能
    └── __init__.py
```
