这是一个非常好的点。

**我建议我们从第一天开始，就不要使用** **`print()`****。**

我们自己封装一套日志工具，以后整个项目所有输出都通过它完成。

而且，我建议**不要直接使用 Python 原生** **`logging`** **输出到终端**。

原因：

- 默认格式太丑
- 不容易阅读
- 不符合工具软件体验
- 后期还需要同时输出到日志文件

## **logger.py**

```python
from __future__ import annotations

from datetime import datetime


class Logger:
    """控制台日志工具"""

    WIDTH = 62

    @classmethod
    def _time(cls) -> str:
        return datetime.now().strftime("%H:%M:%S")

    @classmethod
    def line(cls, char: str = "─") -> None:
        print(char * cls.WIDTH)

    @classmethod
    def title(cls, title: str) -> None:
        print()
        print("═" * cls.WIDTH)
        print(title.center(cls.WIDTH))
        print("═" * cls.WIDTH)

    @classmethod
    def section(cls, title: str) -> None:
        print()
        print("─" * cls.WIDTH)
        print(title)
        print("─" * cls.WIDTH)

    @classmethod
    def info(cls, message: str) -> None:
        print(f"[{cls._time()}] INFO     {message}")

    @classmethod
    def success(cls, message: str) -> None:
        print(f"[{cls._time()}] SUCCESS  {message}")

    @classmethod
    def warning(cls, message: str) -> None:
        print(f"[{cls._time()}] WARNING  {message}")

    @classmethod
    def error(cls, message: str) -> None:
        print(f"[{cls._time()}] ERROR    {message}")

    @classmethod
    def blank(cls) -> None:
        print()

    @classmethod
    def kv(cls, key: str, value: str) -> None:
        print(f"{key:<12}: {value}")

    @classmethod
    def wait(cls) -> None:
        input("\n按 Enter 键退出...")
```

## **不过，我还有一个更好的建议（也是我更推荐的）**

如果这个项目最终是要交付业务人员使用，我建议**不要自己造控制台日志轮子**，而是直接使用一个非常成熟的第三方库：**Rich**。

它的优势包括：

- 自动彩色输出（INFO、WARNING、ERROR 一眼可区分）
- 漂亮的表格、面板、进度条
- 自动处理终端宽度
- 后续如果有批量转换，可以直接显示实时进度
- 代码量反而更少

例如最终效果可以做到：

```text
╭────────────────────────────────────────────╮
│          Excel 订单转换工具 v1.0.0         │
╰────────────────────────────────────────────╯

10:31:26  INFO      正在读取 Excel...
10:31:27  SUCCESS   成功读取 356 条订单
10:31:28  WARNING   第25行手机号为空
10:31:29  ERROR     SKU 字段不存在

┌──────────────┬──────┐
│ 总订单       │ 356  │
│ 成功         │ 355  │
│ 失败         │ 1    │
│ 耗时         │ 2.31s│
└──────────────┴──────┘
```

对于这种**面向业务人员的命令行工具**，我更推荐 **Rich + 我们自己的 Logger 封装**。这样既保持统一调用方式（`Logger.info()`、`Logger.success()`），又能获得非常专业的终端显示效果，后续迁移到 GUI 时也只需要替换日志输出实现，而业务代码完全不用修改。
