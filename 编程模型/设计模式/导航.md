>设计模式不是脱离编程语言独立存在的。设计模式描述的是“解决设计问题的思想”，而编程语言提供了不同的“表达能力”。同一个模式，在不同语言中可能需要完全不同的代码结构，甚至某些模式在某种语言里会自然消失。

1、**不同语言的语言特性，会让某些设计模式更加自然，而让另外一些设计模式变得冗余。**
```
                 编程语言
                    │
       ┌────────────┼────────────┐
       ↓            ↓            ↓
   类型系统      函数能力      元编程
       │            │            │
       ↓            ↓            ↓
   某些模式       某些模式       某些模式
   更自然         更自然         更自然
```



```
                设计问题
                   │
                   ↓
              设计模式
                   │
                   ↓
        ┌──────────┼──────────┐
        ↓          ↓          ↓
       Java       Go        Python
        ↓          ↓          ↓
   interface    interface   function
   class        composition closure
   proxy        middleware decorator
        ↓          ↓          ↓
       不同的代码表达
```


```
第一阶段：Java
        ↓
理解经典设计模式
        ↓
第二阶段：Spring
        ↓
观察真实框架如何使用设计模式
        ↓
第三阶段：Python / JavaScript
        ↓
观察语言特性如何“消解”设计模式
        ↓
第四阶段：Go / Rust
        ↓
理解组合、泛型、Trait、函数式等不同设计思想
```



所以真正高级的设计模式学习不是：

“Strategy 模式有哪几个角色？”

而是：

“当一个系统中存在一个经常变化的行为时，我应该如何把变化隔离出来？”
