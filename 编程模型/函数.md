
# 不同语言中如何实现函数的传递

## ⁠1 ⁠Java：对象的基础上进行引用传递

在Java语言中，类/对象 是构成程序的基本单元，函数/方法不能当作普通的值来进行传递使用，直到Java 8 才出现了函数接口，加上Lambda语法糖的支持，才使得在Java中写回调函数达到了近似“传递函数”的效果，但是本质还是需要依赖对象，通过对象来传递对应方法的引用。

```java
// 内置函数式接口
Function<String, Integer> parseInt = Integer::parseInt;  // 方法引用
Predicate<String> isEmpty = s -> s.isEmpty();            // Lambda
Consumer<String> printer = System.out::println;

// 自定义函数式接口
@FunctionalInterface
interface Calculator {
    int operate(int a, int b);
}

Calculator add = (a, b) -> a + b;
Calculator multiply = (a, b) -> a * b;

// 作为参数传递
int result = execute(3, 4, multiply);  // 传递的是接口实现对象

int execute(int x, int y, Calculator calc) {
    return calc.operate(x, y);
}
```

Lambda `(a, b) -> a + b` 编译后并非真正的函数，而是：

- 生成一个实现 `Calculator` 接口的匿名类（或 invokedynamic 优化的类）
- 变量 `add` 持有的是这个**对象的引用**
- 传递时传的是**对象引用**，调用时通过对象的多态性执行 `operate()`



老方式（Java 8 之前）

用**匿名内部类**实现接口：

```java
button.addActionListener(new ActionListener() {
    @Override
    public void actionPerformed(ActionEvent e) {
        System.out.println("clicked");
    }
});
```

本质还是**传递一个实现了接口的对象**，而不是真正的函数。


**闭包与变量捕获**

Java 的 Lambda 可以捕获外部变量，但必须是 **final 或 effectively final**：

```java
int factor = 2;
Function<Integer, Integer> multiplier = x -> x * factor; // OK
// factor = 3; // 编译错误！不能修改
```



## ⁠2 ⁠语言 —— 函数指针

C 没有真正的“函数对象”，但可以用**函数指针**模拟：

```c
#include <stdio.h>

int add(int a, int b) { return a + b; }
int mul(int a, int b) { return a * b; }

// 接收函数指针
int apply(int (*f)(int, int), int x, int y) {
    return f(x, y);
}

int main() {
    printf("%d\n", apply(add, 3, 4));   // 7
    printf("%d\n", apply(mul, 3, 4));   // 12
    return 0;
}
```

- 优点：性能极高，无额外开销。
- 缺点：语法丑陋、类型不安全、没有闭包、容易写错签名。

## ⁠3 ⁠JavaScript —— 函数是一等公民

函数可以直接当值传递、返回、赋值：

```javascript
function apply(f, x, y) {
    return f(x, y);
}

const add = (a, b) => a + b;
const mul = (a, b) => a * b;

console.log(apply(add, 3, 4));     // 7
console.log(apply(mul, 3, 4));     // 12

// 高阶函数非常自然
[1,2,3].map(x => x * 2);
```

- 非常灵活，闭包强大。
- 没有静态类型检查（TypeScript 可弥补）。

## ⁠4 ⁠Python —— 函数是一等公民

```python
def apply(f, x, y):
    return f(x, y)

def add(a, b):
    return a + b

mul = lambda a, b: a * b

print(apply(add, 3, 4))    # 7
print(apply(mul, 3, 4))    # 12

# 方法也可以直接传
class A:
    def method(self, x):
        return x * 2

a = A()
print(apply(a.method, 5, None))  # 注意：绑定方法
```

- 语法最干净之一。
- 支持装饰器、高阶函数、闭包等非常自然。
- 动态类型，运行时才能发现签名错误



# 函数中的闭包

 **闭包（Closure）** 是函数式编程里非常核心的概念。简单说：

> **闭包 = 函数 + 它所捕获的外部变量**

简单理解：外部变量被内层函数访问时，那么这个外部变量就不会随着外部函数的结束而销毁。



## ⁠1 ⁠JavaScript（最典型、最自由）

```javascript
function createCounter() {
    let count = 0;          // 被闭包捕获的变量

    return function() {     // 这个匿名函数就是闭包
        count++;
        return count;
    };
}

const counter1 = createCounter();
const counter2 = createCounter();

console.log(counter1()); // 1
console.log(counter1()); // 2
console.log(counter2()); // 1   （独立的 count）
```

- 每个闭包都有自己独立的 `count`
- 可以修改外部变量（引用捕获）

常见坑：循环里创建闭包时变量共享问题（用 `let` 或 IIFE 解决）。

## ⁠2 ⁠Python

```python
def create_counter():
    count = 0

    def counter():
        nonlocal count      # 必须声明才能修改
        count += 1
        return count

    return counter

c1 = create_counter()
c2 = create_counter()

print(c1())  # 1
print(c1())  # 2
print(c2())  # 1
```

- 默认是**只读捕获**，要修改必须加 `nonlocal`
- 也很常用，装饰器本质上就是闭包的高级应用

## ⁠3 ⁠Java（有限制的闭包）

Java 8 的 Lambda 和方法引用支持“闭包”，但有严格限制：

```java
public class Demo {
    public static void main(String[] args) {
        int base = 10;   // effectively final

        // Lambda 捕获外部变量
        java.util.function.Function<Integer, Integer> add = x -> x + base;

        System.out.println(add.apply(5)); // 15

        // base = 20;  // 编译错误！被捕获的变量必须是 effectively final
    }
}
```

特点：
- 只能捕获 **effectively final** 的变量（不能修改）
- 捕获的是值拷贝（基本类型）或引用（对象）
- 匿名内部类也是同样规则

所以 Java 的闭包相对“受限”，主要是为了保持线程安全和可预测性。
