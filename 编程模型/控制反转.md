

# 函数式编程控制反转

传统 OOP 中的 IoC 通常指"好莱坞原则"——"别调用我们，我们会调用你"。你需要把对象交给框架，由框架决定何时调用你的代码。

FP 中的 IoC 更本质：**把"做什么"和"何时做/怎么做"解耦**。你定义计算的逻辑，而把执行的控制权交给调用者或运行时。


 在函数式编程（FP）中，**控制反转**（Inversion of Control, IoC）不是通过框架或容器实现的，而是通过**函数本身的组合能力**自然达成的。

## ⁠1 ⁠核心思想

传统 OOP 中的 IoC 通常指"好莱坞原则"——"别调用我们，我们会调用你"。你需要把对象交给框架，由框架决定何时调用你的代码。

FP 中的 IoC 更本质：**把"做什么"和"何时做/怎么做"解耦**。你定义计算的逻辑，而把执行的控制权交给调用者或运行时。


## ⁠2 ⁠1. 高阶函数（Higher-Order Functions）
函数接收或返回其他函数，调用方决定"何时"以及"如何"应用你的逻辑。

```javascript
// 你定义了"做什么"：过滤偶数
const isEven = x => x % 2 === 0;

// 控制权交给 filter：它决定遍历方式、顺序、短路策略
[1, 2, 3, 4].filter(isEven); 
```

这里你把**循环控制**（遍历、计数、边界检查）交给了 `filter`，你只关心判断逻辑。


 下面用 **JavaScript** 和 **Python** 分别展开第 2、3、4 点，每段都说明"控制权到底在哪里发生了反转"。

## ⁠3 ⁠2. 回调与 Continuation

核心思想：**你把"下一步该做什么"打包成一个函数交出去，由接收方（或运行时）决定何时、何地、以什么上下文来继续执行。**

 
- fetchData 提供了`onSuccess`  和 `onError` 2个回调函数，分别用于在成功和失败时下一步做什么，由用户提供，fetchData会在未来成功或者失败时被调用。
- 回调函数的参数也是fetchData提前定义好的，如果有参数，则由fetchData未来调用时提供，用户在定义下一步做什么时可以拿到这个参数


```javascript
// 基础回调：你把后续逻辑交出去
function fetchData(url, onSuccess, onError) {
    // 控制权在 fetchData 内部：它决定什么时候调用你
    setTimeout(() => {
        const ok = Math.random() > 0.5;
        ok ? onSuccess("data") : onError("network error");
    }, 1000);
}

fetchData("/api", 
    data => console.log("成功:", data),   // 你定义了逻辑
    err  => console.log("失败:", err)      // 但何时执行由 setTimeout 决定
);

// Promise：结构化的 Continuation
fetch("/api")
    .then(r => r.json())      // 你定义"解析 JSON"
    .then(data => save(data)) // 你定义"保存数据"
    .catch(e => log(e));      // 控制权在 Promise 调度器手中

// async/await 是语法糖，本质仍是控制权反转
async function main() {
    const result = await fetch("/api");  // 当前函数挂起，控制权交还给事件循环
    console.log(result);
}
```

### ⁠3.1 ⁠Python

```python
import asyncio
from threading import Timer

# 传统回调
def fetch_data(callback):
    def task():
        import random
        callback("data" if random.random() > 0.5 else None)
    Timer(1.0, task).start()  # 控制权交给 Timer 线程

fetch_data(lambda data: print("收到:", data))

# 生成器：yield 是最朴素的 Continuation
def producer():
    print("开始生产")
    received = yield "第一步完成"  # 在这里暂停，控制权交还给调用者
    print("收到调用者传来的:", received)
    yield "第二步完成"

gen = producer()
print(next(gen))      # 启动生成器，拿到 "第一步完成"
print(gen.send(42))   # 控制权回到生成器内部，传入 42

# asyncio：现代 Python 的 Continuation
async def fetch():
    await asyncio.sleep(1)  # 协程挂起，控制权交还事件循环
    return "data"

async def main():
    result = await fetch()  # 看起来同步，实际是控制反转
    print(result)

asyncio.run(main())
```

### ⁠3.2 ⁠控制反转体现在哪？

| 传统写法 | IoC 写法 |
|---------|---------|
| `const data = syncFetch(); process(data);` | `fetch(callback)` — 你把 `process` 交出去，由网络库决定何时调用 |
| `for i in range(1000000): do_something(i)` | `yield i` — 你把循环控制权交还给调用者，调用者用 `next()` 决定节奏 |

## ⁠4 ⁠3. 惰性求值（Lazy Evaluation）

核心思想：**你定义了一个（可能是无限的）计算，但"什么时候真正执行、执行多少"完全由消费者（调用方）决定。**

### ⁠4.1 ⁠JavaScript

```javascript
// 生成器：定义无限序列，但不计算
function* naturals() {
    let i = 0;
    while (true) {
        yield i++;  // 每次在这里暂停，控制权交还给调用者
    }
}

const gen = naturals();
console.log(gen.next().value); // 0 — 调用者决定"现在取一个"
console.log(gen.next().value); // 1 — 调用者决定"再取一个"

// 惰性流水线：map/filter 不立即执行
function* map(iter, fn) {
    for (const x of iter) yield fn(x);
}
function* filter(iter, pred) {
    for (const x of iter) if (pred(x)) yield x;
}

// 定义了一个"无限"流水线，但零开销
const pipeline = filter(
    map(naturals(), x => x * x),
    x => x > 100
);

// 消费者决定取多少
console.log(pipeline.next().value); // 121 (11²)
console.log(pipeline.next().value); // 144 (12²)
// 0~10 的平方从未被真正计算
```

### ⁠4.2 ⁠Python

```python
# 生成器函数：惰性定义无限序列
def naturals():
    i = 0
    while True:
        yield i   # 暂停，控制权交还
        i += 1

gen = naturals()
print(next(gen))  # 0
print(next(gen))  # 1

# 生成器表达式：完全惰性
squares = (x**2 for x in range(10_000_000))  # 内存中只有一个公式，没有实际数据
print(next(squares))  # 0
print(next(squares))  # 1

# itertools：惰性操作链
import itertools

def expensive(x):
    print(f"  计算: {x}")
    return x * 2

# 定义了操作，但什么都没算
stream = map(expensive, range(1000))  
filtered = filter(lambda x: x > 10, stream)

# 消费者按需拉取
for val in itertools.islice(filtered, 3):
    print(f"消费: {val}")
# 输出：
#   计算: 0
#   计算: 1
#   计算: 2
#   计算: 3
#   计算: 4
#   计算: 5
#   计算: 6
# 消费: 12
# ...
# 注意：7~999 从未被计算
```

### ⁠4.3 ⁠控制反转体现在哪？

| 立即求值 | 惰性求值 |
|---------|---------|
| `list = [x*2 for x in range(1e9)]` — 你决定"全部算完" | `(x*2 for x in range(1e9))` — 你交出计算权，调用者用 `next()` 决定算几个 |
| 数组 `map` 立即返回完整结果 | 生成器 `map` 返回"计算约定"，消费者拉取时才执行 |

## ⁠5 ⁠4. 函数组合与管道

核心思想：**你把数据处理拆成一个个纯函数，但"数据怎么流动、以什么顺序经过哪些阶段"交给组合子（combinator）控制。**

### ⁠5.1 ⁠JavaScript

```javascript
// pipe: 从左到右流动  |  compose: 从右到左流动
const pipe    = (...fns) => x => fns.reduce((v, f) => f(v), x);
const compose = (...fns) => x => fns.reduceRight((v, f) => f(v), x);

// 定义原子操作（纯函数）
const addOne    = x => x + 1;
const double    = x => x * 2;
const toString  = x => String(x);
const addPrefix = s => x => `result: ${x}`;  // 柯里化

// 组合：你定义阶段，pipe 控制流动
const transform = pipe(
    addOne,      // +1
    double,      // *2
    toString,    // 转字符串
    addPrefix("final")  // 加前缀
);

console.log(transform(5)); // "result: 12"

// 更实际的例子：验证管道
const validateUser = pipe(
    trim,
    x => x.length >= 3 ? x : throwError("太短"),
    x => x.toLowerCase(),
    checkDatabase,
    normalize
);
// 你定义了每个阶段要做什么，但 pipe 决定了数据必须按这个顺序经过所有阶段
```

### ⁠5.2 ⁠Python

```python
from functools import reduce

# Python 没有内置 pipe，手动实现
def pipe(*functions):
    """从左到右组合"""
    def piped(value):
        return reduce(lambda v, f: f(v), functions, value)
    return piped

def compose(*functions):
    """从右到左组合"""
    def composed(value):
        return reduce(lambda v, f: f(v), reversed(functions), value)
    return composed

# 纯函数定义
def add_one(x): return x + 1
def double(x): return x * 2
def to_string(x): return str(x)

# 组合
transform = pipe(add_one, double, to_string)
print(transform(5))  # "12"

# 实际例子：数据处理流水线
def trim(items): 
    return [s.strip() for s in items]

def remove_empty(items):
    return [s for s in items if s]

def normalize(items):
    return [s.lower() for s in items]

def unique(items):
    return list(dict.fromkeys(items))  # 保持顺序去重

# 控制权反转：你定义每个阶段，pipeline 控制数据流动
pipeline = pipe(trim, remove_empty, normalize, unique)

raw = ["  Apple ", "  banana", "", "APPLE", "  cherry ", "banana"]
print(pipeline(raw))
# ['apple', 'banana', 'cherry']

# 也可以用装饰器风格实现可插拔的管道
class Pipeline:
    def __init__(self):
        self.steps = []
    
    def add(self, fn):
        self.steps.append(fn)
        return self  # 链式调用
    
    def run(self, data):
        return reduce(lambda d, f: f(d), self.steps, data)

p = Pipeline().add(trim).add(remove_empty).add(normalize)
print(p.run(raw))
```

### ⁠5.3 ⁠控制反转体现在哪？

| 传统命令式 | 函数组合 |
|-----------|---------|
| `let x = a(); let y = b(x); let z = c(y);` — 你控制每一步的顺序和中间变量 | `pipe(a, b, c)(data)` — 你把阶段交出去，组合子控制数据如何流经每个函数 |
| 业务代码里写 `if (valid) { save(); }` | 你把 `valid` 和 `save` 注册进管道，由管道决定执行顺序和短路策略 |

## ⁠6 ⁠总结对比表

| 机制 | JS 典型实现 | Python 典型实现 | 反转了什么控制 |
|------|------------|-----------------|-------------|
| **回调/Continuation** | `Promise.then`, `async/await` | `yield`, `asyncio` | **执行时机** — 由调用方/事件循环决定何时继续 |
| **惰性求值** | `function*`, 自定义迭代器 | `yield`, 生成器表达式, `itertools` | **计算量** — 由消费者决定算多少 |
| **函数组合** | `pipe` / `compose`, `Array.reduce` | `functools.reduce`, 自定义组合子 | **数据流向** — 由组合子决定函数调用顺序 |

这三者在 FP 中经常叠加使用：**惰性生成器提供数据流，管道控制处理阶段，回调/异步处理副作用** — 最终你的业务代码只剩下"纯逻辑"，而"何时执行、执行多少、怎么串联"全部交给了函数组合的基础设施。


> **函数式编程中的控制反转，不是把对象交给容器管理，而是把"计算逻辑"写成纯函数，把"执行策略"交给高阶函数、惰性求值或调用方来决定。**
