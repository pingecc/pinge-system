
# Agent应用核心分工


用户负责和Agent交互，而Agent负责和大模型交互，最终由Agent完成实际代码的运行和API调用，模型只负责决策。


这正是当前主流 **Agent 架构** 的核心分工：

- **用户** ↔ **Agent**：用户只和 Agent 交互（发指令、看结果、给反馈）。
- **Agent** ↔ **大模型**：Agent 负责把用户的需求整理成 prompt，调用大模型进行推理和决策。
- **Agent** 负责实际执行：写代码、跑代码、调用各种 API、操作工具、读写文件、管理状态等。
- **大模型** 只负责“想”：规划步骤、决定下一步用什么工具、生成代码或指令、判断结果是否正确，本身不直接执行任何实际操作。

简单来说就是：

> **模型负责决策，Agent 负责行动。**

这也是为什么 Agent 框架（如 OpenAI Agents、LangGraph、CrewAI、AutoGen 等）会把“工具调用 + 代码执行 + 状态管理”放在 Agent 层，而不是直接让模型自己去跑代码的原因。


## Agent如何判读一次对话已经结束

在绝大多数基于 Tool Calling / Function Calling 的 Agent 实现中，**判断一轮对话（或者说一次 Agent 循环）是否结束**，核心判断标准就是：

> **大模型这一次返回的结果里，有没有包含工具调用（tool_calls / function_calls）。**

具体逻辑通常是这样的：

1. **大模型返回了工具调用**  
   → Agent 执行这些工具 → 把工具结果再喂回给大模型 → 继续循环。

2. **大模型没有返回任何工具调用，只返回了普通文本内容**  
   → 认为模型已经完成了任务，可以直接把这段文本作为最终回复返回给用户，循环结束。

这也是目前最主流、最简单可靠的结束条件。

**补充说明（实际工程中常会加的保护）**

虽然“没有 tool call = 结束”是主要判断，但真实系统里通常还会加一些额外控制：

- **最大循环次数**（`max_iterations`）：防止模型一直调工具导致死循环。
- **模型明确返回结束信号**：有些框架会让模型输出特殊标记（比如 `Final Answer:` 或自定义 stop token）。
- **同时有文本 + 工具调用**：有些模型会先说几句话再调工具，这时仍然继续执行工具，而不是结束。
- **Finish Reason**：看 API 返回的 `finish_reason` 是否是 `stop`（而不是 `tool_calls`）。


是的，**当大模型这一轮只返回了文本回复、没有发起任何工具请求时，Agent 就认为这次回话已经结束了**。

这是目前最通用、最干净的判断方式。
