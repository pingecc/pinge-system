在程序运行过程中将一些关键状态信息**按照顺序写入一个文件（称为日志文件）**，方便监控和排查问题。

在应用程序中使用日志工具，主要是关注以下几个方面：
- 控制日志的内容格式、级别
- 输出位置：控制台、文件、文件位置
- 日志优化：异步写入日志，日志文件的归档和压缩


# Java日志发展过程


1、1996年之前，使用 System.out.println()

 java初期没有专门的日志工具，直接使用 System.out.println() 或 System.err.println() 打印调试信息。



2、Log4j（1996-2002）

Java中首个成熟日志框架，引入了日志级别（TRACE、DEBUG、INFO、WARN、ERROR、FATAL）、Appender（输出目标）、Layout（格式化）等核心概念；支持配置文件（如 log4j.properties 或 XML）动态调整日志行为。

3、JUL（Java Util Logging, 2002)

Sum公司在JDK1.4引入java.util.logging（简称 JUL)，试图提供官方日志解决方案，但是配置复杂，API不友好，并没有流行起来。

<div class="highlight-block highlight-tip"> 日志门面</div>
提供一套标准的日志接口，应用程序直接基于日志接口来进行日志记录，具体的日志框架负责实现。

1、Apache Commons Logging（JCL，2002–2006）
配置不灵活，后来逐渐被SLF4J取代


2、**SLF4J**（Simple Logging Facade for Java，2006）

更高效更简洁的日志门面，已成为主流选择，主流实现：
- **Logback**(2006)：原生实现
- **Log4j 2**(2012)：异步日志，吞吐量高于Logback

注意：Log4j2 自带门面（log4j-api），而 Logback 必须搭配 SLF4J 作为门面，当然Log4j2也有slf4j的实现
