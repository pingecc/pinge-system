Spring是Java中的一个应用开发框架，它的**核心是提供了IOC（控制反转）容器和支持AOP**（面向切面编程），其它的几乎所有模块，比如事务、数据库访问，web框架都是在这两个核心功能的**基础之上构建的**。使用Spring进行开发可以根据需要引入对应的模块，但是现在的Java项目**基本直接基于SpringBoot**，可以极大的减少配置，提高开发效率。

1. 控制反转：把对象的创建、依赖交给Spring容器来管理，开发时只需要按照Spring的规则进行配置，然后在程序运行时Spring就可以帮助我们完成对象的实例化和注入。
2. 面向切面编程：Spring的面向切面编程是在**IOC容器的基础**上通过程序**运行时代理**来实现对某个类中的方法进行增强。

## @Autowired和@Resource


- `@Autowired`：默认按照类型注入。
- `@Resource`：默认byName注入，没有指定name时把属性名当做name，根据name找不到时，才会byType注入。
不管是`@Autowired`还是`@Resource`，当按照类型自动注入，发现匹配的Bean有多个时，从2个方面去解决：
- **从注入方（使用方）解决 ——** 明确告诉 Spring 要注入哪个 Bean。直接指定名字，比如对于使用`@Autowired`注解的，配合@Qualifier注解指定名字。或者直接注入具体实现类，不按照接口类型注入。
- **从被注入方（提供方）解决 ——** 指定自己为“默认”或“首选” Bean。比如 使用@Primary注解指示当自己被匹配时，发现和存在和自己同类型的Bean时，优先自己

> 这种情况发生在是按照接口类型注入，接口的实现类有多个导致的。



## Bean如何被实例化的


先调用构造方法来创建Bean，然后再进行依赖注入。
1）先查询是否有被@Autowired注解标注的构造方法，如果有则执行该方法，并自动注入构造方法中的参数。否则直接调用无参构造方法创建Bean。
2）接着查询被@Autowired标注的字段，方法进行依赖注入

## Bean的循环依赖
Bean的循环依赖指的是多个Bean之间相互依赖，要想解决循环依赖，必须满足2点：

- 对象本身的创建和对应依赖的注入是可以分离的。
    
- 对象在还没有完整的创建时可以放入缓存提前暴露给其它Bean使用
>所以在单例模式以及基于Set注入（或者字段注入）的情况下产生的循环依赖，Spring是可以帮助我们解决的。而在多例模式或者基于构造注入的产生的循环依赖无法解决。

>多例模式下之所以无法解决循环依赖，是因为Spring在多例模式下没有给Bean加缓存，也就无法提前暴露。Spring之所以没有给多例Bean加缓存，是多例 Bean 的设计理念就是每次都要 new 一个新的实例，它的目标就是不共享、无缓存！
## 依赖注入的方式

有三种，分别是：构造方法注入、字段注入、setter方法注入。不管是哪种方式，背后都是基于反射机制来完成属性的赋值。

# 事务


实际应用中一般不建议基于编程的方式去管理事务，因为会破坏Spring的事务体系，比如事务的传播机制就没有了。

1、如果需要在事务提交之后做一些操作，可以通过在方法内注册事务提交（afterCommit）之后的回调函数。
2、如果需要在事务失败回滚之后做一些操作，也可以通过在方法内注册事务完成（包含失败）（afterCompletion）的回调函数



<div class="highlight-block highlight-tip">什么情况下必须不得不使用编程式事务</div> 

1、在一个方法内想精细的控制多个操作的事务边界：

```java
public void process() {

    // 事务1
    transactionTemplate.execute(status -> {
        insertA();
        return null;
    });

    // 非事务逻辑
    callRemote();

    // 事务2
    transactionTemplate.execute(status -> {
        insertB();
        return null;
    });
}
```

👉 这种：
✔ @Transactional 做不到
✔ 必须用编程式事务
