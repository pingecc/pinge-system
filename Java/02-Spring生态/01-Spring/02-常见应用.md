# Bean
1、如何通过使用Spring提供的注解把一个类声明成一个Spring Bean交给Spring容器管理
2、类的属性依赖如何配置，才能让Spring自动帮我们注入

### 类
1、最基础的，直接使用 @Component 声明一个Bean
```Java
@Component
public class UserService {
    public void register(String name) {
        System.out.println("注册用户：" + name);
    }
}
```

2、可以使用其它更加有语义的注解：

| **注解**          | **含义**                    | **常用场景**    |
| --------------- | ------------------------- | ----------- |
| @Service        | 表示服务层 Bean                | 业务逻辑        |
| @Repository     | 表示数据访问层 Bean              | DAO 层、数据库访问 |
| @Controller     | 表示控制层 Bean                | Web 控制器     |
| @RestController | Controller + ResponseBody | Web API 控制器 |

3、 @Configuration + @Bean 手动实例化，方法名默认作为Bean的名称
```Java
@Configuration
public class AppConfig {

    @Bean
    public UserService userService() {
        return new UserService();
    }

    @Bean
    public OrderService orderService() {
        return new OrderService(userService());
    }
}
```

> 1. 这种方式的应用场景多是我们在项目中引入了第三方依赖，想在项目中把第三方依赖的某个类也声明成Spring中的Bean，这样在每次使用时不用再去手动创建配置，但是无法直接在第三方依赖的类上添加@Component注解，那么就可以使用这种方式。当然如果自己定义的类实例化方式比较复杂也可以使用这种方式。
> 2. 被@Configuration标注的类，Spring会创建对应的代理类，对于该类中所有被@Bean标注的方法会进行拦截，在执行之前会先去查看容器中是否已经有对应的对象，如果有则直接返回，否则执行原始方法。


### 属性注入

1、**基本数据类型**，只能使用 `@Value`，数据源一般来自配置文件或者环境变量

```Java
// 从配置文件（如 application.properties 或 application.yml）中读取名为 app.timeout 的配置项，如果找不到该配置项，就使用默认值 30。
@Value("${app.timeout:30}")
private int timeout;

@Value("${app.name}")
private String appName;

// 或者
@Component// 必须先让它成为Bean，Spring才会自动执行绑定属性值。
@ConfigurationProperties(prefix = "app")
public class AppProperties {
    private String name;
    private int timeout;
    // getter / setter
}
```


2、**对象服务的依赖**，直接使用  `@Autowired` 注解

```Java
@RestController
@RequestMapping("/api/users")
public class UserController {
    
    @Autowired
    private UserService userService;
    
    @GetMapping("/{id}")
    public String getUser(@PathVariable Long id) {
        return userService2.getUserById(id);
    }
}
```

	对象服务的依赖注入，还有通过set方法注入、构造器注入（虽然代码看起来美观好看，但是如果存在循环依赖就无法解决）

## AOP 
基于Spring的AOP对目标方法进行增强/拦截/扩展。

1、需要在配置类上添加注解.`@EnableAspectJAutoProxy(proxyTargetClass = true)`
来启动AOP
```java
package com.powernode.spring6.service;

import org.springframework.context.annotation.ComponentScan;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.EnableAspectJAutoProxy;

@Configuration
@ComponentScan("com.powernode.spring6.service")
@EnableAspectJAutoProxy(proxyTargetClass = true)
public class Spring6Configuration {
}
```

2、配置增强类、目标类、增强逻辑：

```java
@Component
@Aspect
public class MyAspect {
    // 切点表达式来表示织入的目标类和目标方法：
  // execution([访问控制修饰符] 返回值类型 [全限定类名]方法名(形式参数列表) [异常])
    @Around("execution(* org.pinge.UserService.*(..))")
    public void around(ProceedingJoinPoint joinPoint) throws Throwable {
        try {
            System.out.println("目标方法执行前");
            joinPoint.proceed();
            System.out.println("目标方法执行后");
        } catch (Exception e) {
            System.out.println("方法执行失败");
            e.printStackTrace();
        } finally {
            System.out.println("目标方法执行后最终执行");
        }
    }
}
```
>不管是增强类还是目标类，都要交给Spring容器管理，这样在程序运行时才能自动织入。


## 事务

### 声明式事务

```java
@Transactional(rollbackFor = Exception.class)
public void createOrder(Order order) {
    orderMapper.insert(order);
    orderItemMapper.batchInsert(order.getItems());
}
```

Spring默认回滚  RuntimeException，如果需要对所有异常包括Checked Exception 也回滚的话，可以通过 rollbackFor = Exception.class 指定，但是话又说回来，除了JDK一些比较旧的API存在Checked Exception，大部分异常包括外部框架库的异常还有我们的自定义异常，其实都是RuntimeException。默认的异常就够用了。



### 编程式事务

- 在execute()方法中抛出异常会自动回滚（默认RuntimeException，和使用注解一样）
- 可以手动标记回滚

```java
@Autowired
private TransactionTemplate transactionTemplate;

public void transferMoney(Long fromId, Long toId, BigDecimal amount) {
        transactionTemplate.execute(status -> {
            try {
                // 扣款
                userRepository.decreaseBalance(fromId, amount);
                // 加款
                userRepository.increaseBalance(toId, amount);
                if (somethingWrong) {
			        throw new RuntimeException("出错了！"); // 自动回滚
			    }
                return null; // 成功返回 null 或任意值
            } catch (Exception e) {
                status.setRollbackOnly(); // 标记回滚
                log.error(e);
            }
        });
    }
```

### 注册回调函数

可以在方法内给当前事务注册回调函数，Spring会在对应的执行时机去执行它，提高了很多个回调函数，常用的就是在事务成功提交之后 和 执行执行失败回滚之后：

```java
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import org.springframework.transaction.support.TransactionSynchronization;
import org.springframework.transaction.support.TransactionSynchronizationManager;

@Service
public class OrderService {

    @Transactional
    public void createOrder() {

        // 1. 核心业务（数据库操作）
        System.out.println("创建订单...");

        // 2. 注册事务回调
        TransactionSynchronizationManager.registerSynchronization(
            new TransactionSynchronization() {
                @Override
                public void afterCommit() {
                    System.out.println("【afterCommit】事务已提交，发送MQ消息");
                    sendMq();
                }

                @Override
                public void afterCompletion(int status) {
	                if (status == STATUS_ROLLED_BACK) {
                        System.out.println("【afterCompletion】事务回滚，执行补偿逻辑");
                    }
                }
            }
        );
    }

}
```
