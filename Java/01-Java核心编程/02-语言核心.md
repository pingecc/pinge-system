


# 泛型
1. 从功能表现上来看，Java的泛型类似于C++中的模板，可以预先定义类型参数，然后在使用时传进来，这样就可以**定义出跨类型的类或者方法**。
2. 但是实际上Java的泛型并不是像C++的模板一样，在编译后会根据传进来的类型生成特定的代码，而是在编译后**对泛型参数进行擦除，然后在需要的地方插入强制类型转换**。
3. 泛型并不属于 Java 的语言特性，可以简单认为它是一种类型语法糖，只在静态类型检查时期存在，在编译之后会被擦除为原始类型（或其第一个边界），然后在必要的地方插入类型转换，最终泛型代码内部并不存在有关泛型参数类型的可用信息。


<div class="highlight-block highlight-tip">理解没有泛型时如何设计跨类型的代码</div>
不通过泛型，设计跨类型的代码，通过多态来完成即可，直接把方法的参数设计成父类，如果方法的返回值固定，和使用者传入的参数类型没什么关系时，这样设计没有任何问题。但是如果方法的返回值类型是变化的，和传入的参数类型有关时，最典型的案例就是 Java 中的集合。那么只能直接返回一个父类类型，但是对于使用者来说它不得不进行强制类型转换，而强制类型转换会带来 2 个问题：

- 在编译期间无法确定真正安全，只有在运行期间才能确定，可能会转失败。
- 当代码中大量使用强制类型转换，显得非常臃肿且没有安全感。

所以Java为了避免到处类型转换，同时在编译期间保证类型是安全的。有了泛型，可以让程序员在编写类或者方法拥有更加丰富的表达力，同时会更加有效的使用静态编程语言的类型检查特性，让产出的程式更加稳定，提早在「编译期」就发现问题。

<div class="highlight-block highlight-tip">理解泛型擦除带来的局限性</div>

1. 无法将基本类型作为类型参数。不过，Java 5的自动装箱和自动拆箱机制实现了从基本类型到包装类型的双向转换
2. 静态方法无法使用泛型类中的泛型类型，因为泛型类中的泛型只有在创建对象时才传入。
3. 泛型不能用于 instance of 操作，不能用于 new表达式，试图创建 new T() 是不允许的，一部分原因是类型擦除，另一部分原因是编译器无法验证 T 中是否存在无参构造器。
4. 声明ArrayList.class是合法的，但声明`ArrayList<Integer>.class`却不行

```Java
List list = new ArrayList();
// 这么写没问题
if (list instanceof ArrayList) {
    System.out.println("ArrayList");
}
// 编译器也允许
if (list instanceof ArrayList<?>) {
    System.out.println("ArrayList");
}
// 编译器报错，指定具体的泛型就不行
if (list instanceof ArrayList<String>) {
    
}
```


理解为什么禁止泛型数组
```Java
List<String>[] arr = new List<String>[10]; // 编译报错
```

1. 无法保证泛型类型安全。泛型的本意是在编译期间保证泛型类型的一致性，继而保证运行期间不会出现类型转换的安全问题。而数组本身的协变性会**破坏编译期间对泛型类型的检查**，这使得泛型失去了自身的价值。
```Java
List<String>[] arr = new List<String>[10]; // 如果允许
Object[] objArr = arr; // 由于数组是协变的，这是合法的
objArr[0] = new ArrayList<Integer>(); // 合法
String s = arr[0].get(0); // ClassCastException
```

至于原始类型也可以绕过编译期间对泛型类型检查，但是这是为了历史的兼容性，没有办法（JDK1.5 引入泛型时不得不妥协）。

2. 和数组本身在运行期间需要精确类型检查冲突。在运行期间，JVM 会检查添加到数组中的元素是否类型一致，但是泛型在运行时会丢失了泛型类型信息，JVM 无法验证泛型类型参数的一致性，这和数组需要在运行时进行精确类型检查的机制也存在冲突，容易给开发者造成类型安全的假象，导致在取出数组元素时可能出现类型安全。

泛型集合的设计

Java 中的集合底层都是基于数组来实现的，既然不能设计泛型数组，那这些泛型集合又是如何设计的呢？**使用 Object[] + 强转**

```Java
public class ArrayList<E> implements List<E> {
    private Object[] elementData; // 真正存数据的地方
    private int size;

    public boolean add(E e) {
        ensureCapacity(size + 1);
        elementData[size++] = e; // 实际存的是 Object
        return true;
    }

    @SuppressWarnings("unchecked")
    public E get(int index) {
        return (E) elementData[index]; // 取出时强转
    }
}
```

1）关于 `@SuppressWarnings("unchecked")`注解

`unchecked cast` 是 Java 中关于泛型操作的警告，指将非泛型类型或者原始类型转换为泛型类型，由于泛型擦出的缘故，编译器无法验证这种转换的安全性，后续调用者使用时可能发生 `ClassCastException` 的风险。

```Java
List rawList = new ArrayList(); // 原始类型
List<String> strList = rawList; // 产生 unchecked 警告

Object obj = new ArrayList<Integer>();
List<String> strList = (List<String>) obj; // unchecked 警告
```

@SuppressWarnings("unchecked") 是 Java 的一个 编译器指令注解，意思是告诉编译器：这里的“未检查的类型转换”警告我知道，不用提醒我。

2）(E) elementData[index] 这里的强转作用是什么？

泛型在运行期间会被擦除，也即是 Object，为什么这里不能直接返回 elementData[index]，还要装模作样的使用（E)来强转，且使用了，编译器还发出警告。

擦除后确实是 Object，之所以源码里还是需要写(E)？**这其实是写给编译器看的**，告诉编译器这里的返回值类型就是泛型参数 E，那么调用者就不用自己强制类型转换，可以直接使用特定类型来接收了。如果直接用 Object 返回，那么编译器失去泛型类型推断能力，调用者需要自己进行强制类型转换。

```Java
public Object get(int index) {
    return elementData[index];
}
```

## 泛型类
泛型参数的命名

用＜T＞等形式来表示一个未确定的类型。泛型形参的命名一般使用单个的大写字母，如果有多个类型形参，那么中间使用逗号分隔，如Map＜K，V＞。在设计泛型参数的字母时，JDK 设计者希望：泛型参数字母最好能提示出角色。

- T：Type（类型）
    
- E：Element（元素）
    
- K, V：Key / Value（键值对）
    
- N：Number（数值）
    
- R：Return type（返回值类型）
    

**1、****泛型类****的语法**

```Java
// 在类名后声明泛型参数，然后在类中就可以使用这个泛型类型
public class Box<T> {
    private T value;
    // 注意，这不是泛型方法，只是使用了泛型类型的普通方法
    public void set(T value) { this.value = value; }
    public T get() { return value; }
    public Box() {
    }
}
// 抽象类或者接口类是一样的

// 使用泛型类

// 1. 创建泛型类对象： 表示传入的泛型类型是 String 类型
Box<String> box = new Box<String>();
// 在 JDK1.7 之后可以直接简写成下面的形式
Box<String> box = new Box<>();
// 当然也可以不指定泛型，直接使用原始类型，
// 这个时候可以传入任意类型的值，编译器不会做检查
// 此时类中的泛型 T 自然就是 Object
// 一般建议指定泛型
Box box = new Box();


// 2. 写操作：需要传入 String 类型的
// 如果传入其它类型，编译器报错，因为经过检查已经发现泛型 T 被指定为String 类型
box.set("hello");

// 3. 读操作，直接使用 String类型的变量去接收，无需强制类型转换
String str = box.getValue();
```

**2、子类****继承****泛型类****时**

子类要么指定父类泛型的具体类型，要么子类以及所有的父类都保持泛型参数

```Java
// 1.指定父类的具体泛型，当然直接写Box，也不报错，就认为是Object
public BoxSon extends Box<String> {
}

// 2.指定了父类的具体类型，子类同样可以继续设计成泛型类
public BoxSon<T> extends Box<Strng> {
    // 父类的泛型被指定为 String
    // 子类的泛型等创建时再指定
}

// 3.如果子类希望继续沿用泛型 父类的泛型参数字母必须在子类中有
public BoxSon<T> extends Box<T> {
}
```

当指定了父类的泛型时，子类在**重写或者实现**父类中使用到泛型类型的方法，可以直接使用具体的类型来代替方法中的泛型参数

```Java
public class BoxSon extends Box<String> {
    // 已指定父类泛型是 String，父类的方法setValue(T value)
    // 这里可以直接使用 String 类型代替 T
    @Override
    public void setValue(String value) {
        
    }

    // 编译器生成的桥接方法 用于保证多态性
    public void setValue(Object value) {
        setValue((String) value);
    }
    
}
```

思考：正常编译期间泛型信息是会被擦除的，所以父类的方法实际是`setValue(Object value)`，那么子类在实现或者重写时参数类型也必须和父类保持一致，也即`Object`，所以上面在子类中直接写 `setValue(String value)`正常来说是不行的，和继承的重写机制相违背，之所以可以直接这样写，是因为编译器会**自动生成对应的****桥接****方法。**

```Java
// 可以使用反射验证桥接方法的存在
for (Method declaredMethod : BoxSon.class.getDeclaredMethods()) {
            if (declaredMethod.isBridge()) {
                System.out.println("桥接方法："+declaredMethod);
            } else {
                System.out.println(declaredMethod);
            }
        }
// 输出
public void BoxSon.setValue(java.lang.String)
桥接方法：public void BoxSon.setValue(java.lang.Object)
```

```Java
BoxSon box = new Box();
// 调用过程
// 1. 编译检查父类方法setValue(Object v)是否存在
// 2. 运行期间检查子类是否重写setValue(Object v)，发现子类存在setValue(Object v) （桥接方法）
// 3. 调用子类方法setValue(Object v);
box.setValue("hello");
```

所以下面执行报类型转换错误：class java.lang.Integer cannot be cast to class java.lang.String (java.lang.Integer and java.lang.String are in module java.base of loader 'bootstrap')

```Java
public static void main(String[] args) {
        BoxSon boxSon = new BoxSon();
        Box box = boxSon;
        box.setValue(1);
}
```

## 泛型方法

**1、定义****泛型****方法：**在方法的**返回值前声明泛型参数**，然后可以在方法的任何地方：参数、返回值、方法体中使用这个泛型，

```Java
public static <T> T getItem(T item) {
    return item;
}
```

定义了泛型方法，这个泛型类型虽然可以在方法中完全不使用，语法上没问题，但是这毫无意义。

**2、使用****泛型****方法：**

```Java
// 1. 显示指定泛型类型进行调用
// 如果是静态方法，则类名.<T>方法名()
// 如果是实例方法，则对象.<T>方法名()
String item = Main.<String>getItem("hello");

// 2.无需指定泛型，编译器会自动根据调用者传入的参数类型或者返回类型进行自动推断
// 返回结果无需强制类型转换，直接使用对应的类型进行接收。
String item = getItem("hello");
```

**3、****泛型类****和****泛型****方法之间的关系：**一个方法是否是泛型方法，关键看这个方法的返回值前有没有声明泛型参数，和本身的类是否是泛型方法毫无关系。泛型类和泛型方法本身是可以混着用的。

```Java
public class Box<T> {
    private T value;
    
    public void setValue(T value) {
        this.value = value;
    }
    
    public T getValue() {
        return value;
    }

    // 泛型方法和泛型类本身可以混着用，此时的泛型方法这里的T 和 类中的泛型参数 T 不是同一个
    // 当然建议设置成不一样的
    public <T> T get(T value) {
        return value;
    }

    public static void main(String[] args) {
        Box<String> box = new Box<>();
        box.setValue("hello");
        Integer value = box.get(2);
    }
}
```

  

**什么时候需要设计成****泛型****方法？**

1. 方法的**参数类型不固定**，且**返回****值类型****也不固定和传入的参数类型有关**时：
    

```Java
// 传入什么类型就返回什么类型
public static <T> T getFirst(T[] array) {
    return array[0];
}
```

2）方法的参数多个且是泛型类型，具且体的泛型类型不确定，希望借助于泛型类型的检查机制来限制传入的泛型类型

```Java
// 限制使用者在传入时，dest和src参数传入的具体类型必须一致
public static <T> void copy(List<T> dest, List<T> src);

// 对于开发者来说，如果希望进一步保证读写安全
public static <T> void copy(List<? super T> dest, List<? extends T> src);

// 上面的设计对于使用者来说，
```

## 泛型的上界

`<T exetnds A>`，其中extends 左右都允许多个泛型符号， `<T, k extends A & B>` 表示泛型T，K继承 A 并且实现了 B 接口。**在编译期间可以直接把T 和 K当做它的上界类型去使用，编译器会提供支持，提供的表达力：**

1. 泛型**具备特定类型**的能力，
    
2. 限制传入具体的类型必须是某个类或其子类。
    
3. 在运行期间泛型参数则会被擦除为它的上界。
    

```Java
// 希望泛型类型具备执行 HasF中的f()方法的能力，通过设置泛型参数的上边界为 HasF
class Manipulator2<T extends HasF> {
    private T obj;
    public void manipulate() {
        obj.f();
    }
}

public static <T extends Comparable<T>> void hello(List<T> list, T x) {
        for (T t : list) {
            System.out.println(t.compareTo(x));
        }
    }
}
```

注意⚠️**`：<T extends SomeClass & Interface1 & Interface2>`**如果要指定多个上界的话，并且包含接口的话，接口只能放在后面，这个和定义类是一样的。


## 通配符

如果方法的参数类型本身是泛型类，且具体类型不固定，由使用者传入，**由于****泛型****是不可变的**，这个时候可以把参数类型设置成原始类型。

**泛型****是不可变的**

Java中的泛型为了保证编译期间的类型安全，**泛型是不可变的**

```Java
List<Integer> intList = new ArrayList<>();
List<Number> numList = intList; // ❌ 编译错误
//虽然 Integer 是 Number 的子类，
// 但 List<Integer> 并不是 List<Number> 的子类。
```

❓ 为什么这样设计？因为如果允许这种赋值，就会破坏类型安全！

```Java
// 假设允许 List<Integer> → List<Number>
List<Integer> intList = new ArrayList<>();
List<Number> numList = intList; // 如果允许

numList.add(12.5); // 向 List<Integer> 添加 Double
Integer i = intList.get(0); // ❌ 类型转换错误
```

这就导致一个常见的困境：写一个方法，想接收“所有 Number 的列表”，但是` List<Integer>` 和 `List<Double>` 却都不能传入。

```Java
void printNumbers(List<Number> nums) {
    for (Number n : nums) {
        System.out.println(n);
    }
}

List<Integer> ints = Arrays.asList(1, 2, 3);
printNumbers(ints); // ❌ 编译不通过
```
这时直接把参数设计成原始类型，但是这让代码陷入类型不安全的隐患，回到JDK1.5之前了。

如果**明确知道参数只能读或者写时**，可以使用通配符，定义出来的泛型类型参数**具备一定的多态性，可以接受更多的类型**，同时使得具备指定类型的能力。在开发者这边，可以通过通配符来进一步保证类型的安全。Java 通过限制读或者写来保证类型安全。

使用了通配符时，**可以调用与****泛型****类型无关的任意方法**，但是对于读方法或者写方法，根据不同的通配符会有所限制。

1. **无界通配符** **`<?>`**
    

表示具体的泛型类型不受限定，可以是任意类型。

1. 调用“读”方法，拿到的只能是Object 类型
    
2. 调用写方法，只能写入null值


```Java
void clear(List<?> list) {
    list.clear(); // 可以调用与类型无关的方法
    // 只能拿到Object 类型
    for (Object o : list) {
        System.out.println(o);
    }
}

// ❌ 不能添加（除了 null）
// list.add("hello"); // 错误
```

2. 上界通配符`<? extends T>`
    

表示传入的具体类型是 T 及其子类，泛型会擦除成 T，只能调用泛型相关的**读方法**并当作T类型来处理

```Java
public static <T extends Object & Comparable<? super T>> T max(Collection<? extends T> coll) {
    Iterator<? extends T> i = coll.iterator();
    T candidate = i.next();

    while (i.hasNext()) {
        T next = i.next();
        if (next.compareTo(candidate) > 0)
            candidate = next;
    }
    return candidate;
}
```

3. 下界通配符 `<? super T>`
    

表示传入的具体类型是T及其父类，泛型擦除成T，只能调用泛型相关的**写方法**

```Java
public static <T> void fill(List<? super T> list, T obj) {
    int size = list.size();

    if (size < FILL_THRESHOLD || list instanceof RandomAccess) {
        for (int i=0; i<size; i++)
            list.set(i, obj);
    } else {
        ListIterator<? super T> itr = list.listIterator();
        for (int i=0; i<size; i++) {
            itr.next();
            itr.set(obj);
        }
    }
}
```
#  反射

JVM每加载一种`class`，JVM就为其创建一个`Class`类型的实例并关联起来，Class类型实例中保持了该类的所有信息。程序中通过得到一个类的Class实例就可以获取该类的相关信息并进行相关操作，包括创建对象，访问对象的属性或者方法，这就是反射本身。简单来讲，**就是通过类的Class实例对象去操作类本身**。

Java 源码（`.java`）通过编译转化为字节码（`.class`），交由 JVM 解释执行。JVM 在加载类时，会将 `.class` 文件中的静态字节码信息，一次性解析并转换为结构化、可快速访问的内存数据结构（即“类元数据”）。这些元数据在 JVM 内部（如 HotSpot）由 `InstanceKlass`、`Method`、`ConstantPool` 等 C++ 对象表示，用于高效支持：

- 对象内存分配
- 方法调用（尤其是虚方法）
- 类型检查（`instanceof`、转型）
- 符号解析与 JIT 优化
    

**目的**：避免在程序运行过程中每次操作类时都重新解析 `.class` 文件，从而保障性能与语义正确性。而 `java.lang.Class` 并非元数据本身，**只是这些内部结构在 Java 语言层面的访问句柄（handle）** ——正如 `java.io.File` 或操作系统的文件描述符（file descriptor）是访问“文件资源”的句柄一样。通过 `Class` 对象，Java 程序可以在运行时**安全、标准地获取类的元信息并进行操作**（如反射），而不直接暴露 JVM 底层实现。

## 常用操作

**一、获取 Class 对象（反射入口）**

要想通过Class实例对象去操作类本身，首先第一步就是先获取一个类的Class实例对象。

```Java
Class<?> clazz1 = String.class;               // 编译期已知
Class<?> clazz2 = obj.getClass();             // 运行时从对象获取
Class<?> clazz3 = Class.forName("java.util.List"); // 动态加载（需处理 ClassNotFoundException）
```

**二、获取类的基本信息**

```Java
String name = clazz.getName();                // 全限定名：java.lang.String
String simpleName = clazz.getSimpleName();    // 简名：String
Package pkg = clazz.getPackage();             // 所在包
Class<?> superClass = clazz.getSuperclass();  // 父类
Class<?>[] interfaces = clazz.getInterfaces(); // 实现的接口
int modifiers = clazz.getModifiers();         // 修饰符（如 public、final）
boolean isInterface = clazz.isInterface();    // 是否是接口
boolean isArray = clazz.isArray();            // 是否是数组
```

**三、获取构造器（Constructor）**

```Java
// 获取 public 构造器
Constructor<?>[] cons = clazz.getConstructors();

// 获取所有构造器（包括 private）
Constructor<?>[] declaredCons = clazz.getDeclaredConstructors();

// 获取指定参数的构造器
Constructor<String> cons = String.class.getConstructor(String.class);

// 创建实例（绕过编译期类型检查）
Object obj = cons.newInstance("hello");
```

💡 `getDeclaredConstructors()` 可访问 private 构造器，但需先调用 `setAccessible(true)`。

**四、获取方法（Method）**

```Java
// 获取所有 public 方法（含继承）
Method[] methods = clazz.getMethods();

// 获取本类所有方法（含 private，不含继承）
Method[] declaredMethods = clazz.getDeclaredMethods();

// 获取指定方法（方法名 + 参数类型）
Method method = clazz.getMethod("toString"); // 无参
Method addMethod = List.class.getMethod("add", Object.class);

// 调用方法
Object result = method.invoke(obj); // obj.toString()
addMethod.invoke(list, "item");
```

调用 private 方法需：`method.setAccessible(true)`

**五、获取字段（Field）**

```Java
// 获取所有 public 字段（含继承）
Field[] fields = clazz.getFields();

// 获取本类所有字段（含 private，不含继承）
Field[] declaredFields = clazz.getDeclaredFields();

// 获取指定字段
Field field = clazz.getDeclaredField("name");

// 读写字段值
field.setAccessible(true);          // 若为 private
Object value = field.get(obj);      // 读
field.set(obj, "newName");          // 写
```

**六、获取注解（Annotation）**

```Java
// 获取类上的注解
Annotation[] annos = clazz.getAnnotations();
MyAnnotation anno = clazz.getAnnotation(MyAnnotation.class);

// 获取方法/字段上的注解
MyAnno methodAnno = method.getAnnotation(MyAnno.class);
MyAnno fieldAnno = field.getAnnotation(MyAnno.class);

// 判断是否有注解
boolean hasAnno = clazz.isAnnotationPresent(MyAnnotation.class);
```

🔹 注解要保留到运行时（`@Retention(RetentionPolicy.RUNTIME)`）才能通过反射获取。

**七、处理****泛型****信息（Type 相关）**

```Java
// 获取泛型父类
Type genericSuper = clazz.getGenericSuperclass(); // 如 ParameterizedType

// 获取泛型接口

// 获取方法返回值/参数的泛型类型

```

⚠️ 泛型信息在编译期会被**类型擦除**，但部分信息（如类定义、方法签名中的泛型）仍可通过 `Type` 子接口（如 `ParameterizedType`）获取。

**八、动态创建数组**

```Java
Class<?> arrClass = Array.newInstance(String.class, 5).getClass();
Object arr = Array.newInstance(int.class, 10); // 等价于 new int[10]
Array.set(arr, 0, 100);    // arr[0] = 100
int val = (int) Array.get(arr, 0); // arr[0]
```

**九、判断类型关系**

```Java
boolean isSub = clazz.isAssignableFrom(ArrayList.class); // ArrayList 是否是 clazz 的子类/实现？
boolean isInstance = clazz.isInstance(obj); // obj 是否是 clazz 类型的实例？（等价于 obj instanceof T）
```

**十、常用工具方法**


⚠️ 反射使用注意事项

1. **性能开销大**：相比直接调用，反射慢 10~100 倍（可通过缓存 Method/Field 缓解）
    
2. **破坏封装性**：可访问 private 成员（需 `setAccessible(true)`）
    
3. **安全性限制**：在 SecurityManager 下可能被禁止
    
4. **类型安全丧失**：编译器无法检查，容易抛 `ClassCastException`、`NoSuchMethodException` 等
    
5. **泛型****信息有限**：运行时泛型大多被擦除

## Comparable 和 Comparator接口
都是 Java 中用于定义对象比较规则的接口

Comparable：

- `Comparable` 是一个位于 `java.lang` 包中的接口。
- 它被称为“内比较器”，因为实现 `Comparable` 接口的类具有自身比较的能力。
 Comparator：
- `Comparator` 是一个位于 `java.util` 包中的接口。
- 它被称为“外比较器”，因为它允许开发者为不支持排序的类（即没有实现 `Comparable` 接口的类）定义比较规则。
在使用排序方法（如 `Collections.sort()` 或 `Arrays.sort()`）时，如果指定了 `Comparator`，则会按照 `Comparator` 的规则进行排序；否则，会按照 `Comparable` 的自然排序规则进行排序

## 标记接口
是一种没有任何方法声明的接口，其唯一作用是为实现它的类提供某种元数据（metadata）或**语义标记**，从而让 JVM、框架或开发者知道该类具有某种特殊性质或能力。比如：
- `java.io.Serializable`：标记该类的对象可以被序列化（转为字节流，用于网络传输、持久化等）。JVM 在序列化时会检查对象是否实现了此接口，否则抛出 `NotSerializableException`
-  `java.lang.Cloneable`：标记该类允许调用 `clone()` 方法进行对象复制。如果未实现此接口就调用 `Object.clone()`，会抛出 `CloneNotSupportedException`。
- `java.util.RandomAccess`标记 `List` 实现类支持快速随机访问（如 `ArrayList`），即 `get(i)` 时间复杂度为 O(1)。算法（如 `Collections.binarySearch`）可据此选择最优策略。

```Java
public enum HttpStatus {
    // 默认就是public staic final
    OK(200),
    NOT_FOUND(404),
    INTERNAL_ERROR(500);

    private final int code;

   // 构造方法默认就是private
    HttpStatus(int code) {
        this.code = code;
    }

    public int getCode() { return code; }

    public static HttpStatus fromCode(int code) {
        for (HttpStatus status : values()) {
            if (status.code == code) return status;
        }
        throw new IllegalArgumentException("Invalid HTTP status code: " + code);

}
```

# 异常
程序在执行过程中发生错误无法继续往下执行，必须直接返回，对于C语言这样的语言，它会直接返回一个状态码，用户根据函数返回的状态码决定后面的处理。例如，处理一个文件，如果返回`0`，表示成功，返回其他整数，表示约定的错误码：
```C
int code = processFile("C:\\test.txt");
if (code == 0) {
    // ok:
} else {
    // error:
    switch (code) {
    case 1:
        // file not found:
    case 2:
        // no read permission:
    default:
        // unknown error:
    }
}
```

很显然C语言这种根据状态码来处理异常的方式很繁琐。Java是面向对象语言，内置了一套自动化的异常处理机制，当VM发现无法继续执行时，会启动异常处理机制，首先创建一个异常对象，然后一直向上查找谁可以处理这个异常。如果没有代码可以处理这个异常，则启动默认异常处理机制，控制台打印异常栈信息，然后退出当前线程。
```
当前方法 → 调用者 → 再调用者 → ... → 线程入口（run）
如果整个调用战都没有try-catc，则run() 方法异常退出 → 线程生命周期结束，
- 只要这个线程不是主线程，不影响其它线程，否则如果是主线程，则JVM直接退出。
- 如果这个线程是来自某个线程池的，这线程池会继续创建新的线程补上。
```

## 异常体系设计

![[Pasted image 20260318150336.png]]

总结下，Java 的异常设计分为 2类，一类是 `Error`，一类是 `Exception`。

1. `Error` 语义上表示程序严重的错误，不应该 catch， 因为也处理不了，由 JVM 抛出。
    
2. `Exception` 语义上表示程序没有按照规则执行而 throws 的异常，Exception 下又分为 `RuntimeException` 和`受检异常`:
    
    1. `受检异常`编译器会强制调用者进行处理，语义上是告诉调用者这个方法可能会抛出某种异常，希望你知晓可以处理下，但是随着大量实践发现这种设计很鸡肋，因为即使告诉调用者这个方法可能会抛出什么异常，存在风险，调用者其实也处理不了，还是会继续往外 throws，这样反而使得代码很臃肿，后**来其实所有 Java 框架第三方库不会再使用这个受检异常，而是都使用 RuntimeException。只有 Java 标准库哪些遗留的 API 用受检查异常。**
        

现在基本形成了一个共识：

• **Checked Exception = 历史遗产**，主要还存在于 JDK 标准库。

• **RuntimeException = 现代主流做法**，几乎所有框架/库（Spring, Hibernate, Netty, Guava）都只用 RuntimeException。

• 如果真要标记“这个 API 会失败”，现代做法是：

• 在 **文档（Javadoc）** 里写明可能抛什么异常。

• 或者用 **注解 / Optional / Either 模式** 来显式表达。

## 异常处理

使用 `try...catch...` 语句块处理异常。

```Java
        try{
            //可能触发异常的代码
        }catch(NumberFormatException e){
            System.out.println("not valid number");
        }catch(RuntimeException e){
            System.out.println("runtime exception "+e.getMessage());
        }catch(Exception e){
            e.printStackTrace();
        }
```

异常处理机制将根据抛出的异常类型**找第一个匹配的catch块**，找到后，执行catch块内的代码，不再执行其他catch块，如果没有找到，会继续到上层方法中查找。需要注意的是，**抛出的异常类型是catch中声明异常的子类也算匹配**，所以需要将最具体的子类放在前面，如果基类Exception放在前面，则其他更具体的catch代码将得不到执行。

**对于受检异常，则必须进行声明或者catch处理掉**，

```Java
        public void test() throws AppException,
            SQLException, NumberFormatException {
            //主体代码
        }
```

如果多种异常处理的代码是类似的，可以用“|”操作符：

```Java
    try {
          //可能抛出 ExceptionA和ExceptionB
    } catch (ExceptionA | ExceptionB e) {
          e.printStackTrace();
    }
```

在catch块内处理完后，可以重新抛出异常，异常可以是原来的，也可以是新建的

```Java
        try{
            //可能触发异常的代码
        }catch(NumberFormatException e){
            System.out.println("not valid number");
            throw new AppException("输入格式不正确", e);
        }
```

catch后面可以跟finally语句:

```Java
        try{
            //可能抛出异常
        }catch(Exception e){
            //捕获异常
        }finally{
            //不管有无异常都执行
        }
```

finally内的代码不管有无异常发生，都会执行，具体来说：

- 如果没有异常发生，在try内的代码执行结束后执行。
    
- 如果有异常发生且被catch捕获，在catch内的代码执行结束后执行。
    
- 如果有异常发生但没被捕获，则在异常被抛给上层之前执行。
    

finally语句有一个执行细节，如果在try或者catch语句内有return语句，则return语句在finally语句执行结束后才执行，但finally并不能改变返回值,如果在finally中也有return语句呢？try和catch内的return会丢失，实际会返回finally中的返回值。**为避免混淆，应该避免在finally中使用return语句或者抛出异常.**

`try-with-resources` 在try语句块中的内容执行完之后，会自动调用resources中的close方法。常见于文件资源的处理代码。

```Java
public static void useResource() throws Exception {
      AutoCloseable r = new FileInputStream("hello"); //创建资源
      try {
          //使用资源
      } finally {
          r.close();
      }
}
// 使用try-with-resources
public static void useResource() throws Exception {
      try(AutoCloseable r = new FileInputStream("hello")) { //创建资源
          //使用资源
      }
}
```

## 异常正确抛出与记录

✅ 异常处理三原则

1. **在错误发生的第一现场直接抛出异常**
    
    1. 目的：确保 Throwable 的堆栈快照精准定位到出错的类、方法、行号。
        
    2. 做法：
        

```Java
if (userId == null) {
    throw new IllegalArgumentException("用户ID不能为空"); // ← 在判断处直接抛
}
```

3. 避免：先返回错误码，再在外层统一抛异常（会丢失位置信息）。
    
4. **捕获异常时，必须记录完整堆栈（含 cause）**
    
    1. 目的：生产环境无调试器，日志是唯一排查依据。
        
    2. 正确做法：
        

```Java
logger.error("处理订单 {} 失败", orderId, e); // ← 第三个参数是 Throwable
```

3. 错误做法：
    

```Java
logger.error("失败: " + e.getMessage()); // ❌ 无堆栈，无法定位
```

3. **重新抛出异常时，必须保留原始异常作为 cause**
    
    1. 目的：形成异常链（exception chaining），既暴露当前层上下文，又保留底层根因。
        

```Java
catch (SQLException e) {
    throw new OrderPersistenceException("保存订单失败", e); // ← e 作为 cause
}
```

```Java
throw new OrderPersistenceException("保存订单失败"); // ❌ 丢失原始异常
```

Java Database Connectivity

Java 官方自身定义的一套操作数据库的 API，`位于 java.sql 包下`，这套 API 定义了如何通过 Java 去操作数据库，设计了各种接口规范，各个数据库厂商根据这些接口规范，提供具体实现（即数据库驱动）；

**📚 规范内容概览（给数据库厂商看的）**

这份 PDF 文档（约 300+ 页）详细规定了：

**1. 核心接口与类（必须实现）**

数据库厂商必须实现以下接口（位于 `java.sql` 和 `javax.sql` 包中）：

- `java.sql.Driver`
    
- `java.sql.Connection`
    
- `java.sql.Statement`, `PreparedStatement`, `CallableStatement`
    
- `java.sql.ResultSet`
    
- `java.sql.DatabaseMetaData`
    
- `javax.sql.DataSource`
    
- `javax.sql.ConnectionPoolDataSource`（用于连接池）
    
- `javax.sql.XADataSource`（用于分布式事务）
    

**2. 行为规范**

- 驱动如何注册（`DriverManager.registerDriver()`）
    
- `ResultSet` 的游标行为（可滚动？可更新？）
    
- 事务隔离级别支持（`READ_COMMITTED`, `SERIALIZABLE` 等）
    
- 批量操作（`addBatch()` / `executeBatch()`）
    
- 异常体系（必须抛出 `SQLException` 及其子类）
    

**3.** **兼容性****要求**

- 必须通过 JDBC Technology Compatibility Kit (TCK) 测试
    
- 驱动 JAR 必须包含 `META-INF/services/java.sql.Driver` 文件（用于自动加载，JDBC 4.0+）
    

**4. 扩展能力**

- 支持 SQL 转义语法（如 `{fn now()}`）
    
- 支持大对象（BLOB/CLOB）
    
- 支持保存点（Savepoint）

**🛠 举个例子：****MySQL** **驱动如何遵循规范？**

- 实现了 `com.mysql.cj.jdbc.Driver` 类（实现 `java.sql.Driver` 接口）
    
- 提供 `com.mysql.cj.jdbc.ConnectionImpl`（实现 `java.sql.Connection`）

`DriverManager` 会自动找到 MySQL 驱动并调用其 `connect()` 方法——这正是规范定义的行为。

```Java
// JdbcUtil.java
package com.example.jdbc;

import java.sql.Connection;

public class JdbcUtil {
    private static final String URL = "jdbc:mysql://localhost:3306/jdbc_demo?useSSL=false&serverTimezone=UTC&allowPublicKeyRetrieval=true";
    private static final String USER = "root";
    private static final String PASSWORD = "your_password";

        try {
            Class.forName("com.mysql.cj.jdbc.Driver"); // 加载驱动（JDBC 4.0+ 可省略）

            throw new RuntimeException("MySQL 驱动未找到！", e);
        }
    }

    public static Connection getConnection() throws SQLException {
        return DriverManager.getConnection(URL, USER, PASSWORD);
    }
}
```

4. **事务操作**
    

JDBC 默认是 自动提交（auto-commit = true）。要手动控制事务，需关闭自动提交。

```Java
public void transfer(long fromId, long toId, double amount) {
    String sql1 = "UPDATE accounts SET balance = balance - ? WHERE user_id = ?";
    String sql2 = "UPDATE accounts SET balance = balance + ? WHERE user_id = ?";

    try (Connection conn = JdbcUtil.getConnection()) {
        conn.setAutoCommit(false); // 关闭自动提交

        try (PreparedStatement ps1 = conn.prepareStatement(sql1);
             PreparedStatement ps2 = conn.prepareStatement(sql2)) {

            ps1.setDouble(1, amount);
            ps1.setLong(2, fromId);
            ps1.executeUpdate();

            ps2.setDouble(1, amount);
            ps2.setLong(2, toId);
            ps2.executeUpdate();

            conn.commit(); // 提交事务
            System.out.println("转账成功！");

        } catch (SQLException e) {
            conn.rollback(); // 回滚
            System.out.println("转账失败，已回滚！");
            e.printStackTrace();
        }

    } catch (SQLException e) {
        e.printStackTrace();
    }
}
```

> 🔒 关键点：
> 
> - `setAutoCommit(false)`
>     
> - 成功 → `commit()`
>     
> - 异常 → `rollback()`
>     
> - 使用 `try-with-resources` 确保连接关闭
>

## 核心组件设计
    

JDBC 的核心组件主要分布在两个包中：

- `java.sql`：基础 JDBC API（JDBC 1.0 起）
    
- `javax.sql`：高级 JDBC API（JDBC 2.0 起，支持连接池、分布式事务等）
    

核心组件包括：

|   |   |   |   |
|---|---|---|---|
|组件|接口/类|所属包|核心职责|
|Driver|java.sql.Driver|java.sql|数据库驱动接口，负责创建连接|
|DriverManager|java.sql.DriverManager|java.sql|驱动管理器，加载驱动、获取连接|
|DataSource|javax.sql.DataSource|javax.sql|更现代的连接工厂（推荐替代 DriverManager）|
|Connection|java.sql.Connection|java.sql|表示与数据库的会话，管理事务、创建语句|
|Statement|java.sql.Statement|java.sql|执行静态 SQL|
|PreparedStatement|java.sql.PreparedStatement|java.sql|执行预编译 SQL（防注入、高性能）|
|CallableStatement|java.sql.CallableStatement|java.sql|调用存储过程|
|ResultSet|java.sql.ResultSet|java.sql|查询结果集，可滚动、可更新|
|DatabaseMetaData|java.sql.DatabaseMetaData|java.sql|获取数据库元信息（如表结构、支持特性）|
|SQLException|java.sql.SQLException|java.sql|JDBC 异常体系根类|

  

## 连接池
    

在一个系统中，对数据库的操作还是比较频繁的，如果每次操作都重新创建和销毁JDBC的连接（TCP连接），就比较浪费系统资源，于是我们可以使用连接池来复用（Connection Pool）复用已经创建好的连接，和线程池一样的道理。

JDBC连接池有一个标准的接口`javax.sql.`**`DataSource`**，要使用JDBC连接池，须选择一个JDBC连接池的实现。常用的JDBC连接池有：HikariCP、C3P0、BoneCP、Druid。

常用的是HikariCP，以HikariCP为例，先添加HikariCP的依赖，然后创建一个`DataSource`实例，这个实例就是连接池：

```Java
HikariConfig config = new HikariConfig();
config.setJdbcUrl("jdbc:mysql://localhost:3306/test");
config.setUsername("root");
config.setPassword("password");
config.addDataSourceProperty("connectionTimeout", "1000"); // 连接超时：1秒
config.addDataSourceProperty("idleTimeout", "60000"); // 空闲超时：60秒
config.addDataSourceProperty("maximumPoolSize", "10"); // 最大连接数：10
DataSource ds = new HikariDataSource(config);
```

通常`DataSource`实例总是作为一个全局变量存储，并贯穿整个应用程序的生命周期。有了连接池以后，直接从连接池里获取Connection：

```Java
try (Connection conn = ds.getConnection()) { // 在此获取连接
    ...
} // 在此“关闭”连接
```

通常连接池提供了大量的参数可以配置，例如，维护的最小、最大活动连接数，指定一个连接在空闲一段时间后自动关闭等，需要根据应用程序的负载合理地配置这些参数。
