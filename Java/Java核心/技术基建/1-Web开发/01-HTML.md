# 最佳实践

“CSS 放head里，JS body末尾”。

<div class="highlight-block highlight-tip"> CSS和JS位置 </div>


1. 为什么CSS要放在head里？
    

原理： 浏览器是从上到下读取代码的。

如果放在底部： 浏览器会先用默认样式把内容画出来（丑丑的黑白文字、错乱的排版）。等看到底部的 CSS 时，突然“闪”一下，把页面变成了漂亮的样式。

专业术语： 这种现象叫做 FOUC (Flash of Unstyled Content)，即“无样式内容闪烁”。这非常影响用户体验，感觉网页很“卡”或很“土”。

总结： CSS 放头顶，是为了让用户第一眼就看到化好妆的完美页面。

2. 为什么 JavaScript 要放在 <body> 的最后？
    

**原因一：防止“堵车” (性能)**

原理： 传统的 JavaScript 加载是**“阻塞”**的。当浏览器读到 <script> 标签时，它会立刻暂停手里所有的活（停止画页面），专门去下载并执行 JS 代码。

如果放在 <head>： 如果你的 JS 文件很大，浏览器就会卡在头部很久。用户会对着一个白屏发呆，直到 JS 下载完，浏览器才继续往下读 <body> 里的内容。

如果放在底部： 浏览器先把 <body> 里的文字、图片都显示出来了，用户已经能看东西了，这时候再默默加载 JS。即使 JS 慢一点，用户也感觉网页打开挺快的。

**原因二：防止“找不到人” (逻辑错误)**

场景： 假设你的 JS 代码写着：“把那个 ID 叫 btn 的按钮变成红色”。

如果放在 <head>： 浏览器读到这行代码时，还没读到 <body> 里的 <button id="btn">。JS 就会报错：“我找不到 btn 这个元素啊！”（因为它还没出生）。

如果放在底部： 所有的 HTML 元素都已经渲染完成了，JS 再去操作它们，就绝对没问题。

总结： JS 放脚底，是为了让页面先显示出来（防白屏），并确保JS 想操作的 HTML 元素都已经存在了。
