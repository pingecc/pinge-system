首先理解JS的执行模式 🟰 **JavaScript 引擎**  ➕  **宿主环境**

1. JS引擎负责对源码进行解释执行。
2. 宿主环境：提供与宿主或外部环境交互的机制，例如，在 web 浏览器中执行 JavaScript 时，HTML DOM 就是宿主环境。Node.js 是另一种允许 JavaScript 在服务器端运行的宿主环境。

# 实现异步的机制

	将阻塞/耗时操作的操作委托给宿主环境去执行，并注册一个回调函数，待宿主环境执行完会把结果作为参数传给这个回调函数，然后把这个回调函数放入任务队列中，而JS引擎主线程在执行完所有代码时则会去执行任务队列里的回调函数。
<div class="highlight-block highlight-tip">JavaScript是单线程语言</div>
JavaScript 在语言层面是单线程的（Single Thread），也即无法自主创建新线程的能力，不存在 Java 那样的：
```Java
new Thread(() -> {}).start();
```

JavaScript 的单线程意味着代码执行是顺序的，同一时间只能做一件事情，这个设计避免了多线程环境中的复杂问题（如死锁、资源竞争）。
<div class="highlight-block highlight-tip">如何实现异步</div>

但是，如果遇到一个耗时操作（比如网络请求、文件读取、定时器等），如果等待它完成，就会阻塞整个线程，导致页面无响应。因此，JavaScript 通过异步回调的方式，**将这类耗时操作交给运行环境（浏览器或Node.js）去处理**，当运行环境处理完成后，再通知 JavaScript 主线程执行回调函数。

例如在浏览器运行环境中，浏览器提供了多个线程来处理不同的任务：
- JavaScript 引擎线程：负责执行 JavaScript 代码（主线程）。
- GUI 渲染线程：负责渲染页面。
- 事件触发线程：负责管理事件（如点击、滚动等）。
- 定时器触发线程：负责 setTimeout 和 setInterval。
- 异步 HTTP 请求线程：负责处理网络请求。
    

当我们在 JavaScript 中调用一个异步函数（如 setTimeout 或 fetch）时，实际上是将这个任务交给了运行环境的其他线程去处理。然后，**运行环境在任务完成时，将回调函数放入任务队列中，等待 JavaScript 主线程空闲时执行。**

那主线程什么时候会去执行任务队列里的回调函数呢？当主线程的所有代码都执行完时，就去检查任务队列里是否有任务（回调函数），有的话则取出放入当前的调用栈执行，当调用栈为空，再次去任务队列里检查，如何循环：不断检查当前调用栈和任务队列然后执行，这就是所谓的事件循环。

下面列举常见宿主环境提供的异步能力：

定时器操作
```javaScript
// setTimeout / setInterval
// 由浏览器的定时器线程管理
setTimeout(() => {
    console.log('来自定时器');
}, 0);  // 注意：0ms 不等于立即执行！

// 即使设置为0，也要等同步代码执行完
console.log('同步代码先执行');
// 输出顺序：同步代码先执行 → 来自定时器
```

网络文件操作
```javaScript
// 网络请求
fetch('https://api.example.com/data')
    .then(response => response.json())
    .then(data => console.log('网络数据:', data));

// 文件读取（Node.js）
const fs = require('fs');
fs.readFile('file.txt', 'utf8', (err, data) => {
    console.log('文件内容:', data);
});

// 这些由网络线程/文件系统线程处理
```

UI操作
```javaScript
// DOM 事件
button.addEventListener('click', () => {
    console.log('按钮被点击');
});

// 由浏览器的事件触发线程管理
```


还有过微任务和宏任务的概念：
```javaScript
console.log('脚本开始');  // 1. 同步代码

setTimeout(() => {
    console.log('setTimeout');  // 4. 宏任务
}, 0);

Promise.resolve().then(() => {
    console.log('Promise');  // 3. 微任务
});

console.log('脚本结束');  // 2. 同步代码

// 输出顺序：
// 脚本开始
// 脚本结束
// Promise        (微任务，优先级高)
// setTimeout     (宏任务，优先级低)
```

<div class="highlight-block highlight-tip">javaScript这种设计优势</div>

1. **线程安全**：避免多线程并发访问 DOM 的竞争条件
    
2. **确定性**：执行顺序可预测，易于调试
    
3. **简单性**：开发者不需要处理锁、同步等复杂问题

<div class="highlight-block highlight-tip">异步回调 的问题</div>

但是如果在多个异步任务里需要顺序执行时，则需要不得不嵌套回调，单嵌套过深时，代码难以维护，每个回调都需要单独处理错误，代码冗余，所以就出现了新的方案：Promise 、await/await

```javaScript
// 需求：获取用户 → 获取订单 → 显示结果

// 1. 回调地狱（避免使用）
getUser(123, (user) => {
    getOrders(user.id, (orders) => {
        getOrderDetails(orders[0].id, (details) => {
            displayResults(user, orders, details);
        });
    });
});

// 2. Promise（较好）
getUser(123)
    .then(user => getOrders(user.id))
    .then(orders => getOrderDetails(orders[0].id))
    .then(details => displayResults(user, orders, details))
    .catch(console.error);

// 3. async/await（最佳）
async function displayUserOrders(userId) {
    try {
        const user = await getUser(userId);
        const orders = await getOrders(user.id);
        const details = await getOrderDetails(orders[0].id);
        displayResults(user, orders, details);
    } catch (error) {
        console.error('出错:', error);
    }
}
```

## 优势

撑海量连接的关键在于事件驱动和非阻塞I/O的设计，而不是依赖大量线程。
关键在于：**处理几十万网络连接本身，并不是libuv线程池的主要工作，它默认的4个线程是完全够用的。**

Node.js支撑海量连接的核心是 **“事件驱动 + 非阻塞I/O”** 模型。为了让你快速理解，我们可以把I/O任务分成两类，它们的处理方式完全不同：

| 特性       | **网络 I/O (如HTTP请求、WebSocket)**                                                                                                                                                                                                                                                                                    | **文件 I/O / CPU密集型任务 (如读写文件、加密)**                                                                                                                                                                                                                                           |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **底层实现** | 由操作系统内核提供的**异步接口**实现（如Linux的epoll，Windows的IOCP）[](https://cloud.tencent.cn/developer/information/%E5%9C%A8Node.js%E4%B8%AD%EF%BC%8Clibuv%E7%BA%BF%E7%A8%8B%E6%B1%A0%E6%98%AF%E5%90%A6%E7%94%A8%E4%BA%8E%E5%BC%82%E6%AD%A5%E6%96%87%E4%BB%B6I%2FO%EF%BC%9F%E4%B8%BA%E4%BB%80%E4%B9%88%EF%BC%9F)。                   | 操作系统没有提供通用的异步接口，或任务本身计算耗时。                                                                                                                                                                                                                                                 |
| **处理位置** | **完全在单线程的事件循环中**处理。主线程通过系统调用向内核注册事件，当连接有数据到来时，内核通知主线程，主线程再执行对应的回调[](https://cloud.tencent.cn/developer/information/%E5%9C%A8Node.js%E4%B8%AD%EF%BC%8Clibuv%E7%BA%BF%E7%A8%8B%E6%B1%A0%E6%98%AF%E5%90%A6%E7%94%A8%E4%BA%8E%E5%BC%82%E6%AD%A5%E6%96%87%E4%BB%B6I%2FO%EF%BC%9F%E4%B8%BA%E4%BB%80%E4%B9%88%EF%BC%9F)。 | 由**libuv线程池**处理[](https://cloud.tencent.cn/developer/article/1624504?from=15425)[](https://m.yisu.com/zixun/722202.html)。默认4个线程，任务会排队等待执行[](https://cloud.tencent.cn/developer/article/1624504?from=15425)[](https://blog.csdn.net/qq_36287830/article/details/153885623)。 |
