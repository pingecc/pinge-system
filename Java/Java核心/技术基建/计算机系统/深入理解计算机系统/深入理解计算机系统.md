# 计算机系统漫游

计算机系统是由**硬件**和**系统软件**组成的，它们共同工作来**运行应用程序。** 



<div class="highlight-block highlight-tip"> 信息就是位+上下文</div> 
> 上下文 =当前这串比特是被“谁”，在“什么规则体系下”，用来“干什么”。
> 基本思想:系统中所有的信息--包括磁盘文件、内存中的程序、内存中存放的用户数据以及网络上传送的数据，**都是由一串比特表示的**，物理上表现为可能是信号、电信号、磁方向等。区分不同数据对象的唯一方法是我们读到这些数据对象时的上下文。比如，在不同的上下文中，一个同样的字节序列可能表示一个整数、浮点数、字符串或者机器指令。

**像hello.c这样只由ASCII字符构成的文件称为文本文件，所有其他文件都称为二进制文件**。

<div class="highlight-block highlight-tip"> 程序被其他程序翻译成不同的格式</div> 

为了在系统上运行hello.c程序，每条C语句都必须被其他程序转化为一系列的低级机器语言指令。然后这些指令按照一种称为可执行目标程序的格式打好包，并以二进制磁盘文件的形式存放起来。目标程序也称为可执行目标文件。
汇编语言是非常有用的，因为它为不同高级语言的不同编译器提供了通用的输出语 言。例如，C编译器和Fortran编译器产生的输出文件用的都是一样的汇编语言。·汇编阶段。接下来，汇编器(as)将hello.s翻译成机器语言指令，把这些指令打包成一种叫做可重定位目标程序(relocatable object program)的格式，并将结果保存在目标文件hel1o.o中
> 是不是所有语言编译，都要经历转化成汇编语言，然后再由汇编器转化成机器语言？

链接阶段。请注意，he11o程序调用了printf函数，它是每个C编译器都提供的标准C库中的一个函数。printf函数存在于一个名为printf.o的单独的预编译好了的目标文件中，而这个文件必须以某种方式合并到我们的hel1o.o程序中。链接器(ld)就负责处理这种合并。结果就得到hello文件，它是一个可执行目标文件(或者简称为可执行文件)，可以被加载到内存中，由系统执行。
>特地格式的文件，可以被操作系统识别加载到内存，然后交给 cpu 执行。

## 信息的表示和处理

现代计算机存储和处理的信息以二值信号。

大多数计算机使用8位的块，或者字节(byte)，作为**最小的可寻址的内存单位**，而不是访问内存中单独的位。机器级程序将内存视为一个非常大的字节数组，称为虚拟内存(virtual memory)。**内存的每个字节都由一个唯一的数字来标识，称为它的地址(ad-dress)**，所有可能地址的集合就称为虚拟地址空间(virtual address space)。

与变量类似，指针也有两个方面:值和类型。它的值表示某个对象的位置，而它的类型表示那个位置上所存储对象的类型(比如整数或者浮点数)。


<div class="highlight-block highlight-tip"> 字节序</div> 
字节序（Endianness）只解决一个问题：内存是按照字节编址的，也即一个字节都有唯一的地址，然后对于一个占用多个字节的数，比如int类型的数，准备要把它存入 0x1000 ～0x1003 这块地址， 每个字节放在哪个地址上？

假设有一个 4 字节整数：
```Bash
0x11 22 33 44
```

现在你要把它放进内存，从地址 0x1000 开始：
```Bash
0x1000
0x1001
0x1002
0x1003
```
 ❓ 问题：11 / 22 / 33 / 44
谁放在 0x1000？谁放在 0x1003？,这就是**字节序要回答的唯一问题**。

两种答案 = 两种字节序

 1️⃣ 大端序（Big Endian）：高位字节，放在低地址
 ```Bash
 数值：   0x11 22 33 44
地址：
0x1000  11
0x1001  22
0x1002  33
0x1003  44
 ```
2️⃣ 小端序（Little Endian）：低位字节，放在低地址
```Bash
数值：   0x11 22 33 44
地址：
0x1000  44
0x1001  33
0x1002  22
0x1003  11
```

请问对于一个int 数，CPU在写入内存时，是按照字节序一个个写入内存的么？

>CPU 在进行“内存 ↔ 寄存器”的数据传输时，并不存在“先写高位/先写低位”的过程性动作；字节序只是一个“数据在内存中的空间排列规则”，由硬件在总线层面一次性完成。

案例演示：

假设：int = 4 字节，x86（小端）x 存在地址 0x1000，内存最终状态是：
```Bash
地址     内容
0x1000   44
0x1001   33
0x1002   22
0x1003   11
```

  
⚠️ 注意重点：不是 CPU 先写 44，再写 33，而是：
    - CPU 执行了一条“写 32 位值到内存”的指令
    - 内存控制单元按照小端规则，把这 4 个字节铺到相应的地址线上，然后一次性写入
