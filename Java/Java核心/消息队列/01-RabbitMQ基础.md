# 背景

1、实现服务之间的**异步调用**；对于一些耗时的调用，通过给消息队列发送消息然后直接返回，不等待结果。侧重解决的是性能 & 响应速度问题

2、**缓冲海量的请求**：在某个时间点突然出现大量的并发请求，这可能已经远远超过服务器的并发瓶颈，这时我们需要做一些削峰的操作，也就是将大量的请求缓冲到一个队列中，然后慢慢的消费掉。

3、**解耦合**：当一个操作需要调用多个服务时，比如典型的创建订单服务之后，需要给用户添加积分、通知商家、通知物流系统、扣减商品库存等等，如果其中一个出现问题失败，则直接导致整个操作失败。通过消息队列降低与其它多个服务之间的耦合。


<div class="highlight-block highlight-tip">关于异步与解耦合的区别理解</div>

虽然异步和解耦合都是基于当前操作需要调用其它的服务，然后引入消息队列来进行解决。

1）异步更加侧重的是解决性能和响应速度的 问题：**依赖的另外一个操作比较耗时**，会导致当前web请求的线程占用时间比较长，如果这样的例子比较多的话，那么很容易导致系统性能出现问题。

2）而解耦更加侧重的是**依赖多个微服务**：通过消息队列来解决系统依赖和可维护性，直接发送消息到消息队列即可，然后其它相关的服务直接去消费即可，即使后续扩展新增了新的服务也需要去消费，直接去消费即可，生产者那边无需改动。
