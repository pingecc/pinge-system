
# 保证本地事务与消息发送的原子性

问题描述：一个创建订单的逻辑，在执行订单创建逻辑之后，往消息队列发送消息，消息也成功发送到了消息队列，但是后续却异常了，回滚订单创建失败，这样就出现了消息成功发送到消息队列，但是本地事务却失败，最后数据不一致的问题。


问题的本质：分布式事务问题

本地事务 + MQ 消息发送 不是原子操作，在极低概率下就是会出现不一致问题：
- 本地事务失败，消息发送成功
- 本地事务成功，消息发送失败


猜想：发送消息队列的逻辑放在创建订单逻辑的最后一行不就好了，只要消息发送成功了，方法结束，如果消息发送失败，那么当前方法也会回滚事务，订单也不会创建成功

```java
@Transactional
createOrder() {
    1. 插入订单
    2. 发送MQ
    3. 返回成功（提交事务）
}
```
期望：
- MQ失败 → 抛异常 → 事务回滚 ✔
- MQ成功 → 方法结束 → 事务提交 ✔

但是事务的真正提交是发生在方法结束之后，等方法结束之后，Spring才开始执行事务的提交操作，而还是存在可能性Spring事务提交会失败，比如数据库连接断了，死锁等等，但是这种可以进一步降低概率不一致的概率。

既然有了这个思路，可以**选择一个折中的方案，等事务提交之后再发送消息**：

```java
TransactionSynchronizationManager.registerSynchronization(
    new TransactionSynchronizationAdapter() {
        @Override
        public void afterCommit() {
			try {
			    mq.send();
			} catch (Exception e) {
			    // 失败了重试/补偿
			    saveToLocalTable();
			}
        }
    }
);
```

这种方案**还是存在极端情况**，就是事务提交成功了，还没来得及发送，还没执行send()，当前服务就挂了。


<div class="highlight-block highlight-tip"> 本地消息表：强一致性保障</div>

创建完订单之后不直接发送消息到消息队列，而是写一条消息到本地的表，把创建订单逻辑和写入本地消息表的逻辑放在一个事务内，事务提交成功之后，后台定时任务去扫描消息表再发送MQ，发送成功之后再标记下以发送成功。

```Bash

本地事务：
1. 创建订单
2. 写一条“消息记录”（本地消息表）
COMMIT



定时任务 / 异步线程：
3. 扫描消息表
4. 发送MQ
5. 标记已发送

```
